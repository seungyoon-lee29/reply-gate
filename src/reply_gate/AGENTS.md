# reply_gate 패키지

## 범위

문의 1건을 받아 근거를 모으고 초안을 만들고 판정해 종결하는 애플리케이션 전체.
HTTP 표면, 파이프라인 루프, 게이트, 근거 수집, SQL 검증, 처리 기록, 평가 산출이 여기 있다.

**이 패키지의 범위가 아닌 것**: 데이터 시딩·정책 인덱싱·평가 실행의 **진입점**(→ `scripts/`),
스키마 DDL 과 픽스처(→ `db/`), 정책 문서 원본과 골든셋·검색 정답 라벨·재작성 질의·L1 픽스처·
L2 판정 픽스처 데이터와 **승격 기준선 참조**(→ `data/`).

## 파일별 경계

| 파일 | 소유 | 건드리면 안 되는 것 |
|---|---|---|
| `contracts.py` | 답변 계약·근거 ID 체계·판정/인계 enum | L1·L2 두 층과 저장·응답이 함께 쓰는 계약이다. 구조를 바꾸려면 사용자 승인이 필요하다 |
| `gate.py` | L1 판정, **패턴형 개인정보 정의의 단독 소유**(정규식·탐지 전 접기·정규화 한 벌) | **LLM·네트워크 라이브러리를 import 하지 않는다.** 시간·난수·환경에 의존하지 않는다. **접기는 패턴별이다** — 번호 계열만 구분자 변종 12자(열거된 고정 집합)를 하이픈으로 접고 결합 표식(`Mn` 범주 전체)을 무시하며, 이메일은 공통 접기 그대로다(밑줄·빗금을 접으면 서로 다른 주소가 같은 allowlist 값이 된다). **패턴 집합을 인자로 주입받지 않는다** — 층별 주입점이 곧 층별 비대칭이다 |
| `judge.py` | L2 판정(claim 단위 뒷받침 + 근거쌍 모순) | **판정만 한다** — 파이프라인 제어·저장·재생성·스위치 판단을 하지 않는다. `gate.py` 를 import 하지 않는다. 기각 사유는 2종이 전부다 |
| `sql_guard.py` | 스키마 화이트리스트, 쿼리 검증, 주문 범위 강제, **형변환 대상 타입 허용 목록**, **PII allowlist 출력 유래 판정** | DB 에 접속하지 않는다 — 검증만 하고 실행은 호출자가 한다. **"개인정보 모양"을 여기서 정의하지 않는다** — `gate.pii_shaped` 를 부르기만 한다(구조 검사). **유래 판정은 증명 방식이지 표현식 거부 목록이 아니다** — 직접 컬럼 · CTE·파생 테이블을 거친 직접 컬럼 · 고정값이 개인정보 모양이 아닐 때의 빈칸 채우기(`coalesce`·`nullif`)만 승인하고 나머지는 자동 불승인이다. **이어 붙이기 계열에 고정값이 들어갈 자리를 두지 않는다**(조각을 합치면 번호가 된다). **캐스트 허용 타입 목록의 소유자도 여기다** — SQL 생성 안내는 `describe_allowed_functions()` 가 싣는 문면을 그대로 쓰고 자기 목록을 만들지 않는다(구조 검사) |
| `evidence.py` | 의도 분류·**질의 재작성 조율**·정책 검색(원문·재작성 합집합)·**근거 채택 순서**(`adopt_policy_hits`)·존재성 선검사·text-to-SQL 조율 | SQL 실행은 반드시 read-only 커넥션으로. **개인정보 필터는 판정을 소유하지 않는다** — "개인정보 모양"은 `gate.pii_shaped` 하나이고 여기서 패턴도 접기도 다시 정의하지 않는다(구조 검사). **재작성 호출 실패는 폴백이고 미배선은 조립 오류다** — 둘을 섞지 않는다. **채택 순서는 질의 축(기권 게이트) → 항목 축(절대 하한)이고 통계량 입력은 컷 전 슬라이스다**(불변식 22). **채택 결과는 묶음(`PolicyAdoption`)이고 기권 판정을 함께 들고 나온다** — `abstains` 한 칸만 읽으면 미정의 사유가 근거 묶음·리포트에서 사라진다(사유는 처분과 별개로 밖으로 나간다 — 불변식 14 의 "조용한 폴백 금지"와 같은 규칙이다). **구간 시간 자료형(`StageDurations`)의 소유자도 여기다** — 구간 아홉 중 여섯이 이 모듈 안쪽이라(의도 분류·재작성·임베딩·벡터 검색·조회문 생성·조회 실행) 파이프라인이 수집 호출 하나를 바깥에서 감싸면 여섯이 한 칸으로 접힌다. 결과 묶음이 구간 시간을 함께 들고 나온다 |
| `query_rewrite.py` | 검색용 질의 재작성 프롬프트·스키마·호출 | **프롬프트를 두 벌로 만들지 않는다** — blind 픽스처 생성기가 이 문장을 가져다 쓴다. 갈리는 순간 오프라인 비교표가 런타임을 예측하지 못한다. 재시도하지 않고, 실패는 사유와 토큰을 담아 폴백한다. `LLMCallError`·`LLMFormatError` 보다 넓게 잡지 않는다(설정 오류가 검색 폴백으로 위장한다) |
| `draft.py` | 초안 생성 프롬프트와 호출 | **검증하지 않는다.** 산출이 계약을 어겨도 고치지 않는다 |
| `pipeline.py` | 접수 검증, 루프 제어, 재생성 상한, **층 결합(L1+L2)**, **초안·게이트·판정 구간 계측** | 상한은 `for` 문의 범위다. 프롬프트나 설정으로 빼지 않는다. **게이트 판정 구간은 여기가 잰다** — `gate.py` 는 시간에 의존하지 않는 것이 하드 게이트 1 이고 구조 검사가 지킨다. **시도 기록의 구간 칸은 기본값을 갖고 DB 에 실리지 않는다** — 처리 기록 복원이 생성자를 직접 부르므로 그것이 스키마 무변경을 지키는 유일한 모양이고, 복원된 구간은 0 이 아니라 미측정이다 |
| `records.py` | 처리 기록 저장/복원 | 커밋하지 않는다 — 트랜잭션 경계는 호출자 몫 |
| `api.py` | HTTP 라우트 등록, 응답 스키마 조립, 웹 폼 서빙 | 라우트를 다른 모듈에서 등록하지 않는다. **의존성 해석 단계에서 자원(커넥션·클라이언트)을 열지 않는다** — 열면 그 라우트의 선검사가 무엇을 하든 늦어 422·503 이 500 에 가린다 |
| `llm.py` | 생성·임베딩(OpenAI), 선택 설치 BGE-M3, 판정(Anthropic) 호출 래퍼, 전송 오류 1회 재시도, **밖으로 나가는 호출의 경과 시간(`elapsed_ms`) 측정**, **캐시 계열 토큰 수집(양 provider)** | 프롬프트를 담지 않는다. **두 SDK 모두** `max_retries=0` 을 풀지 않는다 — **주입된 클라이언트도** 생성자의 관문(`_pin_transport_policy`)이 다시 건다(`or` 우변에만 두면 주입 시 우회된다). BGE-M3 의존성을 기본 import 경로로 올리지 않는다. **경과는 전송 재시도 루프의 바깥에서 잰다** — 성공한 마지막 호출만 재면 재시도 1회가 통째로 사라진다(토큰이 이미 겪은 사고다). 산출과 **예외 양쪽에** 실어 올린다. **캐시 계열은 양 provider 에서 읽되 입력 칸에 접지 않는다** — 포함 관계가 반대라(OpenAI 는 적중분이 `input_tokens` **안**, Anthropic 은 **밖**) 접는 순간 한쪽은 적중이 "입력 감소"로 위장하고 다른 쪽은 같은 토큰을 두 번 센다. 없는 값은 0 이 아니라 `None`(미측정) |
| `order_ref.py` | 주문번호 형식 정의 | 형식을 다른 곳에서 다시 정의하지 않는다 |
| `policy_index.py` | 조항 단위 청킹·적재·검색 | 적재는 멱등이어야 하고 사라진 조항은 삭제해야 한다. **검색 정렬은 유사도 → 근거 ID 전순서다** — 코사인만으로 정렬하면 동점의 순서가 DB 몫이고, 동점이 `LIMIT top_k` 절단선에 걸리면 채택 집합과 기권 게이트 통계량이 함께 흔들린다. **저장된 벡터와 질의 임베딩의 출처(모델·차원)가 다르면 검색은 유사도를 내지 않고 거부한다** — 같은 차원의 다른 모델은 DB 도 pgvector 도 막지 않는다. **근사(ANN) 벡터 인덱스를 두지 않는다** — `LIMIT k` 가 k 보다 적게, 1위가 빠진 채 돌아와 검색 품질을 조용히 깎는다(26조항에서 정확 스캔이 0.1 ms 미만이다) |
| `db.py` | 커넥션 분리 | read-only 커넥션의 statement timeout 을 풀지 않는다 |
| `config.py` | 환경 변수 설정, **채택 축 구성의 단독 소유** — 컷(`vector_similarity_threshold`)·`vector_top_k`·기권 게이트 3필드(`abstention_gate_enabled`·`abstention_gate_statistic`·`abstention_tau`), **τ 검증 임베딩 조건 목록**(`VALIDATED_ABSTENTION_EMBEDDINGS`) | 비밀 기본값을 코드에 두지 않고 **자격 증명 필드는 `SecretStr` + `Field(repr=False)`** 다 — 두 겹인 것은 닫는 경로가 달라서다(표시는 `repr=False`, **덤프**(`model_dump()`·`model_dump_json()`·`dict()`·`vars()`)는 `SecretStr`). `tests/test_config_secrets.py` 가 이름이 비밀로 읽히는 필드를 **표시·덤프 양쪽에서** 전수 검사한다. **값은 `.get_secret_value()` 로만 꺼내고 그 자리는 두 모듈 다섯 줄뿐이다**(여기 2 · `llm.py` 3) — 접속 문자열은 값을 조립한 새 문자열이라 이 규칙 밖이고 비밀번호를 그대로 담는다. 게이트를 켜고 끄는 자리는 `Settings.abstention_gate()` **하나**다 — 수집기도 진입점도 이 메서드로만 게이트를 얻어야 런타임과 리포트 조건 지문이 갈리지 않는다. **`embedding_model` 을 바꿔도 `abstention_tau` 는 따라오지 않는다** — τ 는 조건 종속 인자이고 재산출은 명시적 작업이다. 그래서 **등재되지 않은 임베딩 조건에서 게이트를 켜면 `abstention_gate()` 가 조립을 거부한다**(`AbstentionGateWiringError`). 검증 목록은 **설정 필드가 아니라 모듈 상수**이고(환경 변수로 못 끈다) 넓히는 것은 사람의 일이다. 게이트를 명시적으로 끈 실행은 조건을 보지 않는다 — 무력해질 게이트가 없고 지문에 `"꺼짐"` 으로 남는다 |
| `evaluation.py` | 측정 1·2·3 산출과 리포트, 리포트 이름 규칙, 실행 조건(**조건 지문 포함**)·케이스 귀인, **단계별 지연의 케이스별 값과 세트별 집계** | 미실행 측정을 0 이나 빈 값으로 채우지 않는다. **구간 집계도 같은 규칙이다** — 미측정은 0 이 아니라 분모에서 빠지고, 사람이 읽는 줄과 리포트 JSON 이 **같은 원본에서 같은 값**을 적는다(두 표면이 갈린 전례가 있다). **리포트 이름의 자격은 "과금 실행 여부"** 이지 측정 2 실측 여부가 아니다. 회귀 판정 자체는 여기가 아니라 `regression_guard.py` 가 한다 — 리포트는 그 결과를 싣기만 한다. **캐시 칸은 계열별로 한 쌍씩 둔다**(생성·검색) — 두 계열이 같은 클라이언트를 지나 한 쌍으로 묶으면 어느 계열의 캐시였는지 되짚을 수 없다. **계열 수는 그대로 넷**이고 늘어나는 것은 계열마다의 칸이다. 캐시 칸은 계열 합산에 다시 더하지 않는다(입력 칸에 이미 포함돼 있다) |
| `regression_guard.py` | 이중 기준선 대조(승격=구속 / 직전 라이브=경보), 조건 지문, 비악화 판정 두 겹, 승격 참조 **로드**·등재 정합성 검사 | **승격 참조 파일을 쓰지 않는다** — 승격·재등재는 사람이 `data/promoted_baseline.json` 을 바꾸는 것뿐이고 자동 경로는 없다(구조 테스트). `evaluation.py` 를 import 하지 않는다(입력은 리포트 JSON 그대로다). **가드의 술어를 `matched` 하나로 되돌리지 않는다** — 근거 부분 손실이 같은 자격의 판정 조건이다. 옛 산출물에 없는 필드는 "미상"이지 0 이 아니다. 모델은 설명 문자열이 아니라 **벌거벗은 id** 로 비교한다 — 형식 차이로 "대조 불가"가 나면 지문이 스스로를 무력화한다 |
| `retrieval_eval.py` | DB 없는 누적 검색 전략 조합·채점·컷 스윕·비교 리포트, **기권 게이트 격자**(통계량 5종 × τ 스윕)와 **청킹 격자**(조항 단위 vs 고정 크기), blind/oracle 골든셋 재작성 질의 로드 | 검색 전략에 정답 라벨을 전달하지 않는다. **채택 판정은 전 전략이 코사인 절대 축 하나를 쓰고**(결정 0009) 순위 품질은 컷과 분리한다. 게이트 격자는 **채택 규칙 다섯을 순서대로**(케이스 하한 → 상충쌍 보존 → 기권 → 비악화 → 동률) 적용하고 **반증된 통계량 행도 전부 싣는다** — 빼면 "다섯 중 셋이 갈랐다"가 사후 선택이 된다. 코퍼스 변형(`build_policy_sources`·`chunk_policy_sources`)은 라벨을 인자로 받지 않는다(서명 검사). 재작성 조건은 픽스처 경로와 코드로 결속되며 기본값이 없다. 리랭크 폴백·토큰·미측정 단을 리포트가 집계한다. 기존 retrieval 산출물을 덮어쓰지 않는다 |
| `retrieval_strategies.py` | 재작성 합집합(벡터·어휘 양쪽)·인메모리 BM25·RRF·LLM 리랭크 순수 전략, **기권 게이트의 순수 판정 연산**(`AbstentionGate`·`truncate_for_gate`·`abstention_statistic`·`apply_abstention_gate`) | 정답 라벨·정책 파일·DB를 읽지 않는다. 입력은 호출자가 주입한다. **게이트는 점수열만 받는다** — 케이스 정체성도 정답도 받지 않고, `tests/test_answer_key_isolation.py` 가 AST 로 지킨다. **`top_k` 선절단은 조정 인자가 아니라 행동 계약이다**(런타임의 SQL `LIMIT top_k` → 파이썬 임계값 순서와 같은 자리). **통계량 미정의는 0 이 아니라 사유이고, 사유마다 처분이 다르다**(`AbstentionUndefined`) — 측정 2건 미만은 게이트를 열어 두고(0 으로 채우거나 fail-closed 로 접으면 모든 양수 τ 에서 기권이 되어 후보가 하나뿐인 질의가 근거 없이 인계된다) 1위 코사인 0 이하는 기권시킨다. 두 사유를 하나로 접지 않는다. 리랭크 폴백은 순위를 지키되 사유·토큰을 반환값에 담는다 — 조용히 지나가지 않는다. 캐시 키에 지시문이 들어간다 |
| `adoption_axis.py` | 채택 축 **손계산** — 커밋된 `reports/retrieval-strategies-live-*.json` 만 읽어 격자·분리 여유·상충쌍 감사를 계산하는 오프라인 채점자 | **새 임베딩도 새 과금도 없다** — 입력은 커밋된 산출물뿐이고 `config.py` 를 import 하지 않는다(설정이 아니라 산출물을 읽는 채점자다). 정답 라벨은 리포트 안의 `relevant_evidence_ids` 를 **채점에만** 쓴다. 표적 상수(`ABSTENTION_CASE_IDS`·`CONFLICT_PAIR_CASE_IDS`·`KNOWN_CONFLICT_PARTNERS`)는 **채점 전용**이라 전략·런타임이 닿지 않는다. `top_k` 선절단을 런타임과 같은 자리에서 한다 |
| `retrieval_labels.py` | 골든셋별 정책 검색 정답 라벨 로드·교차 검증 | 검색 recall 분모다 — 정답 경계는 **정면 조항 + 상충 조항**이고 조건·제한·채널 조항은 넣지 않는다(결정 0010). 답변의 최소 citation sufficiency나 판정 라벨과 합치지 않는다. 골든셋 ID 누락·추가와 정책에 없는 근거 ID를 조용히 넘기지 않으며, **교차검증 대상은 호출자가 실제로 쓸** 골든셋·정책 디렉터리다 |
| `testing.py` | 결정론 대역 — 어휘 임베딩·판정(`StubJudge`)·대역 파이프라인 조립기 | 실행 경로에서 쓰지 않는다. 대역 판정 수치를 실제 판정 정확도로 쓰지 않는다 |

## 불변식

1. `gate.py` 는 잎 노드다 — `contracts.py` 외에 이 패키지의 어떤 모듈도 부르지 않는다.
2. 재생성 시도는 문의당 최대 2건이다. 코드와 DB CHECK 가 각각 독립적으로 강제한다.
3. 재생성은 **같은 근거**로 한다. 근거를 다시 모으지 않는다.
4. `order_not_found` 를 판정하는 주체는 존재성 선검사뿐이다. SQL 결과 0건은 이 사유가 아니다.
5. SQL 근거 ID 의 실행 순번은 **채택된 쿼리에만** 매긴다. 거부·실패한 쿼리와 선검사 쿼리는
   ID 를 받지 않는다.
6. SQL 근거의 `evidence_text` 는 실행 SQL 을 제외하고 결과 행만 담는다. 비PII 계산 결과는 L2용으로
   유지하지만, 계산된 패턴형 PII는 제외한다. **유래가 `orders` 직접 컬럼으로 증명된 값**은
   마스킹하지 않는다 — 계산 PII를 섞으면 근거 없이 allowlist 에 오르고, 증명된 값을 가리면 정상
   에코가 오기각된다. **증명은 스코프를 타고 내려간다**: 임시 테이블(CTE)·파생 테이블을 거친
   직접 컬럼과, 고정값이 개인정보 모양이 아닌 빈칸 채우기(`coalesce`·`nullif`)까지 승인이다
   (`docs/business-rules.md` "PII 출처는 유래로 승인한다"). 직접 컬럼 provenance 를 계산값이
   덮어쓰지 못하도록 최상위 결과 출력명은 중복될 수 없다.
7. L1 의 PII 검사 대상은 답변 텍스트뿐이다 — **`to_draft` 가 답변으로 내보내는 claim 의 `text`**.
   `citation_ids` 도 스키마 밖 키(최상위 `debug`, claim 안 `note` 등)도 검사하지 않는다. 답변
   후보 텍스트를 하나도 식별할 수 없을 때만 초안 전체를 긁는다(어차피 `schema_violation` 이다).
8. 인계 사유는 6종 고정이다. DB 오류와 자격 증명 부재는 인계 사유가 아니다(각각 전파, 503).
9. **L2 는 L1 통과분에만 돈다.** 시도(초안)당 **1회 배치 판정**이고, 배치인 것은 비용이 아니라
   **기능 요건**이다 — 모순 감지가 claim·근거 교차 시야를 요구해 claim 별 호출로 쪼갤 수 없다.
10. **스위치 켜짐 + 판정자 미배선 = 조립 시점 명시적 오류**(`PipelineWiringError`).
    기본값·`None` 이 조용히 L2 를 끄는 **fail-open 배선을 금지**한다 — 배선을 빠뜨린 실행이
    "L2 를 통과했다"가 아니라 "건너뛰었다"는 사실을 지표가 알 수 없게 되기 때문이다.
    L2 없이 돌리려면 `l2_enabled=False` 로 **명시**한다.
11. **L2 미실행(`l2_result is None`)은 pass 가 아니다.** 층 결합에서 판정에서 빠지고, 판정
    호출이 실패한 시도는 종합 verdict 가 pass 이면서 문의는 인계된다 — 진실은 인계 사유와
    실패 단계(`l2_judge`)가 들고 있다.
12. **판정 토큰은 생성 토큰과 분리 집계한다.** 실행됐으나 실패한 판정 호출의 토큰도 실비용
    이므로 그대로 센다(예외에 실어 올린다).
13. **검색 단계(질의 재작성) 토큰도 같은 자격의 별도 계열이다.** 생성·임베딩·판정 어디에도
    합산하지 않는다 — 섞으면 초안을 만들지도 않은 문의가 초안 생성 토큰을 쓴 것으로 찍힌다.
14. **검색 단계 실패는 폴백이지 인계가 아니다.** fail-closed 원칙이 지키는 것은 "검증하지
    못한 답변을 내보내지 않는다"이고, 검색은 검증이 아니라 재료 수집이다. 다만 **조용한
    폴백은 금지**다 — 사유가 처리 기록(`inquiries.retrieval_fallback_reason`)과 평가 리포트에
    남는다. L2 호출 실패가 인계인 것은 변함없다.
15. **재작성 스위치 켜짐 + 재작성 클라이언트 미배선 = 조립 시점 명시적 오류**
    (`evidence.RetrievalWiringError`). 불변식 10 과 같은 규칙이다 — 기본값·`None` 이 조용히
    전략을 끄면 배선을 빠뜨린 실행이 "재작성을 켜고 돌았다"로 집계된다.
16. **원문 질의와 재작성 질의를 둘 다 검색해 합집합으로 모은다.** 재작성이 주제를 옮겼을 때
    원문이 안전망이다. 합쳐도 채택 상한은 `top_k` 그대로이고, 합침 규칙은 오프라인 비교
    하네스와 **같은 구현**(`retrieval_strategies.merge_rewritten_rankings`)을 쓴다.
17. **회귀 판정의 술어는 `matched` 하나가 아니다.** 비악화 판정은 두 겹이다: ① 기준선에서
    3회 모두 일치한 케이스가 새 실측 3회 중 2회 이상 일치, ② **기준선이 채택했던 정답 근거
    ID 가 새 실측의 케이스별 다수결에서 빠지면 미달**이고 빠진 ID 를 이름으로 찍는다.
    ②가 없으면 `matched=True` 인 채 근거가 사라지는 회귀가 그대로 통과한다 — 이 저장소가
    실제로 겪은 최대 회귀가 그 모양이었다(`docs/tracking/findings.md` 18번, 커밋된
    `reports/evaluation-live-l2-*` 6회 전부 `matched=True`). 감시 모집단을 "기준선 3/3"
    케이스로 한정하지도 않는다. 귀인 필드 `missing_relevant_evidence_ids` 는 표기가 아니라
    **②의 입력**이다.
    **귀인 절이 케이스를 싣지 않은 것과 귀인 절 자체가 없는 것은 다른 상태다.** 앞엣것은
    "정답 조항을 전부 채택하고 정상 답변했다"는 정보이므로 반대편 세트의 라벨을 빌려
    검사를 **계속한다** — 빌리지 않으면 기준선이 3회 모두 멀쩡했던 케이스가 통째로 감시
    밖으로 나가고, 그것이 이 층이 가장 지켜야 할 모집단이다. 뒤엣것은 무지이므로 판정을
    **보류**한다(통과가 아니다).
    **단, 두 실측의 검색 정답 라벨 판이 다르면 빌려 오지 않는다** — 빌린 라벨은 기준선이
    하지 않은 채택을 기준선에 돌리는 것이라, 라벨에 조항 하나를 더한 것만으로 거짓 미달이
    만들어진다. 그래서 검색 정답 라벨 버전은 **지문 항목**(`retrieval_labels_version`)이고,
    라벨 변경은 회귀가 아니라 조건 차이로 읽힌다. 판이 미상이면(옛 산출물) 빌려 온다 —
    그 산출물들은 애초에 귀인 절이 없어 이 층이 돌지 않는다.
18. **합산 일치율은 하한 경보선이다**(결정 0006 재확정). `MetricTarget.alert_only` 가 그
    성격을 코드에 박고, 미달 문면은 "미달"이 아니라 "경보"다 — 사이클 성패 판정은 케이스
    단위(회귀 가드 + 케이스별 귀인)가 맡는다는 것이 리포트 문면에 드러나야 한다.
19. **한 세트로 묶는 술어는 대조 술어보다 엄격하다.** 기준선 대조에서 미상 항목은
    관용한다(옛 산출물에 없는 항목 때문에 대조를 죽이지 않는다). 하지만 **세트 편입은
    "확인된 동일성"만 인정한다** — 모든 지문 항목이 양쪽에서 알려져 있고 값이 같아야 한다.
    관용을 편입에까지 끌고 가면 지문이 통째로 없는 산출물이 "전부 미상 = 어긋남 없음"으로
    읽혀 3회 정족수를 채우고, 다른 조건에서 나온 케이스 결과가 이번 실측의 일치 횟수로
    계산된다. 실제로 그렇게 멀쩡한 케이스 셋이 `1/3` 으로 찍혀 **거짓 미달**이 나왔다.
    **정족수를 채우려고 아무 산출물이나 끌어오지 않는다** — 3회 연속 실측의 1회차·2회차는
    세트가 안 찬 것이 정상이고 그때 답은 **보류**다. 못 채운 이유(제외된 산출물과 사유)는
    산출물에 이름으로 남는다. 라이브 리포트는 사후 편집하지 않으므로 그 자리에 찍힌 거짓
    미달은 기록에 영구히 남고, "미달이면 원복이 기본"이 그 기록을 먹는다.
20. **측정 1 무변경은 가드의 일부이고 측정 3 은 아니다.** 판정 층을 개선하는 실행이
    "측정 3 무변경"에 걸려 무관한 축의 원복을 발동시키면 안 된다. 리포트는 측정 3 수치를
    병기하되 무변경 검사에 넣지 않는다. **다만 표기는 그 실행에서 실제로 성립하는 것을
    적는다** — 아무것도 선언하지 않은 실행의 리포트에 "선언된 실험 변인이라"를 고정 문구로
    박으면 리포트가 거짓말을 한다. 값이 같은지, 달라졌는데 판정 층 변경이 선언됐는지,
    선언 없이 달라졌는지를 갈라 적는다.
21. **케이스 귀인은 세 가지를 구분해 적는다**(`docs/tracking/findings.md` 20번):
    ① **정책 검색 실행 여부** — 의도 분류가 `order` 로 라우팅해 검색이 아예 안 돈 케이스와
    검색이 돌았는데 걸러진 케이스는 다른 실패다(전자는 컷과 무관하다). 검색 토큰 0 +
    `sql:` 단독 채택으로 **역추론하지 않는다** — `GoldenOutcome.intent` 가 답을 들고 있고,
    의도 해석이 무너졌으면 `None`(미상)이지 `False` 가 아니다.
    ② **주문 단계 사전 인계**(`missing_order_ref`·`order_not_found`·`sql_failed`)는 빈 정답
    케이스의 **기대 경로**다 — business-rules 의 "구조적 사유가 이긴다" 계약상 정상 종결이다.
    ③ **`generation_issue` 는 최종 상태와 `matched` 를 병기한다** — 1차 기각 뒤 재생성으로
    회복해 `answered`/일치로 끝난 케이스가 종결 실패처럼 읽히면 안 된다.
22. **근거 채택은 질의 축 → 항목 축 순서다**([결정 0014](../../docs/tracking/decisions/0014-기권-게이트를-1위-top_k위-산포-축으로-채택한다.md)).
    ① 기권 게이트가 상위 `top_k` 점수 분포를 보고 질의 하나를 이분 판정하고(발동하면 채택
    집합이 **통째로** 빈다), ② 발동하지 않았을 때만 절대 하한이 항목을 자른다. 순서를 뒤집거나
    게이트에 항목 선택을 시키면 결정 0009 의 절대 축 원칙이 항목 축에서 깨진다.
    **통계량 입력은 `top_k` 선절단 슬라이스이고 컷 뒤 슬라이스가 아니다** — 컷 뒤로 재면
    컷 위 후보가 둘뿐인 케이스(G04)의 산포가 τ 아래로 떨어져 정답 조항을 잃는다.
    **τ 는 임베딩 모델에 묶인다** — `-3-large` 계열에서는 이 통계량이 기권군과 채택군을
    분리조차 못 한다(`docs/engineering-notes.md` "τ 는 임베딩 모델에 묶인다"). 그래서 τ 와
    `embedding_model` 은 실행 조건 지문에서 **한 쌍**이다(`regression_guard.PAIRED_FINGERPRINT_FIELDS`).

## 이 패키지의 방식

- **주입 가능한 클라이언트**: LLM·임베딩은 프로토콜(`GenerationClient`/`EmbeddingClient`)로
  받는다. 구체 클래스에 의존하지 않아 테스트가 목을 끼울 수 있다.
- **원시 산출을 정규화하지 않고 넘긴다**: 초안 생성 → 게이트 사이에서 형식을 고치지 않는다.
  고치면 게이트가 무엇을 막는지 증명할 수 없다.
- **거부 사유는 재시도가 고칠 수 있는 형태로**: SQL 가드의 거부는 사유 코드 + 안내 문구로
  돌아가 재생성 프롬프트에 실린다.
- **fail-closed**: 검증기가 해석하지 못한 구문은 통과가 아니라 거부다.

## 테스트 지침

- **DB 가 필요한 테스트는 `@pytest.mark.db`.** `app_conn`(롤백) / `ro_conn` 픽스처를 쓰고
  행을 남기지 않는다.
- **외부 호출은 전부 목**이다 — 생성·임베딩·판정 셋 다. `pyproject.toml` 에 `live` 마커가
  **등록만** 되어 있고 **그 마커를 쓰는 테스트는 없으며, 기본 실행에서 제외하는 장치도 없다**
  (`addopts` 는 `-q --strict-markers` 뿐이다). 실 API 를 부르는 테스트를 새로 만든다면
  마커를 붙이는 것으로 끝나지 않고 **제외 장치를 함께 만들어야 한다.** 마커 등록은 그때를 위한
  예약으로 남겨 둔다 — `--strict-markers` 아래에서 등록만으로는 아무 비용이 없다.
- **양성 대조를 반드시 함께 둔다.** 전부 거부하는 검증기는 검증기가 아니다 — 거부 케이스마다
  통과해야 할 정상 케이스를 짝지어라.
- **하드 게이트는 구조 테스트로 못박는다.** 게이트의 LLM import 금지는 AST 검사로,
  재생성 상한은 상한값을 바꾸면 깨지는 테스트로 지킨다.
- **회귀 테스트는 실제로 뚫렸던 문자열을 그대로 쓴다.** 요약한 케이스는 같은 구멍을 다시 놓친다.
- 반드시 다뤄야 할 엣지: 인계 사유 6종 각각, 기각→재생성→확정, 재기각→인계,
  형식 불일치가 `schema_violation` 으로 흐르는 경로, 근거 유래 PII 에코가 통과하는 것,
  **L1 기각분에 L2 가 돌지 않는 것**, **L2 기각→재생성→확정**, **L2 호출 실패가 통과가 아니라
  인계로 끝나는 것**(종합 pass + `llm_call_failed`), **스위치 켜짐 + 판정자 미배선이 조립에서
  죽는 것**, 실패한 판정 호출의 토큰이 0 으로 접히지 않는 것.
