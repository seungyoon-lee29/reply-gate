# 사이클 2 핸드오프 — L2 의미 수준 검증 (governing doc)

## 문서 역할과 충돌 해소

| 문서 | 역할 | 권위 |
|---|---|---|
| `.dryforge/spec.md` | **무엇을** — 행동 계약, ground truth | 충돌 시 항상 이긴다. 오류는 사용자 승인으로만 수정 |
| `.dryforge/plan.md` | **어떻게·순서** — 태스크와 실행 그래프 | 잠정 청사진. 자유롭게 수정 가능 |
| 기존 코드 | HOW 참고 + 현실 대조 | WHAT 의 권위가 아니다 |

프로젝트 컨텍스트는 harness(`CLAUDE.md`/`AGENTS.md` + `docs/`)가 들고 있다 —
이 핸드오프는 이번 사이클 고유의 통제만 담는다.

## 실행 형태

태스크 10개, 파도 6개(그래프 참조). 스키마 변경(T3) 뒤 볼륨 재생성 장벽 1회.
작업 전 필독은 harness 규칙 그대로: `docs/standards.md` → `docs/engineering-notes.md` →
손댈 모듈의 `AGENTS.md`, 그리고 작업 종류별 표(CLAUDE.md).

## 하드 게이트 (실행 에이전트가 코드에서 유도할 수 없는 불가침)

1. **`gate.py` 동작 무변경(주석 시제 정정만 허용 — 승인됨).** L1 은 LLM·네트워크
   import 금지·결정론·사유 4종 그대로. L2 는 별도 모듈이다. 구조 테스트가 지킨다.
2. **판정 기본 배선은 Anthropic 계열.** OpenAI 로 바꾸면 self-judging bias 로 검출률이
   오염된다(결정 0004). 테스트로 고정하라. 그리고 **스위치 켜짐 + 판정자 미배선은
   조립 시점 명시적 오류**다 — 조용히 L2 를 건너뛰는 fail-open 배선 금지(spec 2).
3. **답변 계약(`claims`/`citation_ids`)·근거 ID 체계·text-to-SQL 안전장치 3층·
   재생성 같은 근거·시도 상한 2회 불변.**
4. **평가용 장치 제거 금지.** 골든셋 라벨 변경은 정확히 3건(G17·G01·G02, spec 6-2)뿐이다.
   미끼·모호·상충 조항과 L1 픽스처는 그대로.
5. **과금은 명시적으로만.** `--live`(측정 2+3)와 `scripts.index_policies` 는 사용자
   승인 시에만 실행한다. 완료 게이트 (a)(spec 10)는 키·과금 없이 성립한다.
   (b) 실동작 확인 전에 **사용자에게 요청할 것 세 가지**: `ANTHROPIC_API_KEY` 제공,
   `index_policies` 1회 승인(임베딩 과금 — 볼륨 재생성으로 비워짐), 4장면 라이브 호출 승인.
6. **라이브 리포트 보존.** 기존 `reports/evaluation-live-{1,2,3}.*` 6개는 덮어쓰지도
   지우지도 않는다. 새 실측은 `evaluation-live-l2-<n>` 계열(기본 이름 자동 넘버링).
   기존 라이브 이름 ⇔ 실측 양방향 불변식은 무변경이고, 이름 가드는 **확장만** 한다 —
   "L2-on 실측 ⇔ l2 접두" 차원을 명시 스템에도 양방향 추가(spec 6-3).
7. **비밀 평문 금지.** `ANTHROPIC_API_KEY` 포함 — `.env` 만, 로그·오류·리포트에 값 금지.
8. **미실행 측정을 0 으로 채우지 않는다.** 측정 3 미실행이면 "미실행 + 사유".
   TARGETS 3종은 무변경, L2 목표치는 "미확정(실측 후)".
9. **실측값 선반영 금지.** README·status 의 수치 갱신은 라이브 실측 산출물이 생긴 뒤에만.
10. **검증 게이트**(병합 전): `ruff check`·`ruff format --check`·`mypy`(strict)·`pytest`
    전체 녹색 + `pytest -m db` **skip 0**. 스키마 태스크 이후는 볼륨 재생성 상태에서.

## 작성 중 확정됐지만 spec/plan 에 자리가 없는 의도

- **판정 모델로 Sonnet 5 는 사용자의 명시 선택이다**(권장은 Opus 5 였음). 판정 품질이
  아쉬워도 임의로 상위 모델로 올리지 마라 — 모델은 조정 가능 기본값이므로 실측을 보고
  사용자가 정한다.
- **배치 판정의 근거는 비용이 아니라 기능이다** — 모순 감지가 claim·근거 교차 시야를
  요구한다. claim 별 개별 호출로 "개선"하면 모순 감지가 구조적으로 약해진다.
- **fail-closed(L2 장애 시 인계)는 "검증 못 한 답변을 내보내지 않는다"는 제품 서사의
  선택이다.** business-rules 의 옛 "단일 실패점 아님" 문구와 충돌하므로 문구 쪽을 고치는
  것까지가 승인 범위다(spec 4-7). fail-open 으로 "개선"하지 마라.
- **"없다" 안내의 의미 정책(spec 4-4)이 이번 사이클 제품 행동의 심장이다.** 주제 인접
  인용은 기각, 정면 조항의 "없다"는 통과 — 이 비대칭이 무너지면 정직한 안내가 인계로
  쏟아지거나(과잉) 무근거 4건이 계속 통과한다(과소). 판정 프롬프트·픽스처·골든셋
  라벨이 전부 이 정책에 정렬돼 있다.
- **알려진 확률 리스크 — 재생성의 '주제 바꿔치기'.** G21–G24 기대 경로(L2 재기각→인계)는
  재생성 초안이 "안내가 어렵다" 문장을 버리고 **인접 조항이 실제로 말하는 내용만**
  진술하면 무너진다 — `unsupported_claim` 은 근거-주장 정합만 보고 문의-답변 관련성은
  안 본다. 그렇다고 판정 범위를 관련성까지 넓혀 "고치지" 마라(L2 사유 2종이 전부라는
  계약). 빈 claims 도피는 L1 `schema_violation` 이 잡는다. 이 리스크의 실재 여부는
  첫 라이브 실측이 판정한다 — 피드백 문구(T5)가 "근거가 다루지 않는 문장은 빼라" 쪽으로
  기울수록 이 경로가 열린다는 것을 알고 쓰라.
- **G16–G20(미끼)의 `answered` 허용과 `expect_reject` 구조는 건드리지 않는다.**
  (G17 은 하드 게이트 4 대로 **허용 인계 사유만** `no_evidence` 로 확장한다 — spec 6-2.
  이 확장의 목적은 mismatch 보고의 정직성이고, G17 을 일치로 만들지 않는다.)
  L2 도입 후에도 미끼의 `answered` 허용은 정당하다 — 정면 조항 "없다" 안내는 뒷받침되기
  때문(4-4). 미끼 재현율이 낮게 유지되는 것은 결함이 아니라 관측이다(무목표 유지,
  결정 0006 문구 한정 수정).
- **지연 비교 오염 주의**: L2 는 `latency_ms` 에 포함되므로 p50/p95 가 기존 실측과 직접
  비교되지 않는다. 리포트의 실행 조건(L2 켜짐 여부)이 구분자다 — 수치를 나란히 쓸 때
  반드시 조건을 병기하라.
- **Anthropic SDK 규약은 구현 시점에 확인하라**(구조화 출력 파라미터·재시도 옵션·모델
  ID). 기억으로 쓰지 말 것 — 프로젝트 규칙("설정/CLI는 실행해서 답한다")과 같은 정신.
- 사이클 1 인계 문서가 남긴 규율 그대로: "고쳤다"는 자기 보고 대신 **실제로 넣어보고**
  확인한다. 특히 judge 프롬프트는 픽스처 4분면을 실제로 흘려 보고 조정하라(대역으로
  배관, 라이브는 사용자 요청 시).

## 완료의 정의

spec 10 의 완료 검증 전부 + 실동작 4장면(정상 / L2 기각→재생성→통과 /
L2 재기각→인계 / 스위치 꺼짐) + 서버 종료 확인. 확률 장면 2개가 문의를 바꿔가며
시도해도 재현되지 않으면 무한정 붙잡지 말고 시도 내역을 그대로 보고해 사용자 판단을
받는다(spec 10). 라이브 실측과 실측값 문서 반영은 완료 게이트 뒤의 별도 단계다
(사용자 요청 시).
