# 사이클 2 스펙 — L2 의미 수준 검증

이 문서가 이번 사이클의 **ground truth** 다. plan 과 어긋나면 spec 이 이긴다.
spec 의 오류는 사용자 승인으로만 고친다.

---

## 1. 목표와 동기

**L1 통과분을 claim 단위로 근거와 대조하는 의미 수준 검증(L2)을 파이프라인에 넣는다.**

실측 근거(사이클 1, 라이브 3회):

- e2e 일치율 71.1%(64/90) — 목표 75% 미달. 어긋난 26 케이스-실행의 최대 단일 원인은
  무근거 문의 G21–G24(12회): 모델이 주제 인접 조항을 인용해 "안내가 어렵다"고 답하고,
  L1 은 구조만 보므로 `answered` 로 종결된다. 실측 세부(status.md): 12회 중 11회는
  먼저 `missing_citation` 으로 L1 기각된 뒤 **재생성 초안**이 인접 조항을 인용해
  통과했다 — L2 기대 경로는 이 재생성 초안의 인용 행동에 의존한다(handoff '주제
  바꿔치기' 리스크와 짝).
- 미끼 기각 재현율 6.7%(1/15): 모델이 값을 지어내지 않아 구조적 결함이 안 생긴다.
  남은 위험은 의미 층 — "근거를 달았지만 그 근거가 주장을 뒷받침하지 않는" 답변.

L2 는 이 간극을 겨냥한다. 성공하면 G21–G24 가 인계로 흘러 75% 에 닿는 것이 기대 경로다.

## 2. 아키텍처 위치와 스위치

- 위치: **초안 → L1 → (L1 pass 시) L2 → 종결**. L1 reject 면 L2 는 실행되지 않는다.
- **스위치**: 설정값(기본 **켜짐**)으로 L2 를 통째로 끌 수 있다. 끄면 사이클 1 동작과
  완전히 같다(L1 pass → answered). 스위치의 존재 이유는 도입 전후 비교 실측이다.
  켜져 있는데 판정자가 배선되지 않은 조립은 **명시적 오류**다 — 조용히 L2 를
  건너뛰는 경로를 두지 않는다(fail-closed 는 배선 실수에도 성립해야 한다).
- L2 는 **새 모듈**이다. `gate.py` 의 동작은 손대지 않는다(주석 시제 정정만 허용 —
  불변 1) — L1 의 LLM·네트워크 import 금지와 결정론은 하드 게이트로 불변이다.

## 3. 판정 모델

- **Anthropic Claude Sonnet 5** (`claude-sonnet-5`), 조정 가능 기본값.
  생성(OpenAI)과 다른 계열이어야 한다는 결정 0004 의 구조적 요건을 충족한다.
  **기본 배선이 Anthropic 클라이언트인 것을 테스트가 검사한다** — 같은 계열로 바뀌면
  self-judging bias 로 검출률이 오염되기 때문이다.
- 새 환경 변수 `ANTHROPIC_API_KEY`. 비밀 규칙은 기존과 동일(.env 만, 평문 금지,
  `.env.example` 에는 키 이름만).
- 래퍼 규칙은 기존 OpenAI 래퍼와 동일: SDK 자동 재시도 차단(`max_retries=0`) + 래퍼가
  전송 오류 1회 재시도, 샘플링 파라미터 미전송(Sonnet 5 는 기본값 아닌 값을 보내면
  400, 기본값·미전송은 허용 — 미전송 규칙과 정합), 거절(refusal) 처리 동수준,
  프롬프트는 래퍼 밖(판정 모듈)에.
  thinking 설정은 보내지 않는다 — 단, 미전송은 "끔"이 아니라 **adaptive thinking 켜짐**이
  모델 기본이다: 판정 토큰에 thinking 이 포함되고(실비용이므로 그대로 집계),
  `max_tokens` 는 thinking+응답 합산 상한이라 여유를 둔다. effort 는 조정 가능 기본값.

## 4. 판정 행동 계약

### 4-1. 호출 형태

시도(초안)당 **1회 배치 호출** — 재생성된 초안은 다시 판정하므로 문의당 최대 2회다.
전 claim 과 근거를 한 번에 주고 구조화 출력으로
claim 별 판정 배열 + 근거쌍 모순 배열을 받는다. 배치인 이유는 모순 감지가
claim·근거 교차 시야를 요구하기 때문이다(비용이 아니라 기능이 근거다).

### 4-2. 판정 입력

- **뒷받침 판정**: 각 claim 의 text + 그 claim 이 **인용한** 근거의 `evidence_text`.
- **모순 감지**: 이번 문의의 **수집 근거 전체**(인용 여부 무관)의 `evidence_text`.
  상충 쌍이 한쪽만 인용돼도 검출돼야 하기 때문이다.

### 4-3. 기각 사유 2종 (기각 사유 계약 확장 — 승인됨)

| 사유 | 규칙 |
|---|---|
| `unsupported_claim` | 어떤 claim 이 인용한 근거로 뒷받침되지 않는다 |
| `contradictory_evidence` | 수집 근거에 서로 모순되는 쌍이 있고, 초안이 그 모순을 명시하지 않은 채 해당 근거를 딛고 답한다 |

기존 L1 4종("이 전부다")은 L1 의 전부로 유지되고, 위 2종은 **L2 의 전부**다.

### 4-4. 의미 정책 — "없다" 안내의 판정 기준 (제품 서사를 정하는 규칙)

- **주제 인접 인용은 기각한다**: 인용한 조항이 claim 의 주제를 실제로 다루지 않으면
  (예: 해외 배송 문의에 국내 배송 조항을 인용해 "안내가 어렵다") 그 claim 은
  `unsupported_claim` 이다. → G21–G24 가 인계로 흐르는 경로.
- **정면 조항의 "없다" 안내는 통과한다**: 조항이 그 주제를 정면으로 다루며 값만 비어
  있는 경우(미끼 조항), "기재되어 있지 않다" claim 은 그 조항이 뒷받침한다.
  → 정직한 "없음" 안내는 유지된다. 미끼 문의 G16–G20 의 `answered` 허용 라벨과 정합.

### 4-5. 모순 판정 규칙

- 모순은 **근거쌍 단위**로 기록한다: `{근거 ID A, 근거 ID B, 설명}`. claim 판정 배열과
  별도다 — 모순은 근거 두 건 사이의 관계라 특정 claim 에 귀속되지 않을 수 있다.
- **초안이 모순을 명시하고 두 기준을 모두 안내하면 통과한다**(현재 실측에서 모델이
  이미 하는 행동). 명시 없이 한쪽만 딛고 답하면 `contradictory_evidence` 기각.

### 4-6. 기각 후 흐름 — L1 과 같은 루프

- L2 기각 → 사유 + **claim 단위 상세**(어느 문장이 왜)를 피드백으로 재생성 1회 →
  L1 → L2 → 재기각이면 `escalated(rejected_twice)`.
- 시도 상한 2회와 DB CHECK 는 불변. `rejected_twice` 의 정의는
  **"초안이 2회 연속 기각(층 무관)"** 으로 확장된다(문서 갱신 포함).
- 재생성 피드백 형태는 SQL 검증기 선례를 따른다: 사유 코드 + 무엇을 어떻게 고칠지.
  근거쌍 모순 기각의 피드백에는 "모순을 명시하고 두 기준을 모두 안내하라"가 실린다
  (같은 근거 재생성 불변식 안에서 구제 가능한 유일한 방향이므로).
- 재생성 인터페이스는 사유 코드 목록만 받던 것을 **L2 상세를 함께** 받도록 확장한다.

### 4-7. 실패 정책 — fail-closed

- 전송 오류: 래퍼 1회 재시도 → 재실패 시 `escalated(llm_call_failed)`,
  실패 단계 이름 `l2_judge` 기록. 그 시도 행은 L1 판정만 남고 L2 판정은 null 이다
  (층 결합 정의상 종합 verdict 는 pass — 인계 사유와 실패 단계가 진실을 들고 있다).
- 구조화 출력 형식 불일치: 1회 재시도(의도 해석 패턴) → 재실패 시
  `escalated(llm_call_failed)`. 배치 판정이므로 형식 불일치의 반경은 문의 전체다(승인됨).
- **검증하지 못한 답변은 내보내지 않는다.** 이에 따라 business-rules 의
  "상위 층은 단일 실패점이 아니다" 문구는 "스위치로 끌 수 있다(끄면 L1 단독 동작)"로,
  `rejected_twice` 만이 "초안이 실제로 만들어졌다"는 구분 서술은 L2 도입에 맞게 고친다.
- `ANTHROPIC_API_KEY` 미설정 + L2 켜짐: `POST /inquiries` 는 **503 설정 오류**
  (처리 기록 없음, `llm_call_failed` 로 집계하지 않음 — OpenAI 키 부재와 동일 규칙).
  **검사 시점은 eager**: POST 처리 진입 시 스위치+키를 선검사해 무조건 503 을 낸다.
  lazy(L2 도달 시 실패)로 하면 생성 토큰을 태운 뒤 503 이 나고, L1 이 2회 기각하면
  키 없이도 정상 종결되어 이 조항이 조건부가 된다. 선검사는 **POST 경로에만** 건다 —
  `GET /inquiries/{id}`·422 경로까지 걸면 키 없는 환경에서 조회가 죽는다
  (engineering-notes "목만으로는 잡히지 않는 결함" 재발).

## 5. 기록·API 계약

### 5-1. 층별 판정 분리 기록

시도(attempt) 기록은 **L1 판정과 L2 판정을 구조적으로 구분**해 남긴다.

- 시도당: L1 판정(verdict + L1 사유), L2 판정(verdict + L2 사유 + claim 단위 판정 +
  근거쌍 모순; **L2 판정이 없으면 null** — L1 reject·스위치 꺼짐·L2 호출 실패).
- 종합 verdict/사유(기존 컬럼·키)는 유지한다: 종합 pass ⟺ L1 pass 이고 L2 가
  실행됐다면 L2 도 pass. 종합 사유 = L1 사유 ∪ L2 사유(순서: L1 사유 먼저,
  각 층 안에서는 고정 순서). 기존 평가·조회 코드의 호환 지점이다.
- DB CHECK 로 모순 상태를 막는다: L1 reject 인데 L2 판정이 존재하는 행,
  종합 pass 인데 어느 층이 reject 인 행, L2 판정이 null 인데 L2 부속(사유·claim
  판정·모순쌍)이 존재하는 행은 불가능해야 한다.
- 스키마 변경이므로 볼륨 재생성 1회를 동반한다(마이그레이션 도구 없음 — 알려진 제약).

### 5-2. claim 단위 판정 기록

L2 가 실행된 시도에는 claim 별 `{text 참조, verdict, 사유 설명}` 과 근거쌍 모순
목록이 기록된다. 데모의 "왜 기각됐는지" 장면이 여기서 나온다.

### 5-3. API 응답 (`POST /inquiries` · `GET /inquiries/{id}` 공통 골격)

- `attempts[]` 에 층 구분이 노출된다: 종합 verdict/reject_reasons(기존 키, 값 집합에
  L2 사유 2종 추가) + L2 상세 키(미실행이면 `null` — 키는 항상 존재 규칙 준수).
- `metrics.tokens` 의 기존 의미(**생성 LLM 합산, 임베딩 제외**)는 불변. 판정 모델
  토큰은 **별도 키로 분리 신설**한다(임베딩과 같은 취급 — 타 provider·타 단가 토큰을
  생성 합산에 섞으면 건당 비용 지표가 무너진다). 처리 기록에도 분리 컬럼으로 남긴다. L2 미실행이면 판정 토큰은 0
  (임베딩 토큰 관례와 동일). L2 가 실행됐으나 실패한 호출이 반환한 토큰(형식 불일치
  1차 응답 등)도 실비용이므로 그대로 집계한다.
- `latency_ms` 는 L2 호출을 포함한다(파이프라인 벽시계 시간 정의 불변). 기존 실측과의
  비교 오염은 리포트에 L2 켜짐 여부를 실행 조건으로 병기해 막는다.
- 웹 폼은 층 구분과 claim 단위 판정을 표시한다(판정 과정이 답변보다 먼저·크게 원칙).

## 6. 평가·측정

### 6-1. 측정 3 신설 — L2 판정 단위 정확도 (확률층)

- L1 픽스처와 같은 구조의 **판정 픽스처 셋**: 고정 (claims 집합, 근거 집합, 기대 판정
  — claim 별 verdict + 모순쌍) 쌍. 픽스처 단위는 claim 집합(배치 호출과 동일 단위)이다.
- 판정 모델을 실제로 호출하므로 **과금·확률층**이다: `--live` 로만 실행되고, 리포트에
  확률층임이 명시된다(측정 1 과 달리 재실행 시 값이 달라질 수 있음).
- 산출: L2 검출률(기각해야 할 픽스처를 기각)·오탐률(통과해야 할 픽스처를 기각)·
  사유 일치. **목표치는 미확정** — 첫 실측 후 확정한다(결정 0006 철학).
- 픽스처에는 4-4 의미 정책의 양쪽이 반드시 들어간다: 주제 인접 인용(기각 기대),
  정면 조항 "없다" 안내(통과 기대), 모순 명시(통과 기대), 모순 비명시(기각 기대).

### 6-2. 골든셋 라벨 변경 (평가용 데이터 변경 — 승인됨)

- **G17**: 허용 인계 사유에 `no_evidence` 추가. 목적은 **mismatch 보고의 정직성**이다 —
  실측 3회 재현된 사유를 라벨이 "허용 밖"이라고 계속 말하지 않게 한다. `expect_reject` 는
  유지하므로 시도 0건인 `no_evidence` 인계의 G17 은 **여전히 불일치로 남는다** — 일치율을
  올리는 변경이 아니고, 75% 기대 경로는 G21–G24 만으로 성립한다(그 넷의 라벨은 이미
  `rejected_twice` 를 허용한다).
- **G01·G02**(상충 조항 정상 문의): 허용 결과 집합에 `escalated(rejected_twice)` 추가.
  모순 명시 답변의 `answered` 통과는 그대로 허용된다(4-5 규칙과 짝). 두 케이스의
  note 문구(사이클 1 시제 — "이번 사이클에서는 기각 사유가 아니다" 류)도 현재형으로
  정정한다. **알려진 관측 한계**: 이 확장으로 G01·G02 에 한해 L2 오탐(모순과 무관한
  엉뚱한 기각)도 허용 집합 안이라 측정 2 에서 일치로 집계된다 — L2 오탐 감시는 측정 3
  담당이다(forbidden 감시는 상충 문의의 정당한 `unsupported_claim` 경로 때문에 부적합).
- 그 외 라벨·미끼·모호·상충 조항·L1 픽스처는 **불변**(평가 장치 제거 금지).

### 6-3. 재실측 프로토콜

- **L2-on 골든셋 3회**만 과금 실행한다. off 기준선은 기존 `evaluation-live-{1,2,3}`.
- 라이브 리포트 이름은 기존과 구분하고, 구분은 규율이 아니라 코드가 강제한다:
  L2 켜짐 실측의 기본 이름을 코드가 `evaluation-live-l2-<n>` 으로 **자동 넘버링**한다
  (3회 반복이 기본 이름 충돌로 죽지 않게). 이름 가드에 **"L2-on 실측 ⇔
  `evaluation-live-l2` 접두" 차원을 명시 스템에도 양방향으로** 추가한다 — 기본 이름만
  가르면 `--report-stem evaluation-live-4` 가 기준선 계열을 오염시킨다. 빈 이름 제안도
  계열을 따른다. 기존 라이브 이름 ⇔ 실측 불변식과 gitignore 추적 패턴은 이 접두가
  그대로 만족한다. 실행 조건에 **L2 켜짐 여부와 판정 모델**이 기록된다.
- **키 선검사는 측정 시작 전**: `--live` + L2 켜짐이면 `OPENAI_API_KEY` 와
  `ANTHROPIC_API_KEY` 를 **둘 다** 선검사한다. 판정 키 부재를 측정 도중 발견하면
  과금 후 산출물 없이 죽는다 — 리포트 이름 가드를 측정 전에 돌리는 것과 같은 원칙.
  판정 키가 없으면 측정 2·3 을 **모두 skip**(사유 기록)한다 — L2 를 꺼서 측정 2 만
  돌리는 **강등 실행은 금지**다(기준선과 실행 조건이 오염된다).
- 측정 2 의 토큰 집계·리포트 표에 **판정 계열을 분리 신설**한다(생성·임베딩·판정).
  건당 비용 지표가 L2-on 실측에서 판정 비용을 빠뜨리면 5-3 분리 신설의 근거가 무너진다.
- 측정 2 의 기존 지표 정의(일치율·미끼 기각 재현율 — 시도 중 최소 1건 기각, 층 무관)는
  불변. L2 기각은 자동으로 재현율에 포함된다.
- `--stub-llm` 배관 검증은 결정론 판정 대역을 포함한다(실제 수치 아님 경고 동일).

### 6-4. 목표치·결정 문서 정합

- TARGETS 3종(L1 100%/0%, 일치율 75%)은 불변. L2 지표는 실측 후 확정.
- 결정 0006 의 미끼 무목표 근거 문구를 "**L1 층에서는** 우리 코드가 올릴 수 있는
  수치가 아니다"로 한정 수정하고, L2 층 검출은 측정 3 담당임을 명시한다.
  미끼 재현율은 이번 사이클도 목표 없는 관측값이다.
- findings 1번의 "기각 장면은 missing_citation 경로로" 서사는 L2 기각 장면이 생기면
  실측을 보고 갱신한다.
