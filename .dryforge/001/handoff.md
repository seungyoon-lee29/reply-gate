# Reply-Gate 핸드오프 — 사이클 1 (governing doc)

## 문서 역할과 충돌 해소

| 문서 | 역할 | 권위 |
|---|---|---|
| `.dryforge/spec.md` | WHAT — 행위·계약·불변식 (ground truth) | 충돌 시 spec이 이긴다. spec의 오류는 사용자 승인으로만 고친다 |
| `.dryforge/plan.md` | HOW/순서 — 태스크·작업 대상·Execution Graph | 잠정 청사진. 자유롭게 수정 가능 |
| `.dryforge/handoff.md` | 통치 문서 + spec/plan에 없는 의도 | 이 문서 |

기존 코드는 없다(그린필드). 이후 사이클에서 코드는 HOW 참고일 뿐 WHAT의 권위가 아니다.

## 실행 형태 (big picture)

태스크 9개, 웨이브 6개: {T0 스캐폴드} → {T1 데이터 기반, T4 초안 생성, T5 L1 게이트} →
{T2 정책 문서·인덱싱} → {T3 근거 수집} → {T6 루프+API+웹 폼} → {T7 평가, T8 README}.
상세와 그래프는 `.dryforge/plan.md`.

## 하드 게이트 (실행 에이전트가 코드만으로 도출할 수 없는 비타협 제약)

1. **L1은 LLM 호출 0회.** 게이트 검사에 LLM을 쓰는 순간 제품 정체성이 무너진다. 어떤 편의도
   이 규칙을 깨지 못한다.
2. **text-to-SQL 안전장치 3종(read-only 계정·스키마 화이트리스트·쿼리 검증)은 생략 불가.**
   "데모니까 나중에"가 허용되지 않는다 — 채용 면접 역공 방지가 존재 이유.
3. **루프 종료·데이터 접근·권한은 항상 코드가 통제.** LLM은 의도 해석·초안 생성·SQL 문자열
   생성까지만. 재생성 상한 1회는 코드가 강제.
4. **비밀은 어디에도 평문 금지.** API 키(이번 사이클 OpenAI 1개)와 DB 접속 정보는 환경
   변수로만. `.env`는 gitignore.
5. **완료 게이트**: spec의 "완료 검증 게이트" 5항목(pytest·ruff·mypy·평가 하네스·실동작 3종
   시연)이 전부 통과해야 완료 선언.
6. **답변 계약 JSON 스키마와 근거 ID 체계는 다음 사이클 L2가 이어받는 계약**이다. 편의로
   구조를 바꾸지 말 것(바꾸려면 사용자 승인).

## 작성 중 포착된 의도 (spec/plan에 못 실은 것)

- **기각 순간이 데모의 주인공.** 웹 폼 UI 판단이 필요할 때는 "기각·인계가 가장 잘 보이는 쪽"을
  택한다. 예쁜 챗 UI보다 판정 과정 노출이 우선.
- **LangGraph 미채택은 거절이 아니라 전시 전략.** 자체 루프로 내부 동작을 설명할 수 있음을
  보여주되, README 비교 문서로 프레임워크 이해도 키워드는 확보한다. 실행 중 "LangGraph를 쓰면
  더 쉬운데"라는 판단이 들어도 되돌리지 말 것.
- **PII allowlist 설계(근거 유래만 허용)는 이 게이트의 정교함을 보여주는 셀링 포인트**로
  선택된 것이다. 단순 전면 차단으로 "개선"하지 말 것. 단 커버리지는 패턴형 PII뿐이라는 한계를
  README·면접 서술에 그대로 남긴다 — 과장이 오히려 역공 지점이고, 비패턴형(이름·주소)은
  L2 이월이라고 말하는 것이 방어다.
- **기각 유발 장치(미끼 조항·기각 유발 문의·L1 픽스처 셋)는 데모·지표의 신뢰성 장치다.**
  "테스트 데이터 정리" 명목으로 제거하거나 미끼 조항을 "문서 품질 개선"으로 채워 넣지 말 것 —
  기각 장면이 재현되지 않으면 제품 서사가 무너진다.
- **3-doc은 버전관리에 포함한다** (2026-08-04 사용자 승인). `.gitignore`의 `.dryforge/` 제외를
  해제했고, `go`의 커밋에 3-doc 변경이 함께 실린다 — spec이 사이클 간 ground truth이므로
  이력이 남아야 한다.
- **차별화 축은 신뢰성 지표**(검출률·오탐률)이지 생산성 지표(응답 시간 단축)가
  아니다. README·리포트 서술에서 이 축을 유지.
- 이 저장소의 `HANDOFF.md`(대문자, 루트)는 /ready 이전의 임시 세션 문서다. 이 3-doc이 생겼으니
  역할이 끝났다 — go 실행 시 삭제하거나 세션 저널로 성격을 바꿔도 된다. `기획-입력.md`는 이력
  자료로 유지.
- 전역 환경에 개발 세션 수집 훅이 설치되어 있다(이 세션 자체가 별도 프로젝트의 데이터).
  훅·로그를 건드리지 말 것.

## Project Foundation

> **비실행 프로젝트 컨텍스트** — `go`는 이 절을 컨텍스트 + 하네스 씨앗으로 읽는다.
> 구현 대상이 아니다. 구현 대상은 spec.md에만 있다.

### 1. 프로젝트 정체성

- **무엇**: 근거 없는 답변은 스스로 reject하는 이커머스 CS 답변 에이전트. 검증이 주인공이고
  RAG는 재료. 데모 첫 3초 = 답변이 기각되는 순간.
- **누구를 위해**: 한국어 사용자를 대상으로 한 시연·설명. 담당 영역은 "제품 안에서 AI
  산출물 검증" 하나다 — LLM API·프롬프트 / RAG / 에이전트 / Python 백엔드 / 평가·운영.
  그 밖의 영역(혼자 출시·풀스택·배포·MCP·자동화)은 다른 프로젝트가 맡는다 — 여기서
  무리하게 다 넣지 않는다.
- **규모·제약**: 단일 개발자, 합성 데이터, 실사용자·실운영 없음. 면접 시연·설명이 목적이므로
  운영급 인프라는 불필요하지만, 게이트 검증 로직과 평가 지표는 실제 제품 수준으로 촘촘해야
  신뢰성 서사가 선다. 데이터·문의는 한국어.
- **차별화 축**: 같은 소재(고객상담 AI)가 대개 생산성 지표를 낼 때, 이쪽은 신뢰성 지표
  (hallucination율·검출률·오탐률)로 축을 다르게 간다.
- **주의**: 과거 provenance 프로젝트의 설계는 흡수하지 않는다(폐기됨) — citation·근거 추적은
  이 프로젝트에서 백지부터 설계한 것이 현 spec이다.

### 2. 도메인 모델 (프로젝트 전체)

**엔티티**: 문의(order_no?·content·최종 상태) / 시도(초안 + L1 판정, 문의당 최대 2건) /
초안 답변(claim 목록, claim = 문장 + citation_ids) / 근거(정책 조항 청크 `policy:*` |
SQL 결과 스냅샷 `sql:*`) / L1 판정(pass | reject + 사유 목록) / 정책 문서(조항 단위,
모호·상충·미끼 조항 심음) / 합성 주문 DB 500건 / 골든셋(허용 결과 집합 라벨 부착 문의 30건) /
L1 픽스처 셋(측정용 고정 초안+근거 쌍) / 상담원 인계(사유 코드 포함 종결).

**게이트 2층 구조 (설계 결정, 일정 타협 아님)**:
- **L1 (결정론적, 이번 사이클)** — citation 존재·참조 무결성·스키마 준수·패턴형 PII(근거 유래
  allowlist; 이름·주소 등 비패턴형은 L2 이월). 코드 검사, LLM 0회, 100% 재현. L1만으로도
  게이트는 동작하므로 L2는 단일 실패점이 아니다.
- **L2 (확률론적, 차기 사이클)** — L1 통과분만 LLM-as-a-judge가 claim 단위로 근거 대조.
  현 답변 계약(claim + citation_ids)과 근거 스냅샷이 L2의 입력 계약이 된다.

**핵심 규칙** (상세·enum은 spec이 정본):
- 한 답변에 두 종류 근거(정책 + 주문)가 공존할 수 있는 것이 구조적 특징.
- 모든 claim은 citation을 딛고 서야 하고, citation은 실제 수집된 근거만 가리켜야 한다.
- 근거가 부족하면 생성하지 않는다(초안 전 인계) — 지어낼 기회 자체를 차단.
- 기각 → 사유 피드백 재생성 1회 → 재기각 시 인계. 상한은 코드가 강제.
- 상태 전이: 접수 → (초안 전 인계 | 초안 → L1 → (확정 | 재생성 → L1 → (확정 | 인계))).
  역방향 전이 없음, answered/escalated는 종결 상태.

### 3. 기술 결정 (사용자 확정분만)

- **스택**: Python / FastAPI. uv(패키지) + pytest(테스트) + ruff(린트/포맷) + mypy(타입).
- **LLM**: 생성 계열은 OpenAI(`gpt-5.6-terra` 기본, 합성 데이터 1회 생성만 상위 모델 + Batch),
  임베딩은 OpenAI `text-embedding-3-small`. **L2 judge는 OpenAI가 아닌 다른 계열**(계열 미결) —
  같은 계열이면 self-judging bias·blind spot 중첩으로 검출률 지표가 오염된다.
- **저장**: 로컬 Docker Postgres + pgvector 단일 DB (주문 + 벡터 + 처리 기록).
  앱 계정과 SQL 실행용 read-only 계정 분리.
- **에이전트 루프**: 자체 구현 (LangGraph 미사용, README 비교 문서로 키워드 확보).
- **보안 모델**: 인증 없음(데모, 단일 사용자). 보안의 핵심은 text-to-SQL 안전장치 3종과
  PII 게이트, 비밀 관리(환경 변수, 평문 금지). 이것이 이 프로젝트의 보안 정책 전부다.
- **동시성**: 요청 단위 무상태, 공유 가변 상태 없음 — 별도 동시성 제어 불필요(N/A 결정).
- **운영**: 이번 사이클 배포 없음. 로컬 Docker + uv 실행이 전부.

### 4. 향후 범위 (go는 구현하지 않음 — 호환성 판단용 컨텍스트)

- **L2 게이트**: claim 단위 LLM judge. 현 claim/citation 계약과 근거 스냅샷을 입력으로 쓴다.
  judge는 생성과 다른 계열(OpenAI 아님 — 계열 미결).
- **RAG 심화**: 벡터 단독 → 하이브리드(BM25+벡터) → 리랭킹 비교(단계별 recall@k·precision),
  청킹 전략 실험(고정 크기 vs 조항 단위), reject 사유의 "생성 문제 vs 검색 실패" 분해 보고.
- **대시보드**(스택 미정), **웹훅 송출**, **n8n 여부**, **배포**, **MCP**: 모두 미결 또는 차기.
- **지표 확장**: 게이트 도입 전후 hallucination율, L1 필터링에 의한 L2 호출 감소율 → 건당
  비용 절감.
