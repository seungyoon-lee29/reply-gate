# 사이클 3 핸드오프 — 검색 품질 (RAG 심화) (governing doc)

## 문서 역할과 충돌 해소

| 문서 | 역할 | 권위 |
|---|---|---|
| `.dryforge/spec.md` | **무엇을** — 행동 계약, ground truth | 충돌 시 항상 이긴다. 오류는 사용자 승인으로만 수정 |
| `.dryforge/plan.md` | **어떻게·순서** — 태스크와 실행 그래프 | 잠정 청사진. 자유롭게 수정 가능 |
| 기존 코드 | HOW 참고 + 현실 대조 | WHAT 의 권위가 아니다 |

프로젝트 컨텍스트는 harness(`CLAUDE.md`/`AGENTS.md` + `docs/`)가 들고 있다 —
이 핸드오프는 이번 사이클 고유의 통제만 담는다.

## 실행 형태

태스크 12개, 파도 11개(그래프 참조). 작업 전 필독은 harness 규칙 그대로:
`docs/standards.md` → `docs/engineering-notes.md` → 손댈 모듈의 `AGENTS.md`,
그리고 작업 종류별 표(`CLAUDE.md`). 이번 사이클은 **벡터 검색·임베딩** 행과
**평가·지표** 행이 둘 다 걸린다.

**과금선은 T6 앞에 있다.** T1–T5 와 T9 는 전부 무과금으로 완주할 수 있어야 한다.
T6(격자 비교)·T8(재색인)·T10(라이브 3회)이 돈이 나가는 지점이다.

**2026-08-12 사용자 확정 상태:** 수정된 검색 정답 라벨 30건과 blind 재작성 30건은
확정됐다. 사용자가 전략 비교는 기다리라고 명시했으므로 T6 는 새 실행 지시가 있을 때까지
보류한다. 이 확정은 비교 입력만 승인하며, 유료 호출 실행 승인이 아니다.

## 하드 게이트 (실행 에이전트가 코드에서 유도할 수 없는 불가침)

1. **게이트 두 층은 무변경이다.** `gate.py`·`judge.py` 의 동작, 사유 4종·2종, L1 의
   LLM·네트워크 import 금지, L2 의 배치·fail-closed. 이번 사이클은 **게이트 앞**만
   손댄다. 검색이 좋아졌다고 판정을 느슨하게 하지 마라.

2. **재작성 질의 픽스처는 런타임으로 새면 안 된다.** `data/rewritten_queries.jsonl` 은
   오프라인 비교 전용이다. 실행 경로가 읽으면 골든셋 30건 전용 치트가 되고 측정 2 의
   수치가 통째로 무의미해진다. **구조 테스트로 못박고, 그 테스트가 실제로 실패하는지
   확인하라**(참조를 일부러 넣어 빨개지는 것을 본 뒤 되돌린다).

3. **검색 단계 실패는 폴백이고, 배선 누락은 조립 오류다.** 둘을 섞지 마라.
   런타임 호출 실패(재작성·리랭크) → 폴백해서 계속. 전략 켜짐 + 클라이언트 미배선 →
   조립 시점에 명시적으로 죽는다. **L2 호출 실패가 인계인 것은 변함없다.**

4. **조용한 폴백 금지 · 토큰 은폐 금지.** 폴백은 처리 기록과 리포트에 남는다. 실패한
   호출의 토큰도 실비용이므로 센다. 검색 단계 생성 토큰은 생성·임베딩·판정 어디에도
   합산하지 않는다.

5. **평가 장치 제거 금지 — 목록이 둘 늘어난다.** 기존(정책 문서의 미끼·모호·상충 조항,
   골든셋, `l1_fixtures.jsonl`, `judge_fixtures.jsonl`)에 더해
   **`data/retrieval_labels.jsonl`** 과 **`data/rewritten_queries.jsonl`** 이 같은
   자격으로 들어온다. 라벨이 사라지면 이번 사이클 모든 수치의 분모가 사라진다.

6. **라벨은 채점자만 본다.** 어떤 검색 전략도 정답 라벨을 입력으로 받지 않는다.
   비교 하네스 안에서 둘이 가까이 있어 실수로 새기 쉽다 — 테스트로 지켜라.

7. **산출물 보존.** 기존 라이브 실측 6회분 **12개 파일**(`reports/evaluation-live-{1,2,3}`
   · `evaluation-live-l2-{1,2,3}` × `.md`·`.json`)은 덮어쓰지도 지우지도 않는다.
   새 검색 비교 리포트(`reports/retrieval-*`)는 git 추적 대상이고, 추적되는 순간
   저장소의 PreToolUse 훅이 Edit/Write 경로의 사후 편집을 막는다. **훅이 못 잡는 경로가
   하나 있다** — 비교 스크립트 재실행이다. 그래서 하네스가 기존 산출물에 쓰기를 스스로
   거부해야 한다(spec §14).

8. **과금은 명시적으로만.** 상한 $10 안에서 오프라인 비교·재색인은 승인 없이 돈다.
   **라이브 재실측(T10)은 실행 직전에 한 번 더 확인받는다.** 상한을 넘길 상황이면
   실행 전에 멈추고 보고한다. 비밀은 `.env` 에만 — 로그·리포트·오류 메시지에 값 금지.

9. **볼륨 재생성 전 사용자 확인 + 처리 기록 백업·복원.** 차원 변경이나 스키마 확장이
   채택에 포함되면 T8 의 절차를 그대로 탄다. 복원은 **API 로 실제 열어** 확인한다 —
   건수 대조만으로는 부족하다.

10. **미달이면 원복이 기본이다.** 라이브가 오프라인 채택을 반증하면 기존 기본값으로
    되돌리고 실측·원인을 남긴다. **실측이 정당화하지 않는 기본값을 저장소에 남기지
    않는다** — 남기면 "측정해보니 충분해서"라는 채택 근거 전체가 무너진다.

11. **미실행·미측정을 0 으로 채우지 않는다.** BGE-M3 미설치, 라벨 부재, 중단 — 전부
    "미실행 + 사유"다. 기존 리포트 불변식 그대로다.

12. **검증 게이트**(병합 전): `ruff check` · `ruff format --check` · `mypy`(strict) ·
    `pytest` 전체 녹색 + `pytest -m db` **skip 0**. DB 를 재생성했다면 재생성 상태에서
    다시 확인한다.

13. **`.dryforge/` 는 이 저장소에서 버전관리 대상이다 — gitignore 하지 마라.**
    **이 3-doc 은 이미 커밋돼 있다(`da4c6a1`).** 프로듀서가 untracked 로 넘기는 것이
    일반적인 인계 상태지만 여기서는 아니다 — 추적 상태가 정상이고, 더러운 작업 트리도
    이상 징후도 아니다. 이 사실 때문에 멈추지 마라.
    `.gitignore` 는 `.dryforge/worktrees/` 와 `.dryforge/backup/` 만 무시하고, 그 자리에
    "3-doc 본문은 버전관리 대상"이라고 적혀 있다. 사이클 1·2 의 3-doc 이 실제로
    `.dryforge/001/`·`002/` 로 커밋돼 있다.
    - 이번 3-doc 은 사이클 끝에 **`.dryforge/003/` 로 옮겨 커밋**한다(앞 두 사이클과 같은
      방식). 작업 중에는 루트의 `spec.md`·`plan.md`·`handoff.md` 그대로 둔다.
    - **`git rm -r --cached .dryforge/` 를 실행하지 마라.** 이전 사이클이 남긴 추적 상태를
      정리하는 기본 절차지만, 여기서는 **보존 대상인 001·002 를 통째로 추적 해제한다.**
    - 이 항목은 실행 하네스와 무관하다(Claude Code · Codex 어느 쪽이든 같다).

14. **이 사이클은 설계와 실행이 다른 세션·다른 하네스에서 돈다.** 설계 대화는 넘어오지
    않는다 — **이 3-doc 이 전부다.** 그래서 판단이 갈리는 지점을 이 문서에 박아 뒀다.
    문서로 풀리지 않는 것이 나오면 **추측하지 말고 사용자에게 올려라.** 설계 세션에
    물어볼 수 없다는 사실이 escalate-don't-guess 를 더 엄격하게 만든다, 느슨하게가 아니라.
    - Codex 세션에서도 `reports/` 아래 커밋된 산출물은 훅이 막는다
      (`.codex/config.toml` → `.claude/hooks/protect-live-reports.sh codex`).
      막히면 우회하지 말고 그 사실을 보고하라 — 그게 훅의 목적이다.

## 작성 중 확정됐지만 spec/plan 에 자리가 없는 의도

- **이 사이클의 판정 기준은 "측정해서 보여주기"가 아니라 "실제로 좋아지기까지"다.**
  사용자가 그렇게 골랐다. 비교표만 만들고 채택 없이 끝내지 마라. 다만 **어떤 단도
  표적 결함을 개선하지 못하면 기본값을 바꾸지 않는 것**이 올바른 결말이고, 그때는
  그 사실이 이 사이클의 산출이다 — 억지로 채택하지 마라.

- **채택 규칙을 목표선으로 바꾸지 마라.** "recall@5 ≥ 0.9" 같은 경계는 명시적으로
  기각된 선택지다(결정 0006 의 논리 — 측정 전에 목표를 적으면 숫자를 맞추러 간다).
  spec §7 은 경계선이 아니라 **직전 단과의 상대 비교 규칙**이고, 그래서 실측 전에
  정할 수 있다.

- **리랭커가 생성기와 같은 계열(OpenAI)인 것은 알고 고른 것이다.** 판정 계열 분리
  (결정 0004)는 self-judging bias 를 막는 규칙이고, 리랭크는 자기 출력을 평가하는 것이
  아니라 문서를 고르는 일이다. 다만 "생성기와 같은 계열이 재료를 고른다"는 편향
  가능성은 남으므로 **리랭크 없는 구성이 비교표에 함께 있어야 한다** — 그 차이가 곧
  관측이다. 일관성을 이유로 리랭커를 Anthropic 으로 옮기지 마라(판정 계열에 검색
  책임을 얹으면 두 역할이 섞인다).

- **BM25 토큰화를 형태소 분석기로 "개선"하지 마라.** 문자 2-gram 은 의존성을 늘리지
  않으면서 한국어 조사 문제를 우회하는 선택이다. 26개 조항 규모에서 형태소 분석기의
  이득보다 의존성·설치 무게가 크다. 성능이 아쉬우면 그 사실을 비교표에 적는다.

- **비교를 DB 로 끌어들이지 마라.** 인메모리 계산은 편의가 아니라 설계다 — 차원이 다른
  벡터를 `vector(1536)` 에 담을 수 없고, 비교마다 볼륨을 재생성하면 보존하기로 한 처리
  기록이 실험마다 날아간다.

- **리포트 이름 계열을 늘리지 않기로 한 것은 판단이다.** L2 도입 때는 이름을 갈랐고
  (지표 정의 자체가 달라졌으므로) 이번엔 실행 조건 필드로 간다(같은 지표를 다른 설정으로
  잰 것이므로). 구성마다 이름을 늘리면 이름 가드가 조합 폭발한다. **이 판단이 틀렸다고
  보이면 임의로 바꾸지 말고 사용자에게 올려라** — 산출물 이름 규칙은 이 저장소가 한 번
  사고를 낸 자리다(`docs/engineering-notes.md`).

- **검색 개선이 성공하면 지금 가장 안정적인 L2 라이브 기각 장면이 사라진다.**
  무근거 4건(G21–G24)이 검색 단계에서 걸러지면 그 12/12 인계는 더 이상 L2 장면이
  아니다. 사용자는 **새 서사로 재구성**을 골랐다 — "검색이 먼저 거르고, 남은 의미
  결함은 L2 가 잡는다". L2 라이브 재현은 **G18(모순 기각, 사이클 2 에서 3/3)** 이
  맡는다. 이 장면을 살리려고 검색을 일부러 느슨하게 두지 마라.

- **성공 판정 ②를 "생성 토큰 0"으로 재지 마라.** 의도 해석 호출이 검색보다 먼저
  무조건 돌고 그 토큰이 `input_tokens`/`output_tokens` 에 들어간다 — 커밋된
  `reports/evaluation-live-l2-1.json` 의 G17 이 이미 `no_evidence` 인계인데
  `input_tokens 216` 이다. 판정 기준은 **시도(초안) 0건 + 판정 토큰 0** 이다(spec §10-2).
  "정직하게 0 으로 만들자"며 의도 해석 토큰을 새 검색 계열로 옮기지 마라 — 그건 생성
  토큰의 정의를 바꾸는 계약 변경이고 §8-5 의 무변경 목록에 있다.

- **G17 은 "검색이 성공하면 답변으로 끝나도 정답"이다.** 골든셋 라벨이 `answered` 와
  `no_evidence` 인계를 둘 다 허용한다(결정 0008). 표적 관측 ①은 **일치율이 아니라
  채택 근거에 `policy:support:4-1` 이 있는가**로 판정한다 — 그래서 T9 의 근거 ID 필드가
  T10 보다 먼저 서야 한다.

- **목표치 재확정은 이번 사이클 실측 뒤로 미뤄 둔 상태다.** 새 라벨 기준으로는 L2 꺼짐
  기준선(86.7%)도 목표 75% 를 넘어 목표가 이미 현황 추인이 됐다(결정 0008 위험 절).
  T11 에서 결정 0006 갱신으로 닫는다. **그 전에 임의로 숫자를 올리지 마라.**

- **`build_pipeline` 의 판정자 주입 구멍 문제(findings 10)를 이번에 고치지 마라.**
  검색 전략 배선이 파이프라인 조립을 만지게 되어 유혹이 생기는 자리다. 그건 공개 표면
  변경이고 별도 설계가 필요하다고 이미 판단해 둔 항목이다.

- **외부 SDK 규약은 구현 시점에 확인하라** — 임베딩 차원 파라미터(`3-large` 절단),
  저가 모델 ID, BGE-M3 로더 API. 기억으로 쓰지 말 것(프로젝트 규칙: "설정/CLI는
  실행해서 답한다").

- 사이클 1·2 인계 문서가 남긴 규율 그대로: **"고쳤다"는 자기 보고 대신 실제로 넣어보고
  확인한다.** 특히 재작성·리랭크 프롬프트는 표적 케이스(G17·G21–G24)를 실제로 흘려
  보고 조정하라(오프라인은 상한 안에서 자유).

## 완료의 정의

**게이트가 셋이다**(spec §15). 사이클 2 는 둘로 갈랐지만 이번엔 제품 배선이 **채택
결과에 종속**되어 배선 검증을 과금 앞으로 당길 수 없다.

- **(a) 비교 준비 완료 — 무과금.** T1–T5·T9. 검증 명령 전부 + 라벨·픽스처 로더 대조 +
  런타임 격리 구조 테스트 + 대역으로 비교 하네스 완주 + 검색/생성 분해 3분류.
- **(b) 채택과 제품 배선 — 오프라인 과금(상한 안).** T6·T7·T8. 폴백·미배선 테스트는
  **채택 구성이 검색 단계에서 생성 호출을 쓸 때만** 해당한다 — 안 쓰는 구성이 이기면
  "해당 없음"이지 미달이 아니다.
- **(c) 실측과 판정 — 라이브 과금(별도 승인).** T10·T11·T12.
