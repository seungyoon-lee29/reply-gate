## 실행 방식 (내가 정한 것 — plan 에 없다)

- **파도 1·2 의 병렬을 직렬 디스패치로 축소했다.** 객관 조건: Postgres 컨테이너/볼륨 이름이
  compose 에 고정돼 워크트리가 **DB 하나를 공유**하고, 두 번째 DB 를 만드는 것은 하드 게이트
  (볼륨 재생성 0) 위반 + 유료 재색인이다. 각 태스크의 구속 검사가 DB 를 요구해 검증을 분리할
  수도 없다. **워크트리 격리·독립 검증·merge-gate 는 그대로 유지**하고 병렬성만 포기했다.
- **코드 태스크 전부에 병합 전 spec-review 를 붙였다.** 하류에 되돌릴 수 없는 유료 구매가 있고
  커밋된 라이브 리포트는 사후 편집 금지라 이탈이 영구화되기 때문이다. 실제로 값을 했다 —
  T7 은 검사 규율 3건, T4 는 뮤테이션 생존 7건이 이 단계에서 잡혔다.
- 워크트리는 하나를 재활용한다. `.env` 심볼릭 링크 + `uv sync`(워크트리마다 **자기 `.venv`** —
  editable 설치가 절대경로 `.pth` 라 공유하면 본체 소스를 import 한다).
