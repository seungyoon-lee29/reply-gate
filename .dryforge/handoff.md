# 사이클 5 핸드오프 — 마지막 사이클 (governing doc)

## 문서 역할

| 문서 | 역할 | 권위 |
|---|---|---|
| `.dryforge/spec.md` | **무엇을** — 행동 계약, ground truth | 충돌 시 이긴다. 오류는 사용자 승인으로만 수정 |
| `.dryforge/plan.md` | **어떻게·순서** — 태스크 12개와 실행 그래프 | 잠정. 자유롭게 수정 가능 |
| 기존 코드 | HOW 참고 + 현실 대조 | WHAT 의 권위가 아니다 |

프로젝트 컨텍스트는 `CLAUDE.md`/`AGENTS.md` + `docs/` 가 든다.
**유지 규칙: 덧붙이는 곳이 아니라 현재 상태로 갈아 끼우는 곳이다.** 남기는 기준은
"다음 사람이 알아야 하는데 **코드도 git 도 결정 기록도** 말해주지 않는 것" 하나다.

## 실행 모양

```
1파도  T1 초안 판정 · T3 채택 축 · T7 자격 증명/임베딩        (병렬 · 무과금)
2파도  T2 조회 가드 · T4 단계별 시간                          (병렬 · 무과금)
3파도  T5 캐시 토큰
4파도  T6 실행 조건 기록 확장
5파도  T8 풀셋 라이브 3회            ← 과금 · 직전 승인 (약 $1.53)
6파도  T9 재등재                     ← 사람의 결정
7파도  T10 확인 라이브 1회           ← 과금 · 직전 승인 (약 $0.51)
8파도  T11 시연 세 장면              ← 소액 과금
9파도  T12 종결 문서
```

**T2 가 1파도가 아닌 이유**: 조회 가드가 "개인정보 모양"을 판정해야 하는데 **그 모듈에는
개인정보 정규식이 한 줄도 없다.** 정의는 게이트 모듈이 소유하고 T1 이 그 소유를 확정하므로
T2 는 그것을 가져다 쓴다. **자기 정의를 만들면 저장소에 개인정보 정의가 셋이 되고, 그것이
T1 이 닫으려는 결함 그 자체다.**
**T4 가 1파도가 아닌 이유**: 아홉 구간 중 여섯이 근거 수집 모듈 안쪽이라 T1·T3 과 같은 파일을
쓰고, 호출 래퍼는 T7 과 겹친다.

## 하드 게이트 (코드에서 유도할 수 없는 불가침)

`CLAUDE.md` "절대 깨지 않는 것" 7개와 `docs/standards.md` 의 하드 게이트 9개가 **정본**이다.
그 위에 이번 사이클에서만 사는 것:

1. **HTTP 응답 계약 확장 0 · DB 스키마 무변경 · 볼륨 재생성 0.** 계측은 평가 리포트까지만.
   스키마를 건드리면 **유료 재색인**이 딸려 온다.
2. **판정 층 무변경.** 판정 프롬프트 · 픽스처 · 모델 · 캐싱 기본값 중 어느 것도 바꾸지 않는다.
3. **평가 장치는 추가만.** 초안 판정 채점표에 새 우회 케이스를 **더하는 것**은 범위 안,
   기존 케이스를 지우거나 고치는 것은 금지.
4. **커밋된 라이브 리포트를 사후 편집하지 않는다.** 정정은 문서 쪽에 병기.
5. **과금은 명시적으로만.** **"라이브" = 평가 리포트를 사는 풀셋 실행** — 전부 **직전 승인**,
   회당 상한 $10, **재구매 상한 풀셋 세트 1번**(T10 확인 라이브는 재구매하지 않는다).
   시연(T11)은 문의 단위 소액(총 $0.5 미만)이라 승인 대상이 아니다.
   계획 총액 ≈ **$2.04**, 최악 ≈ **$3.6**. **단가 기준일 2026-08-19 — 옮겨 적을 때 함께 옮긴다.**
6. **승격은 사람만.** 요약 보고 → 사용자 확인 → 파일 수정. 코드가 쓰는 경로를 만들지 않는다.
7. **미달이면 원복이 기본, 원복은 축별, 귀인이 갈리지 않으면 사용자 판단.**
8. **자격 증명은 어디에도 평문 금지** — 로그와 테스트 출력까지.

## 기획에서 나왔지만 코드·git·결정 기록이 말해주지 않는 것

- **"마지막 사이클"이 범위를 한 번 뒤집었다.** 설정 객체 덤프의 자격 증명 노출은 처음에 범위
  밖이었다. "다음 세션이 없다"가 확정되자 **"미룸"이 "영구 미조치"로 바뀌므로** 되돌려 넣었다
  (spec §3-6). **같은 논리를 다른 항목에 자동 확장하지 마라** — 이 항목이 특별한 것은 비밀
  규칙이 프로젝트가 낮출 수 없는 하한이기 때문이다.
- **이미 초록이던 검사 셋 — 두 번째 점검이 잡은 차단 3건이 전부 이 형태였다.**
  ① 기권 게이트의 "사유가 결과에 실린다"는 **이미 참**이다(순수 판정 연산이 사유를 담아 준다).
  없는 것은 **근거 묶음 → 리포트** 경로다(T3 이 묶음까지, T6 이 리포트까지).
  ② 검색 순서의 파이썬 합집합 병합은 **이미** 유사도 → 근거 ID 로 정렬한다. 남은 비결정은
  DB 가 상위 `top_k` 를 자를 때뿐이라 구속력 있는 검사는 **DB 마커**여야 한다.
  ③ 측정 1 은 결정론이라 라이브가 새로 알려줄 것이 없다 — 합격선 항목이 아니라 동일성 확인이다.
  **셋 다 "고치기 전에 실패하는가"를 물어야 드러난다.**
- **접기를 전역이 아니라 패턴별로 둔 것은 새 구멍을 막기 위해서다.** 밑줄·빗금을 하이픈으로
  접으면 `a_b@…` 와 `a-b@…` 가 같은 값이 되어 근거 주소를 한 글자 바꾼 지어낸 주소가 통과한다.
  **이 판단이 없으면 전역 접기가 자연스러운 구현이라 그대로 들어간다.**
- **미해결 문서의 "대시 12종"은 범주 이름이 아니다.** 실제로 찍어 확인했다 — 12자 중 대시
  범주는 여섯 자뿐이고 나머지는 수학기호·구두점·연결선이다. **범주로 구현하면 절반이 뚫린 채
  "닫았다"고 기록된다.** 열거 고정 집합으로 다룬다.
- **기권 게이트의 fail-open 은 절반만 결함이다.** 미정의 사유 둘 중 "후보 2건 미만"은 근거
  채택 함수의 설명이 *"여기서 뒤집지 않는다"* 고 명시한 **계약**이다. 통째로 뒤집으면 문서화된
  계약을 실측 근거 없이 되돌리는 것이 된다.
- **확인 라이브(T10)가 생긴 이유.** 재등재가 닫혔다는 증거는 "등재 뒤 첫 실행"인데 산 3회가 곧
  등재 대상이라 **자기 대조**가 된다. **이 실행의 구속 줄은 "보류"가 정상** — 증거는 판정이
  아니라 **"대조 불가가 아니다"** 이다.
- **관측 합격선 3회 중 2회**는 회귀 가드가 이미 쓰는 술어와 같게 맞춘 것이다. 직전 사이클은
  넷 모두 3/3 이었고 **실제 회차는 승격 사유에 그대로 적는다.** 합격선이 걸리는 것은 관측
  항목 1~4 뿐이다.
- **지문을 일곱 칸이나 더하는 이유.** 이번에 바꾸는 동작 축 넷이 **지금 지문(18칸)에 한 칸도
  없다.** 특히 기권 미정의 처리는 바꿔도 기존 지문 값이 전혀 안 움직여, 항목이 없으면 그 변경이
  산출물에 아무 흔적을 남기지 않는다. **지문 확장은 재등재 시점에만 가능하고 이번이 마지막이다.**
  항목 ②(판정 사고 과정)는 기존 판정 effort 칸과 **다른 축이라 새 칸**이다.
- **채점표를 늘리는 대가는 재등재가 흡수한다.** 픽스처를 더하면 측정 1 분모가 바뀌는데, 이번이
  새 기준선을 세우는 사이클이라 대가가 0 이다. **다른 사이클이었으면 넣을 수 없었다.**
- **시연 세 장면의 재현 확률이 서로 다르다.** 장면 3(G21)은 12/12, 장면 2(G30)의 L2 기각은
  3/3 이지만 재기각 인계는 1/3, 장면 1(G16)은 직전 라이브 15 케이스-실행 중 1회로 가장 낮다.
  **예전에 장면 1을 안정적으로 내던 무근거 문의 네 건은 이제 장면 3으로 옮겨 갔다.** 그래서
  장면 1 미재현은 사고가 아니라 예상 범위이고, 미해결 19번을 닫는 것이 **조건부**인 이유다.
  **장면 2(G30)는 주문 문의라 주문번호 `ORD-20260202-0001` 을 함께 넣어야 한다.**

## 함정

**대부분은 durable 문서가 든다** — `docs/engineering-notes.md`(실제로 뚫린 경로와 밟은 함정) ·
`tests/AGENTS.md`(구조 검사 관례·음성 대조·선언값) · `docs/standards.md`(재시도 상한·인용 규율).
**여기에는 그 문서들이 아직 모르는 것만 남긴다.**

- **같은 작업 공간에 다른 세션이 붙어 있으면 편집이 조용히 지워진다.** 편집 성공 응답은 그 뒤의
  덮어쓰기를 말해주지 않는다 — 고친 뒤 실재를 다시 확인하라. 병렬 세션이 같은 DB 를 쓰면 스키마
  적용에서 교착도 난다.
- **되돌린 뒤에는 파이썬 캐시와 테스트 캐시를 함께 지운다.** 안 지우면 되돌린 코드로 테스트가
  계속 빨간불이다.
- **정의를 지울 때 줄 번호를 시작 줄로 쓰지 마라** — 데코레이터가 고아가 되어 수집이 통째로
  죽는다. 린트·타입 검사는 통과하므로 테스트를 돌려야 잡힌다.
- **개인정보 우회 문자는 배치가 가른다.** 결합문자·변이선택자는 숫자열 **안쪽**에 끼워야 뚫리고
  끝에 붙이면 원래도 기각된다. **회귀 검사에 자리 사이 배치를 박아라.**
- **τ 방어를 오프라인 비교 도구에 걸지 마라** — 여러 임베딩 조건을 일부러 훑는 것이 그 도구들의
  일이라, 걸면 실측 자체가 막힌다.
- **미해결 목록의 항목 번호를 다시 매기지 마라.** 저장소 45곳이 이 번호로 인용하는데 **대부분
  번호가 링크 글자에만 있어**, 바꾸면 **링크 검사가 못 잡은 채** 인용이 통째로 다른 항목을
  가리킨다. 앵커로 걸린 10곳만 검사에 잡힌다.
- **시연 문의는 골든셋 원문 그대로 넣어라** — 바꿔 적으면 실측과 다른 것을 잰다.
- **설계 세션은 없다 — 이 3-doc 이 전부다.** 문서로 안 풀리면 추측하지 말고 사용자에게 묻는다.
  소스 주석은 durable 문서만 인용한다(**이 3-doc 을 소스에서 인용하지 마라**).

## 미결로 넘어가는 것

- **OpenAI API 키 로테이션 권고** — 실패한 단언이 테스트 출력에 키 전문을 실은 적이 있다.
  저장소에는 안 들어갔지만 노출은 실제로 났다. 코드는 고쳤고 **T7 이 같은 계열의 남은 경로를
  닫는다.** 로테이션 자체는 사용자 몫이다.
- **미병합 곁가지는 없다** — `git branch -a` 로 확인했다. 남은 가지는 `main` 뿐이다.
- **범위 밖 목록은 spec §10, 두 갈래 재분류는 T12 가 한다.**
