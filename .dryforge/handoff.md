# 사이클 3 핸드오프 — 검색 품질 (RAG 심화) (governing doc)

## 문서 역할과 충돌 해소

| 문서 | 역할 | 권위 |
|---|---|---|
| `.dryforge/spec.md` | **무엇을** — 행동 계약, ground truth | 충돌 시 항상 이긴다. 오류는 사용자 승인으로만 수정 |
| `.dryforge/plan.md` | **어떻게·순서** — 태스크와 실행 그래프 | 잠정 청사진. 자유롭게 수정 가능 |
| 기존 코드 | HOW 참고 + 현실 대조 | WHAT 의 권위가 아니다 |

프로젝트 컨텍스트는 harness(`CLAUDE.md`/`AGENTS.md` + `docs/`)가 들고 있다 —
이 핸드오프는 이번 사이클 고유의 통제만 담는다.

**T1–T7·T9·T10 은 끝났다. T8 은 해당 없음.** 남은 것은 **T11·T12** 이고 **둘 다 문서 작업이라
과금이 없다.** 이 사이클의 과금 지점은 전부 지났다 — 다시 사려면 아래 "남은 판단" 의 재실측
건이고, 그건 사용자 결정이다.

## 이 문서를 유지하는 방식

**어떤 절의 주장이 커밋·문서로 대체되면 그 절을 해시 한 줄로 줄인다.** 사이클 끝을 기다리지
않는다. `.dryforge/` 는 버전관리 대상이므로(하드 게이트 13) 지운 절은
`git log -p -- .dryforge/handoff.md` 에 그대로 남고, 남겨 두면 매 compact 마다 전문이 다시
주입되는 비용만 낸다. 남기는 기준은 하나다 — **다음 사람이 알아야 하는데 코드도 git 도
말해주지 않는 것.** 지우기 전에 갈 곳이 있는지 본다: 트레이드오프 판단 → `docs/tracking/decisions/`,
지금 못 고치는 것 → `findings.md`, 실측·기준선 → `status.md`, 함정·방법론 →
`docs/engineering-notes.md`.

**이 규칙은 인계 게이트 훅이 함께 요구한다** — 갱신 지시가 "덧붙이기가 아니라 대체하기"라고
말하고 현재 크기(줄 수·KB)를 실어 준다. 32KB 를 넘으면 줄이라고 재촉하고, 128KB 를 넘으면
스냅샷을 만들 수 없어 compact 가 막힌다.

## 진행 상태 — **T10 완료·원복 완료, 남은 것은 T11·T12 (무과금)**

### 다음 세션의 **첫 행동 하나** — T11 을 시작한다

**T10 은 끝났다.** 표적 관측 ①(G17, 3/3)·②(G21–G24, 11/12)는 **충족**했고 비악화 가드가
**미달**(G04 0/3)이라 spec §10-3 대로 원복했다. **다만 두 축을 갈라서 되돌렸다** — 컷만
0.30 으로 내리고 **재작성은 유지**한다. 판정표·기전·토큰 대비는 `status.md` "T10 라이브
재실측" 이 들고 있고, 원인 분석은 findings 18 이 들고 있다. 여기 반복하지 않는다.

T11 의 작업 목록은 `plan.md` 에 그대로 있다. 아래 세 가지만 **plan 작성 시점에 몰랐던 것**이라
따로 적는다.

### T11·T12 가 부딪힐 것 — **T10 이 만든 새 사실 셋**

1. **G18 의 L2 모순 기각이 사라졌다.** 사이클 2 는 3/3 회 `contradictory_evidence` 기각,
   T10 은 3/3 회 첫 시도 통과다. 원인은 컷 0.50 이 상충 조항 `policy:refund:2-4`(0.4676)를
   자른 것이고 **컷을 0.30 으로 되돌렸으니 기전상 복구된다 — 그러나 그 조건의 라이브 실측이
   없다.** spec §16 과 T12 가 이 장면 위에 서 있으므로, **재실측 없이 "G18 이 기각한다"고
   README 에 쓰지 마라.** 쓸 수 있는 것은 "사이클 2 에서 3/3 재현됐고, T10 의 컷 0.50 이
   그것을 없앴으며, 컷을 되돌렸다"까지다.

2. **데모용 기각 처리 기록이 DB 에 없다**(findings 19 — `inquiry_attempts` 0행).
   findings 6 이 "`GET /inquiries/{id}` 로 열린다"고 적은 그 기록이다. 즉 **T12 시점에
   기각 장면이 DB 에도 없고 골든셋 라이브 산출물에도 없다.** 무엇을 어떤 조건으로 다시
   만들지는 데모 서사 결정이라 사용자 몫이다 — 임의로 문의를 흘려 만들지 마라(과금·비결정론).

3. **결정 0009 갱신 사안이 하나 생겼다.** 채택 규칙(spec §7)에 *"라벨이 있는 케이스가 채택
   근거 0건이 되면 안 된다"* 가 없어서 오프라인 격자가 컷 0.50 을 골랐다. G04 의 전면 실패는
   §4-3 규약대로 precision 분모에서 빠지고 recall 에서만 0.04 를 냈는데 같은 구간 macro F1 은
   0.403 → 0.676 으로 **올랐다.** **규약이 틀린 것이 아니다** — 제품 사건(정상 문의가 인계됨)과
   집계 단위가 다른 것이다. findings 18 에 전문이 있다. 결정 0009 를 확정할 때 이 조건을
   명시할지가 판단 지점이다.

### 남은 판단 — **전부 사용자 몫이고 코드 수정이 아니다**

- **원복 구성(재작성 + 컷 0.30)의 라이브 실측이 없다.** 컷 0.30 은 사이클 1·2 가 6회, 재작성은
  T10 이 3회 실측했지만 **조합은 재지 않았다.** 재실측은 과금(3회 ≈ 46만 토큰)이라 사용자
  판단이다. **안 사기로 하면 T11·T12 는 "각 축은 측정됐고 조합은 미측정"이라고 적어야 한다** —
  측정하지 않은 것을 측정한 것처럼 쓰지 않는다.
- **목표 75% 가 새 라벨에선 L2 없이도 달성된다**(L2-off 기준선 86.7%). T10 은 96.7% 다.
  `evaluation.TARGETS` 주석에 폐기된 전제가 남아 있다. 결정 0006 갱신이 T11 이다.
- **결정 0007 의 "배치만이 모순 감지를 보존한다"가 false dichotomy** — claim별 support 호출
  + 전체 근거 contradiction 호출로 나누는 hybrid 를 검토하지 않았다. J11 이 그 비용이다.
- **J11 라벨 자체가 틀렸을 수 있다** — C 슬라이스 3명이 독립적으로 "환불 7일 vs 반품 14일이
  같은 사안인지 입력에 명시되지 않는다"고 지적했다. 판정기가 옳고 픽스처가 틀렸을 가능성.
  **T10 3회 모두 같은 방식으로 어긋났다** — 잡음이 아니다.
- **`bait_reject_recall` 이름이 과장이다** — 분자가 `rejected_at_least_once`(층·사유 무관)라
  T10 의 13.3% 는 "reject_bait 범주의 any-layer 기각률"이고, 남은 2건은 **둘 다 G16 의 L1
  `missing_citation`** 이다. `pii_detected` 는 여전히 0/15.
- **범위 결정 2건이 findings 에서 대기 중이다** — 16(**빈** 정책 인덱스는 아직 `no_evidence`
  로 위장한다. 낡은 인덱스만 503 이 됐다)과 17(조회 라우트가 쓰지도 않는 RO 계정에 묶여
  있다). 둘 다 "안 고치는 이유"까지 적혀 있고 고르는 것이 사용자 몫이다.
- **A4 2건은 등급 동결 확정이다** — `GROUP BY` 별칭이 시스템 컬럼 검사를 가림 · 같은 `WITH`
  안 중복 CTE 이름. 둘 다 심층 방어 침식이지 활성 유출이 아니다(전자는 그 경로로 시스템 컬럼
  값이 출력되는 쿼리를 만들지 못했고, 후자는 PostgreSQL 이 그 쿼리를 거부한다).
  **등급을 올리지 마라.**

### 이 사이클이 남긴 방법론 — 사이클 4 로 가져갈 것

- **적대리뷰를 상설 게이트로 올려라.** 사이클 3 의 완성도 차이는 설계가 아니라 리뷰에서 왔다.
- **수확은 버그가 아니라 "숫자가 라벨이 말하는 것을 뜻하지 않는다"였다.** 이 계열은 테스트로도
  라이브로도 안 잡힌다 — 전부 녹색이고 전부 숫자를 낸다. **T10 이 세 번째 사례를 보탰다**:
  G18 의 회귀는 일치율에도(결정 0008 이 라벨을 내림) 비악화 가드에도(`matched=True`) 측정 3
  에도(픽스처 기반) 안 잡혔고, **T9 가 넣은 분해 절 하나만 잡았다.**
- **검색 층에 무언가를 더하거나 조일 때는 "이것이 조용히 적게 돌려줄 수 있는가"를 먼저 물어라.**
  이 계열은 오류가 아니라 **업무 판정으로 위장한다**(검색이 짧아지면 `no_evidence` 가 늘고 그
  수가 "검색 품질"로 리포트에 실린다). HNSW 건·낡은 인덱스 건(findings 16)·T10 의 컷 0.50 이
  전부 같은 모양이다.
- **이미 관대하게 설명해 둔 이상 신호를 공격 대상으로 지목하라.** `pii 0/15` 와 `J11` 을
  루브릭에 박았더니 리뷰어 7명이 독립적으로 그 설명을 깼다.
- **보안 슬라이스는 Codex 제공자 필터에 걸릴 수 있다.** 12회 중 2회가 그렇게 죽었다.
  재시도하거나 Claude 서브에이전트로 그 슬라이스만 돌리는 우회가 필요하다.

## 하드 게이트 (실행 에이전트가 코드에서 유도할 수 없는 불가침)

1. **게이트 두 층은 무변경이다.** `gate.py`·`judge.py` 의 동작, 사유 4종·2종, L1 의
   LLM·네트워크 import 금지, L2 의 배치·fail-closed. 이번 사이클은 **게이트 앞**만
   손댔다. 검색이 좋아졌다고 판정을 느슨하게 하지 마라.

2. **재작성 질의 픽스처는 런타임으로 새면 안 된다.** `data/rewritten_queries.jsonl` 은
   오프라인 비교 전용이다. 실행 경로가 읽으면 골든셋 30건 전용 치트가 되고 측정 2 의
   수치가 통째로 무의미해진다. 구조 테스트가 못박고 있고 **그 검사는 문자열 상수까지 본다** —
   런타임 모듈의 주석·docstring 에 픽스처 파일명을 적어도 걸린다. 가드를 느슨하게 하지 말고
   문장을 바꿔라.

3. **검색 단계 실패는 폴백이고, 배선 누락은 조립 오류다.** 둘을 섞지 마라.
   런타임 호출 실패(재작성·리랭크) → 폴백해서 계속. 전략 켜짐 + 클라이언트 미배선 →
   조립 시점에 명시적으로 죽는다. **L2 호출 실패가 인계인 것은 변함없다.**

4. **조용한 폴백 금지 · 토큰 은폐 금지.** 폴백은 처리 기록과 리포트에 남는다. 실패한
   호출의 토큰도 실비용이므로 센다. 검색 단계 생성 토큰은 생성·임베딩·판정 어디에도
   합산하지 않는다.

5. **평가 장치 제거 금지.** 정책 문서의 미끼·모호·상충 조항, 골든셋, `l1_fixtures.jsonl`,
   `judge_fixtures.jsonl`, **`data/retrieval_labels.jsonl`**, **`data/rewritten_queries.jsonl`**,
   **`data/rewritten_queries_oracle.jsonl`**. 라벨이 사라지면 이 사이클 모든 수치의 분모가
   사라진다.

6. **라벨은 채점자만 본다.** 어떤 검색 전략도 정답 라벨을 입력으로 받지 않는다.
   비교 하네스 안에서 둘이 가까이 있어 실수로 새기 쉽다 — 테스트로 지켜라.

7. **산출물 보존.** 라이브 실측 **9회분 18개 파일**(`reports/evaluation-live-{1,2,3}` ·
   `evaluation-live-l2-{1..6}` × `.md`·`.json`)과 검색 비교 리포트(`reports/retrieval-*`)는
   덮어쓰지도 지우지도 않는다. 전부 git 추적 대상이고, 추적되는 순간 저장소의 PreToolUse
   훅이 Edit/Write 경로의 사후 편집을 막는다. **훅이 못 잡는 경로가 하나 있다** — 스크립트
   재실행이다. 그래서 하네스가 스스로 거부한다(spec §14, `resolve_report_stem`).

8. **과금은 명시적으로만.** 상한 $10 안에서 오프라인 비교·재색인은 승인 없이 돈다.
   **라이브 실측은 실행 직전에 한 번 더 확인받는다.** T10 은 이 절차로 돌았다.
   상한을 넘길 상황이면 실행 전에 멈추고 보고한다. 비밀은 `.env` 에만 — 로그·리포트·오류
   메시지에 값 금지.

9. **볼륨 재생성 전 사용자 확인 + 처리 기록 백업·복원.** 복원은 **API 로 실제 열어** 확인한다 —
   건수 대조만으로는 부족하다. **이 조항이 지켜지지 않은 실측 사례가 findings 19 다** —
   08-13 재생성에서 보존 대상 2건이 사라졌고 건수만으로는 드러나지 않았다.

10. **미달이면 원복이 기본이다.** **실측이 정당화하지 않는 기본값을 저장소에 남기지 않는다.**
    T10 이 이 게이트를 실제로 탔다(`72ff2d4`) — 컷은 반증돼 되돌렸고 재작성은 정당화돼
    남겼다. **축을 갈라 되돌리는 것은 spec §10-3 의 문자 그대로가 아니므로 사용자 결정이었다.**

11. **미실행·미측정을 0 으로 채우지 않는다.** BGE-M3 미설치, 라벨 부재, 중단 — 전부
    "미실행 + 사유"다. 기존 리포트 불변식 그대로다.

12. **검증 게이트**(병합 전): `ruff check` · `ruff format --check` · `mypy`(strict) ·
    `pytest` 전체 녹색 + `pytest -m db` **skip 0**. DB 를 재생성했다면 재생성 상태에서
    다시 확인한다.

13. **`.dryforge/` 는 이 저장소에서 버전관리 대상이다 — gitignore 하지 마라.**
    **이 3-doc 은 이미 커밋돼 있다(`da4c6a1`).** 프로듀서가 untracked 로 넘기는 것이
    일반적인 인계 상태지만 여기서는 아니다 — 추적 상태가 정상이고, 더러운 작업 트리도
    이상 징후도 아니다. 이 사실 때문에 멈추지 마라.
    - 이번 3-doc 은 사이클 끝에 **`.dryforge/003/` 로 옮겨 커밋**한다(앞 두 사이클과 같은
      방식). 작업 중에는 루트의 `spec.md`·`plan.md`·`handoff.md` 그대로 둔다.
    - **`git rm -r --cached .dryforge/` 를 실행하지 마라.** 이전 사이클이 남긴 추적 상태를
      정리하는 기본 절차지만, 여기서는 **보존 대상인 001·002 를 통째로 추적 해제한다.**
    - 이 항목은 실행 하네스와 무관하다(Claude Code · Codex 어느 쪽이든 같다).

14. **이 사이클은 설계와 실행이 다른 세션·다른 하네스에서 돈다.** 설계 대화는 넘어오지
    않는다 — **이 3-doc 이 전부다.** 문서로 풀리지 않는 것이 나오면 **추측하지 말고 사용자에게
    올려라.** 설계 세션에 물어볼 수 없다는 사실이 escalate-don't-guess 를 더 엄격하게 만든다,
    느슨하게가 아니라.
    - Codex 세션에서도 `reports/` 아래 커밋된 산출물은 훅이 막는다

      막히면 우회하지 말고 그 사실을 보고하라 — 그게 훅의 목적이다.

## T11·T12 에 남은 계약

T7·T10 이 소진한 항목은 지웠다(재작성 자리·프롬프트 단일 소유·합집합·폴백 규칙·리랭커 계열·
BM25 토큰화·외부 SDK 규약·라이브 과금 절차 → 전부 코드·`docs/`·커밋이 들고 있다).
남은 것은 **T11·T12 가 실제로 부딪힐 것들**이다.

- **성공 판정 ②를 "생성 토큰 0"으로 재지 마라.** 의도 해석 호출이 검색보다 먼저 무조건 돌고
  그 토큰이 `input_tokens`/`output_tokens` 에 들어간다. **T10 이 이것을 실측으로 확정했다** —
  G21–G24 가 검색 단계에서 기권한 실행에서도 `input_tokens` 208~213 이 남았다. 기준은
  **시도(초안) 0건 + 판정 토큰 0** 이다(spec §10-2).

- **리포트 이름 계열을 늘리지 않는다.** 검색 구성은 같은 지표를 다른 설정으로 잰 것이라
  **실행 조건 필드**가 맞는 자리다(T7 이 `retrieval_strategy`·`embedding_dimensions` 를
  넣었고 T10 산출물이 그것을 싣고 있다). L2 켜짐 실측의 자동 넘버링을 그대로 쓴다.
  **이 판단이 틀렸다고 보이면 임의로 바꾸지 말고 사용자에게 올려라** — 산출물 이름 규칙은
  이 저장소가 한 번 사고를 낸 자리다(`docs/engineering-notes.md`).

- **`build_pipeline` 의 판정자 주입 구멍(findings 10)을 고치지 마라.** 공개 표면 변경이고
  별도 설계가 필요하다고 이미 판단해 둔 항목이다. T7 이 넓힌 드리프트 면적은
  `tests/test_testing_doubles.py` 가 두 조립의 재작성 배선까지 대조해 덮는다.

- **T12 의 새 서사는 "검색이 먼저 거르고(비용 0), 남은 의미 결함은 L2 가 잡는다"였다.**
  T10 이 그 전반부를 실측했지만(표적 관측 ② 11/12, 판정 토큰 -22.9%) **그것은 컷 0.50
  조건의 수치이고 그 컷은 되돌렸다.** 되돌린 구성에서 이 서사가 몇 %로 성립하는지는
  재실측 전에는 모른다. **컷 0.50 의 수치를 현재 기본값의 수치인 것처럼 README 에 싣지 마라.**
  기각 장면을 살리려고 검색을 일부러 느슨하게 두지 않는다는 원칙은 그대로다.
