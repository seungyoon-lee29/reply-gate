# 사이클 4 핸드오프 — 채택 축과 회귀 가드 (governing doc)

## 문서 역할과 충돌 해소

| 문서 | 역할 | 권위 |
|---|---|---|
| `.dryforge/spec.md` | **무엇을** — 행동 계약, ground truth | 충돌 시 항상 이긴다. 오류는 사용자 승인으로만 수정 |
| `.dryforge/plan.md` | **어떻게·순서** — 태스크 13개와 실행 그래프 | 잠정 청사진. 자유롭게 수정 가능 (spec 의 행동 계약을 바꾸면 사용자 승인) |
| 기존 코드 | HOW 참고 + 현실 대조 | WHAT 의 권위가 아니다 |

프로젝트 컨텍스트는 harness(`CLAUDE.md`/`AGENTS.md` + `docs/`)가 들고 있다.
유지 규칙: **대체된 절은 즉시 해시 한 줄로 줄인다.** 남기는 기준은 "다음 사람이 알아야
하는데 코드도 git 도 말해주지 않는 것" 하나다.

## 실행 모양 (2026-08-19 개정 — 적대리뷰 반영)

파도 9개 / 태스크 13개: {T0 손계산, T1 가드} → {T2 기준선⚠, T3 격자} → {T5 채택 결정,
T12 청킹} → T9 배선 → T10 라이브 판정⚠ → T6 J11 → {T7 judge 비교, T8 캐싱} → T11 비용
문서 → T13 문서·README·데모. ⚠ = **풀셋 라이브 과금**(실행 직전 사용자 승인, 두 번뿐).
T5·T12·T6·T7·T8·T13 은 **소액 등급**이라 상한 안에서 승인 없이 실행한다.

**핵심 착륙은 T0·T1·T2·T3·T5·T9·T10(= spec §3·§4·§5)이다.** 조이면 나머지(§6·§7·§8
계열: T6·T7·T8·T11·T12)를 뒤로 미룬다 — **미루는 순서까지는 정해져 있지 않으니 그
시점에 사용자에게 묻는다.**

**개정에서 바뀐 것 셋** — 이전 청사진을 기억하는 사람을 위해:
1. **T0 신설** — 후보 공간 손계산이 파도 1 이다. 사이클 3 은 도달 불가능한 후보군에
   라이브를 태울 뻔했다. 답이 공짜로 나오는 질문을 유료 실측 뒤에 두지 않는다.
2. **T4(상충 후보 탐지기) 삭제** — 컷 0.30 이 세 상충쌍을 이미 채택하므로 고칠 것이
   없고, 성립 조건은 코퍼스의 `planted` 주석 때문에 통과가 보장된 검사였다. **번호는
   재사용하지 않는다.**
3. **T6·T7·T8 이 T10 뒤로** — 셋 다 판정 층을 건드린다. T10 앞에 두면 승격 기준선 대비
   T10 이 채택 축 말고도 판정 층 변수를 들고 있어 축별 원복이 귀인 불가능해진다.
   spec §7-2 가 이 순서를 명시하도록 개정됐다. **이제 §6·§7 을 통째로 미뤄도 핵심
   착륙이 죽지 않는다** — 이전 청사진에서는 T9 가 T8 에 매달려 있었다.

**T5 가 "채택 없음"으로 끝나면 T9·T10 은 건너뛰고 반증 서사로 간다** — 원복이 아니라
애초에 바꾸지 않은 것이며, 이것도 정상 결말이다(spec §13).

## 사용자가 정한 것 중 spec/plan 에 다 담기지 않는 맥락

- **우선 가치는 전시 서사다.** 같은 작업이라도 "README 에 실릴 장면·표가 나오는가"로
  범위를 자른다. 단, 서사를 위해 측정을 굽히지 않는다 — 반증이면 반증이 서사다.
- 사용자는 남은 주제 넷을 **전부** 이번 사이클에 담기를 원했고, 대신 핵심 착륙을 채택
  축+회귀 가드로 지정했다.
- **감사에서 잡혀 사용자가 추가 확정한 것 넷**: ① **G18·G01·G02** 상충쌍 동시 채택을
  성공 판정의 구속 조건으로(헤드라인이 3방향이 된 이유. **G02 는 심은 쌍
  `shipping:1-3`/`1-4` 를 라벨로 갖는데 적대리뷰 전까지 빠져 있었다**) ② 이중 기준선 중 **승격이 구속,
  직전은 경보** ③ judge 비교표는 **비교만**(교체는 별도 결정) ④ 캐싱은 "무변화+절감
  실측 → 기본 켜짐" 규칙을 **사전 승인**.
- **총액 상한은 두지 않는다** — 회당 $10 + 건별 승인이 통제다(예상 합계 ~$20 안팎).
- 비동기화는 **검토 문서까지**다(구현 금지). 청킹은 **측정까지**다(반영 금지).

## 하드 게이트 (코드에서 유도할 수 없는 불가침)

1. **게이트 두 층의 판정을 느슨하게 하지 않는다.** L1 사유 4종·L2 사유 2종·배치·
   fail-closed·산출 검증 무변경. 이번 사이클의 판정기 변경은 **강화만**이고(spec §6-2),
   J11 을 잡으려고 픽스처 사안을 특정하는 프롬프트 문구를 넣는 것은 치트다.
2. **평가 장치 제거 금지 + J11 픽스처 수정은 사용자 승인·전후 병기로만**(결정 0008
   전례). 목록: 미끼·모호·상충 조항, 골든셋, `l1_fixtures`·`judge_fixtures`·
   `retrieval_labels`·`rewritten_queries`·`rewritten_queries_oracle`.
3. **정답은 채점자만 본다 — 그리고 정답은 라벨 파일에만 있는 것이 아니다.** 전략·
   런타임 어느 것도 정답 라벨·골든셋을 입력으로 받지 않고, **정책 코퍼스의
   `planted`/`planted_note` 도 같은 자격으로 금지**다(구조 테스트로 못박는다).
   `data/policies/shipping.md`·`refund.md` 의 `<!-- planted: conflicting; note: … -->`
   는 짝의 조항 번호까지 적어 둔 **정답 그 자체**이고 `policy_index` 가 이미
   `PolicyChunk.planted` 로 1급 노출한다 — 라벨만 막으면 12줄짜리 정규식이 심은 쌍
   2개를 오탐 0 으로 맞힌다. 적대리뷰 심판 5인이 전원 독립으로 이 경로를 찾았다.
4. **승격 기준선 갱신은 명시적 사용자 결정으로만.** 하네스 자동 승격 경로 금지. 구속은
   승격 기준선, 직전 라이브는 경보 — 이 배치를 한 줄로 합치지 마라.
5. **미달이면 원복이 기본 · 실측이 정당화하지 않는 기본값을 남기지 않는다** — 축별
   원복(결정 0011). 캐싱 채택도 같은 자격: 무변화+절감이 실측되지 않으면 켜 두지 않는다.
6. **이번 사이클 API 응답 계약 확장 0.** `failed_stage` 노출 포함 전부 범위 밖.
7. **처분 고정**: judge 기본 모델 교체 금지 · 청킹 제품 반영 금지 · 비동기화 구현 금지.
   셋 다 "측정·검토 + 별도 결정 기록"까지다.
8. **조용한 폴백·토큰 은폐 금지.** 검색 계열 분리 유지, 캐시 write/read 토큰은 판정
   토큰 정의를 왜곡하지 않게 분리 표기 + 단가 명시 달러 환산. **캐싱을 켜면
   `usage.input_tokens` 가 캐시 적중분을 제외한 값이 되는데 `llm.py` 는 지금 그것만
   읽는다** — `cache_creation_input_tokens`·`cache_read_input_tokens` 를 수집하지 않은
   채 절감을 주장하면 이 게이트 위반이다(T8). **단가 표는 저장소에 아직 없다 — T11 이
   만든다.** 기준일 없는 달러 수치는 싣지 않는다.
9. **미실행·미측정을 0 으로 채우지 않는다.** **선언되지 않은** 지문 불일치는 "대조 불가
   + 어긋난 항목", 승격 부재는 "기준선 미등재"로 명시한다(선언된 실험 변인은 차이를
   병기하고 대조를 진행한다 — spec §5-3).
10. **과금은 명시적으로만.** 회당 상한 $10, 라이브는 실행 직전 개별 승인, 넘길 상황이면
    멈추고 보고. 비밀은 `.env` 에만.
11. **산출물 보존.** 커밋된 라이브 **9회분**(`evaluation-live-{1..3}`·`-l2-{1..6}` —
    3회 = 1세트이므로 3세트다)과 `retrieval-*` 리포트 전부 덮어쓰기·삭제·사후 편집
    금지. 새 실행은 이름을 올려 붙인다. 리포트 이름 계열은 늘리지 않는다.
    **단, 라이브 이름의 자격 판정 근거는 `measurement2_is_real` 에서 "과금 실행 여부"로
    바꾼다**(T1). 지금 규칙대로면 측정 3 단독 실측이 `evaluation` 스템으로 떨어져
    gitignore 되고 다음 실행에 덮인다 — **과금된 4~5세트가 통째로 유실된다.**
12. **재작성 픽스처 런타임 격리 유지**(구조 테스트 — 문자열 상수·docstring까지 본다.
    가드를 느슨하게 하지 말고 문장을 바꿔라).
13. **검증 게이트**: `ruff check`·`ruff format --check`·`mypy`·`pytest` 녹색 +
    `pytest -m db` skip 0. DB 는 `docker compose up -d --wait` 가 전제다.
14. **스키마·볼륨 무변경 사이클이다.** 볼륨 재생성이 필요해지는 설계가 나오면 진행 전에
    사용자 확인 + 처리 기록 백업·복원 절차(findings 19 가 위반의 실측 사례).
15. **`.dryforge/` 는 버전관리 대상** — gitignore 금지. 사이클 끝에 3-doc 을
    `.dryforge/004/` 로 옮겨 커밋한다(001~003 전례).
16. **회귀 가드의 술어를 `matched` 하나로 되돌리지 마라.** 이 사이클의 출발점인 G18
    회귀는 `matched=True` 로 통과했다(커밋된 `evaluation-live-l2-{1,3,4,5,6}` 6회 전부).
    비악화 판정은 **근거 부분 손실 검사와 두 겹**이어야 하고, 귀인 필드
    `missing_relevant_evidence_ids` 는 표기가 아니라 **판정 조건**이다(spec §5-2).
17. **설계 세션은 없다 — 이 3-doc 이 전부다.** 문서로 안 풀리면 추측하지 말고 사용자에게.
    소스 주석은 durable 문서만 인용한다(`tests/test_durable_citations.py` 가 막는다 —
    이 3-doc 을 소스에서 인용하지 마라).

## 함정 (사이클 3 에서 물려받은 것)

- **세션 한도**: 서브에이전트 대량 병렬은 ~1M 토큰에서 끊길 수 있다. 검증류는 소규모
  분할로.
- **링크 검사는 프래그먼트까지.** 앵커 무시 검사기가 "0건 깨짐"을 잘못 말한 전례가 있다.
- **확률 층 장면에 "항상"을 붙이지 마라**(G30 교훈 — "3/3"은 관측이지 결정론이 아니다).
- 커밋 메시지의 주장은 반증될 수 있다 — 정정은 문서 쪽에만 남는다.
- 기권 판정 기준은 "시도 0건 + 판정 토큰 0"이다. "생성 토큰 0"으로 재지 마라(의도 해석이
  먼저 돈다).

## 함정 (2026-08-19 적대리뷰가 새로 드러낸 것)

- **τ 는 임베딩 모델에 묶인다.** 손계산에서 `text-embedding-3-small` 1536 은 분리했고
  (여유 +0.0147) `-3-large` 계열은 분리하지 못했다(−0.0114 / −0.0160). 전 조건 공통 τ 는
  없다. 임베딩을 건드리는 순간 게이트가 **조용히 무력해진다.**
- **경계는 케이스 2건이 정한다.** 기권 쪽 G23 · 채택 쪽 **G15**("반품 접수했는데 배송비는
  누가 부담하나요?")이고 G15 는 τ 위로 +0.0073 밖에 안 남는다. 라이브에서 볼 케이스는
  G04 가 아니라 G15 다.
- **손계산의 근거는 1회 관측이다.** `-small-d1536-blind` 리포트 2개는 통계량이 완전히
  같다 — 임베딩이 결정론이라 복제가 아니라 같은 조건의 한 번이다. 질의 문면이 다른
  독립 관측은 oracle 세트 하나뿐이다(거기서는 여유가 +0.0534 로 넓어졌다).
- **오프라인 격자는 고정 질의, 라이브는 매 실행 새 질의다.** 격자는
  `data/rewritten_queries.jsonl` 의 blind 픽스처를 쓰고 런타임은 `rewrite_query` 가 매번
  새로 만든다. 좁은 창에서 고른 τ 가 이전된다는 보장은 없다 — T10 이 그것을 산다.
- **런타임은 임계값 전에 `LIMIT top_k` 로 먼저 자른다.** 통계량을 전체 코퍼스 랭킹으로
  계산하면 배선 시점에 오프라인과 라이브가 어긋난다.

## 다음 첫 행동 하나

사용자 승인이 떨어지면 **go 를 호출**한다. go 의 첫 파도는 **{T0, T1}** 이고 **둘 다
무과금**이다. 첫 과금(T2 풀셋 라이브)은 그 다음 파도라 승인 시점이 온다.

**T0 을 건너뛰지 마라.** 손계산이 이미 끝나 있고 수치가 spec §4-2 에 인용돼 있지만,
그것을 저장소 안에서 **재현 가능한 산출물**로 만드는 것이 T0 의 일이다(spec §12-5).
재현 없이 인용된 수치는 다음 사람이 검증할 수 없다.
