# 사이클 5 플랜 — 마지막 사이클: 재등재 · 계측 · 마감

이 문서는 **잠정 청사진**이다. spec 과 어긋나면 spec 이 이긴다.
자유롭게 수정할 수 있지만, 수정이 spec 의 행동 계약을 바꾸는 것이라면 사용자 승인이 필요하다.

---

## 단계 서사

1. **동작을 바꾸고, 각 변경이 판정을 몇 건 바꾸는지 무과금으로 먼저 센다** — T1(초안 판정) ·
   T3(채택 축 둘) · T7(자격 증명과 임베딩 안전장치)이 병렬. **T2(조회 가드 두 구멍)는 T1 이
   패턴 집합의 소유를 확정한 뒤인 2파도다**(실행 그래프·핸드오프와 같다).
   **이 파도가 라이브에서 관측될 값의 사전 예측을 만든다.**
2. **하네스가 더 적게 만든다** — T4(단계별 시간) → T5(캐시 토큰) → T6(실행 조건 기록 확장).
   셋이 같은 파일들을 고쳐서 직렬이다.
3. **산다** — T8 풀셋 라이브 3회. **사용자 직전 승인**.
4. **사람이 등재한다** — T9. 요약 보고 → 사용자 확인 → 승격 참조 파일 수정.
5. **닫혔다는 증거를 산다** — T10 확인 라이브 1회. 등재 **뒤**에 돌아야 자기 대조가 아니다.
6. **띄워서 돌린다** — T11. 세 장면을 웹 폼으로 흘려 실제 기록을 남긴다(소액 과금).
7. **닫는다** — T12. 미해결 재분류 · 범위 종결 · 전시 갱신.

**과금선**: T8(3회, 약 $1.5)과 T10(1회, 약 $0.5)이 **직전 승인**. T11 은 문의 단위 소액
(총 $0.5 미만)이라 승인 없이. **재구매는 풀셋 세트 1번까지이고 그 1번도 승인 사안이다 —
T10 은 재구매하지 않는다(spec §5-6).** 나머지 태스크는 전부 무과금 —
T1~T7 의 대조는 커밋된 데이터·산출물과 결정론 대역만 쓴다.

## 함께 쓰는 파일 — 미리 갈라 둔다

이 저장소는 파일 몇 개가 여러 관심사를 함께 든다. **그래서 파도가 길다 — 의도한 직렬이다.**

- **호출 래퍼**를 T7(값 꺼내기) · T4(경과 시간) · T5(캐시 토큰)가 고친다 → **T7 → T4 → T5** 직렬.
- **평가 산출 모듈**을 T4 · T5 · T6 이 고친다 → 같은 사슬에 얹힌다.
- **근거 수집 모듈**을 T1(개인정보 필터) · T3(채택 함수 · 기권 사유 내보내기) · T4(구간 시간)가
  고친다 → **T4 를 T1·T3 뒤로 보내 직렬화했다.** 같은 파도에 남는 T1·T3 은 **서로 다른 자리만**
  고친다: T1 은 개인정보 필터, T3 은 채택 함수. 겹치면 실행 도구의 병합 방어가 잡는다.
- **조회문 생성 안내도 근거 수집 모듈 안에 있다** — SQL 생성 프롬프트가 `[허용 함수]` 절로
  조회 검증 모듈 소유의 목록 문자열을 그대로 싣는다. 그래서 **T2 의 캐스트 허용 목록은 검증
  모듈이 소유한 그 목록 문면에 실어, 근거 수집 모듈을 건드리지 않는 것이 기본 구현이다** —
  "정의는 가드 단독 소유"와 "안내에도 실린다"가 한 곳 수정으로 함께 성립한다. 프롬프트에
  새 절이 필요해 근거 수집 모듈을 고치게 되면 **그 편집은 2파도 안에서 T4 시작 전에 끝낸다**
  (T2 → T4 순서).
- **개인정보 패턴 집합**은 T1 이 소유자를 확정하고 T2 가 가져다 쓴다 → **T2 는 T1 뒤다.**
- **모듈 경계 노트**는 여러 태스크가 나눠 쓴다. **자기가 건드린 모듈의 행만** 고친다 — 한
  태스크가 두 모듈을 건드리면 그 두 행이다(T1 은 게이트·근거 수집, T3 은 검색 전략·정책 인덱스·
  근거 수집). 남의 행은 손대지 않는다.
- **미해결 목록 · 엔지니어링 노트 · 결정 기록 색인 · 현재 위치 · 전시 문서**는 **T12 가 단독으로
  쓴다.** 앞선 태스크는 자기 결정 기록 **새 파일**만 만들고 색인은 건드리지 않는다. 닫힌 미해결
  항목도 직접 표시하지 않고 T12 에 넘긴다.
- **단가 문서**는 T5 가 캐시 단가와 정본 구분만 더하고, 서사 갱신은 T12 가 한다.

## 이 저장소에서 실제로 밟은 함정 (전 태스크 공통)

- **파일을 고친 뒤 실재를 다시 확인한다.** 같은 작업 공간에 다른 세션이 붙어 있으면 편집이
  조용히 지워질 수 있다 — 편집 성공 응답은 그 뒤의 덮어쓰기를 말해주지 않는다.
- **되돌린 뒤에는 파이썬 캐시와 테스트 캐시를 함께 지운다.** 지우지 않으면 되돌린 코드로
  테스트가 계속 빨간불이다.
- **선언값을 잴 때 인자 없는 설정 생성자를 쓰지 않는다** — 전용 헬퍼를 쓴다.
- **단언식 안에 설정 객체를 두지 않는다** — 실패 출력이 자격 증명을 평문으로 싣는다.
- **무시 여부는 실제 파일을 만들어 상태로 확인한다** — 부정 패턴 때문에 확인 명령의 종료 코드가
  반대로 읽힌다.
- **정의를 지울 때 줄 번호를 시작 줄로 쓰지 않는다** — 데코레이터가 고아가 되어 수집이 통째로
  죽는다. 린트·타입 검사는 통과하므로 테스트를 돌려야 잡힌다.
- **병렬 실행은 리포트 번호 구간을 미리 갈라 준다.**
- **확률 층 장면에 "항상"을 붙이지 않는다.**
- **결정 기록은 durable 문서다.** 앞선 태스크가 만드는 새 결정 기록도 인용 규율(spec §7-4)을
  그대로 받는다 — 사이클 문서 절 라벨 인용 금지(규칙은 내용으로 옮겨 적는다), 하드 게이트
  번호는 규칙 문서 정본만, T번호에는 사이클 병기. T12 에서야 잡히면 전부 고쳐 쓰게 된다.

## T1 — 초안 판정: 패턴별 접기 · 층 통일 · 채점표 확장  (무과금)

**목표**: 사람이 같은 값으로 읽는 표기 변형이 초안 판정을 비껴가지 못하게 하되, **그 과정에서
반대 방향 구멍을 열지 않는다.** spec §3-1.

**작업 대상**
- 수정: L1 게이트 모듈 — 접기를 **패턴별**로 만들고 번호 계열의 구분자·무시 문자를 넓힌다
- 수정: 근거 수집 모듈의 개인정보 필터 — 게이트와 **같은 패턴 집합·같은 접기**를 쓰게 한다
- 수정: `data/l1_fixtures.jsonl` — 새 우회 케이스 **추가만**
- 신규: 회귀 검사(구분자 12자 + 무시 문자 2자, **자리 사이 배치**) · 정상 에코 보존 검사 ·
  두 층의 패턴 집합 일치 구조 검사(음성 대조 포함)
- 신규: 대조 스크립트 — 정책 조항·주문 값 전수 + 결정론 대역 초안 프로브
- 수정: 도메인 규칙 문서의 개인정보 절 · `src/reply_gate/AGENTS.md` 의 게이트 행(자기 행만)

**행동 계약**
- **12자를 열거된 고정 집합으로 다룬다. 범주 이름으로 구현하지 않는다** — 12자 중 실제로 대시
  범주인 것은 여섯 자뿐이라, 범주로 짜면 절반이 뚫린 채 문서는 닫혔다고 적는다.
- **결합문자·변이선택자(②)는 반대로 범주로 구현한다** — 결합 표식(Mn) 전체 + 변이선택자
  전부 무시(spec §3-1, 사용자 확정). 열거 2자(U+0301·U+FE0F)는 회귀 검사의 대표다.
- **이메일 패턴의 접기는 건드리지 않는다.** 밑줄·빗금을 하이픈으로 접으면 두 주소가 같은 값이
  되어 새 우회가 열린다.
- **초안과 근거 양쪽에 같은 패턴별 접기가 걸린다.** 한쪽만 넓히면 두 층의 기준이 다시 갈린다.
- **패턴 집합의 층별 비대칭도 함께 닫는다** — 지금 게이트는 집합을 주입받을 수 있는데 근거
  필터는 기본 집합을 직접 든다. 접기가 층마다 달라 터진 것과 같은 모양이다.
  **소비자는 셋이다** — 근거 필터와 **T2 의 조회 가드**까지. T2 가 개인정보 모양 판정에 이
  집합을 가져다 쓰므로 이 태스크가 그 단독 소유자를 확정하고 구조 검사를 세운다.
- **채점표에 추가만 한다.** 심어 둔 기존 픽스처는 한 건도 지우거나 고치지 않는다.
- **양방향을 잰다.** 미탐이 닫히는 건수와 정상 에코가 기각되는 건수를 같은 대조에서 낸다.
  **오탐이 늘면 채택하지 않는다.**
- 게이트 모듈은 계속 LLM·네트워크·시간·난수·환경을 import 하지 않는다.

**검증 게이트**: 회귀 검사가 **수정 전에 실패하고 수정 후에 통과한다**(음성 대조를 실제로
돌린다) · 이메일 허용값이 이 변경으로 충돌하지 않는다(전수) · 정상 에코 보존 검사 · 두 층의
패턴 집합 일치를 구조 검사가 지킨다 · 대조 수치가 모집단과 함께 나온다 · 고친 문서의
링크·앵커 0건 깨짐 · 전체 스위트 녹색 · 파일 diff.

**thinking-base**: 회귀 검사에 **자리 사이 배치**를 박는 이유는, 끝에 붙인 문자열이 수정 전에도
기각되기 때문이다 — 끝에 붙여 검사하면 아무것도 지키지 못하는 초록 검사가 된다.
채점표를 늘리는 이유는, 넣지 않으면 새로 닫은 계열을 **헤드라인 검출률이 한 번도 재지 않은
채** 프로젝트가 끝나기 때문이다. 그 대가(측정 1 분모 변화)를 감당할 수 있는 자리가 재등재하는
이번 사이클뿐이다.

## T2 — 조회 가드의 두 구멍  (무과금)

**의존**: T1 (개인정보 패턴 집합의 소유자가 먼저 확정돼야 한다)

**목표**: 승인한 정상 조회가 정상 답변을 기각하는 경로를 닫고, 형변환으로 화이트리스트 밖
이름이 근거로 들어오는 경로를 막는다. spec §3-2 · §3-3.

**작업 대상**
- 수정: 조회 검증 모듈 — 개인정보 허용 출처의 유래 추적을 안쪽 스코프까지, 형변환 대상 타입
  허용 목록
- 수정: 조회문 생성 안내가 그 허용 목록을 그대로 싣게 한다(정의는 가드가 단독 소유 — 기본
  구현은 검증 모듈 소유의 목록 문자열에 싣는 것, "함께 쓰는 파일" 참조)
- 수정: 도메인 규칙 문서의 개인정보 절 · 보안 문서의 1층 서술 · `src/reply_gate/AGENTS.md`
  관련 불변식(자기 행만)
- 신규: 양성·음성·공격 검증 테스트 · 안내와 가드의 목록 일치 구조 검사
- 신규: 대조 — 손으로 만든 조회문 코퍼스 + 결정론 대역 프로브

**행동 계약**
- **유래 추적을 안쪽 스코프까지 내린다.** 임시 테이블·파생 테이블을 거친 출력도, 안쪽 결과가
  주문 실테이블의 직접 컬럼에서 왔음이 확인되면 허용 출처가 된다.
- **빈칸 채우기 계열의 고정값은 허용하되, 개인정보 모양이면 불승인이다.**
- **"개인정보 모양"의 정의를 여기서 새로 만들지 않는다.** 조회 검증 모듈에는 지금 개인정보
  정규식이 **한 줄도 없다.** T1 이 확정한 **게이트 모듈의 패턴 집합을 가져다 쓴다** — 자기
  정의를 만들면 저장소에 개인정보 정의가 셋이 되고, 그것이 T1 이 닫으려는 결함 그 자체다.
- **값을 이어 붙이는 계열은 고정값이 섞이면 불승인이다** — 조각으로 나눈 값을 합성하는 길을 막는다.
- **검증기가 모르는 표현식은 자동으로 불승인**이라는 성질을 유지한다.
- **출력 이름 중복 거부(직접 컬럼 유래를 계산값이 덮지 못하게 하는 규칙)는 그대로다** —
  유래 추적을 재작업하는 바로 그 자리의 기존 규칙이라, 보존 검사를 회귀 가드로 둔다.
- **형변환 대상 타입은 허용 목록(fail-closed)** 이고, **같은 목록이 생성 안내에도 실린다** —
  갈리면 생성기가 목록 밖 타입을 쓸 때마다 거부 → 재시도 → **인계**가 되고 그 인계가 이번에
  사는 기준선의 수치가 된다.
- 검증 모듈은 계속 DB 에 접속하지 않는다.

**검증 게이트**: ① 정상 통과 — 임시 테이블·파생 테이블 경유, 빈칸 채우기 관용구. ② **공격
검증** — 개인정보 모양 고정값, 이어 붙이기 합성, 조각 합성, 부질의 경유. ③ 카탈로그 참조 타입
거부 + 허용 목록 전 타입 통과. ④ 기존 우회 목록(주문 범위 강제·화이트리스트·읽기 전용 쓰기)이
전부 그대로 거부된다. ⑤ 안내와 가드의 목록이 같다. ⑥ 캐스트 거부 사유가 안내 문구를 들고
나와 재생성 프롬프트에 실린다. ⑦ 출력 이름 중복 거부가 그대로다(보존 검사). ⑧ 대조 수치.
⑨ 고친 문서의 링크·앵커 0건 깨짐. ⑩ 전체 스위트 녹색 · 파일 diff.

**thinking-base**: 이 태스크는 **안전장치를 넓힌다.** 이 저장소의 규율은 "실제로 뚫고 → 고치고
→ 다시 공격한다"였다. 통과 케이스만 있는 검사로는 넓힌 구멍이 열렸는지 알 수 없다.

## T3 — 채택 축 둘: 미정의 처리와 결정론 순서  (무과금)

**목표**: 통계량이 정의되지 않을 때의 처리를 사유별로 가르고, 검색 결과 순서를 결정론으로
만든다. spec §3-4 · §3-5.

**작업 대상**
- 수정: 기권 게이트의 순수 판정 연산 — 미정의 사유별 처리
- 수정: 정책 검색 정렬 — 유사도 → 근거 ID
- 수정: 근거 채택 함수의 계약 설명(자기 자리만) · 도메인 규칙 문서의 채택 규칙 절 ·
  `src/reply_gate/AGENTS.md` 관련 행(자기 행만)
- 신규: 두 사유 각각의 판정 검사 + 동점 재현 검사
- 신규: 전수 대조 — 각 미정의 분기를 타는 질의 수, 순위가 바뀌는 질의 수

**행동 계약**
- **미정의 두 사유를 하나로 접지 않는다.**
  - 1위 코사인이 0 이하 → **기권한다.**
  - 측정 점수 2건 미만 → **기권하지 않는다.** 항목 축에 맡긴다.
- **두 번째는 결함이 아니라 계약이다** — 근거 채택 함수의 설명이 이미 *"여기서 뒤집지 않는다"*
  고 못박고 있다. 되돌리면 후보가 하나뿐인 질의가 근거 없이 인계된다.
- **미정의 사유를 밖으로 내보내는 자리를 만든다.** 지금 순수 판정 연산은 사유를 담아 돌려주는데
  **근거 채택 함수가 "기권했나" 한 칸만 읽고 버린다.** 이 태스크는 사유가 **근거 묶음까지**
  나오게 하고, **거기서 평가 리포트로 잇는 것은 T6 이 한다**(평가 산출 모듈은 T4·T5·T6 의
  것이다). 두 태스크 사이의 계약은 "근거 묶음이 기권 사유를 들고 있다"이다.
- **⚠ "사유가 결과에 실린다"는 이미 참이다** — 그것을 검증 항목으로 쓰면 수정 전에도 초록이다.
- **정렬은 DB 질의 한 곳만 고친다.** 파이썬 합집합 병합은 **이미** 유사도 → 근거 ID 로
  정렬하고 기본값 경로가 그것을 지난다. 남은 비결정은 DB 가 상위 `top_k` 를 자를 때 어느 행이
  살아남는가 하나다. **그래서 파이썬 층 동점 검사는 수정 전에도 통과한다** — 구속력 있는 검사는
  실제 DB 에 동점을 만드는 **DB 마커 검사**다.
- **동점 행은 정본 순서(근거 ID 오름차순)와 반대로 심는다.** 갓 삽입된 행은 물리 순서가 삽입
  순서라, ID 순으로 심으면 tie-break 없는 지금 코드도 우연히 정본 순서를 돌려줘 "수정 전에
  실패"가 성립하지 않는다 — 음성 대조가 초록으로 태어나는 함정이다.
- **전수 대조는 오프라인 전체 코퍼스 점수를 쓴다** — 커밋된 산출물은 이미 잘린 상위 `top_k` 만
  담아 절단선의 동점을 보여줄 수 없다.
- **오프라인 손계산 쪽 쌍둥이 구현의 처분을 결정 기록에 적는다** — 같은 미정의 두 조건이 채택 축
  손계산 모듈에 같은 문면으로 한 벌 더 있고, τ 를 정당화한 격자는 런타임 원시연산을 따라
  움직이지만 손계산 쪽은 따라오지 않는다.
- 게이트는 계속 **점수열만** 받는다 — 정답도 케이스 정체성도 받지 않는다(구조 검사가 지킨다).
- 통계량 입력은 계속 `top_k` 선절단 슬라이스다.

**검증 게이트**: 두 사유 각각의 판정이 계약대로 · **근거 묶음이 기권 사유를 들고 나온다(수정
전에 실패하는 검사)** · **DB 마커 동점 검사가 수정 전에 실패하고 수정 후에 통과한다** ·
기존 기권 게이트 판정(τ 축) 무변경 · 전수 대조 수치 · 쌍둥이 처분이 기록됐다 · 고친 문서의
링크·앵커 0건 깨짐 · 전체 스위트 녹색 · 파일 diff.

**thinking-base**: fail-closed 를 기계적으로 적용하면 **이 층에서는 정상 케이스가 죽는다.**
미해결 문서는 이것을 fail-open 결함 하나로 적었지만, 두 사유 중 하나는 모듈이 의도로 선언한
계약이다. 결함으로 읽고 통째로 뒤집으면 문서화된 계약을 실측 근거 없이 되돌리는 것이 된다.

## T7 — 자격 증명과 임베딩 안전장치  (무과금)

**목표**: 설정 객체 덤프로 자격 증명이 평문으로 나오는 경로를 닫고, τ 가 검증되지 않은 임베딩
조건에서 제품이 조용히 돌지 않게 한다. spec §3-6 · §4-4.

**작업 대상**
- 수정: 설정 모듈 — 자격 증명 네 종을 비밀 전용 타입으로, τ 검증 조건 목록과 조립 시점 판정
- 수정: 값을 읽는 자리(호출 래퍼 · DB 커넥션) — 명시적으로 꺼내 쓰기
- 수정: 비밀 검사 — 표시 경로에 더해 **덤프 경로까지** 전수로 훑기
- 수정: 보안 문서 · `src/reply_gate/AGENTS.md` 의 설정 모듈 행(자기 행만)
- 신규: 조립 거부 테스트(음성) + 현재 기본값 통과 테스트(양성) + 대조

**행동 계약**
- **비밀 전용 타입으로 옮기면 덤프 경로와 표시 경로가 함께 닫힌다.** 값이 필요한 곳은
  명시적으로 꺼내 써서 **어디서 평문이 되는지 셀 수 있게** 한다.
- **접속 문자열 경로는 이 태스크가 닫지 않는다** — 값을 조립한 새 문자열이라 필드 규칙 밖이고,
  고치기 전에 재현이 먼저다. **닫는다고 적지 않는다.**
- **제품 판정을 바꾸지 않는다** — 같은 값이 같은 자리로 간다. 조건 보존을 대조로 확인한다.
- **τ 불일치는 조립 시점 명시적 오류다.** 요청당 오류가 아니라 조립 오류인 것은, 이것이 런타임
  데이터 상태가 아니라 **설정 조합**이고 조립 시점에 알 수 있기 때문이다 — 이 저장소가 "스위치
  켜짐 + 배선 없음"을 조립에서 죽이는 것과 같은 자리다.
- **우회 플래그를 두지 않는다.** τ 를 재산출했을 때의 명시적 경로는 **사람이 검증 조건 목록을
  고치는 것**이다 — 승격과 같은 자격.
- **오프라인 비교·격자 도구는 대상이 아니다.** 여러 임베딩 조건을 일부러 훑는 것이 그 도구들의
  일이다.
- 게이트를 얻는 자리는 계속 하나다.

**검증 게이트**: 덤프에 평문이 없다(음성) · 실행 경로가 값을 정상적으로 얻는다(양성) ·
검증되지 않은 임베딩 조건의 조립이 죽는다 · 현재 기본값 조립은 통과한다 · 오프라인 도구
무영향 · 선언값 검사에 전용 헬퍼를 쓴다 · 고친 문서의 링크·앵커 0건 깨짐 · 전체 스위트
녹색 · 파일 diff.

**thinking-base**: 이 항목은 원래 다음 사이클로 미뤄져 있었다. **다음 사이클이 없다는 것이
확정되면 "미룸"이 "영구 미조치"로 바뀐다** — 비밀 규칙은 이 저장소가 낮출 수 없는 하한이라
그 전환을 받아들일 수 없다.

## T4 — 단계별 시간 계측  (무과금)

**의존**: T7 · T1 · T3 (호출 래퍼와 근거 수집 모듈을 함께 쓴다)

**목표**: 어느 단계가 몇 초인지를 처음으로 말할 수 있게 한다. spec §4-1.

**작업 대상**
- 수정: 호출 래퍼 — 재시도를 포함한 구간 경과 시간, 예외에도 실어 올리기
- 수정: **근거 수집 모듈과 그 결과 묶음** — 아홉 구간 중 **여섯이 이 안쪽**이다(의도 분류 ·
  재작성 · 임베딩 · 벡터 검색 · 조회문 생성 · 조회 실행). 바깥에서 감싸면 여섯이 한 칸으로
  접힌다
- 수정: 파이프라인과 **시도 기록 구조** — 지금 시도 기록은 토큰도 시간도 들지 않는다.
  시도별 값을 실으려면 자리를 만들어야 한다
- 수정: 평가 산출 모듈 — 케이스별 값과 세트별 집계, 리포트 JSON 과 사람이 읽는 줄
- 수정: 판정 픽스처 측정 경로 — 판정 호출 지연 기록
- 수정: `src/reply_gate/AGENTS.md` 의 평가 산출 행(자기 행만)
- 신규: 테스트

**행동 계약**
- **구간 경계**: 밖으로 나가는 호출 여섯(의도 분류 · 질의 재작성 · 질의 임베딩 · 조회문 생성 ·
  초안 생성 · 판정)과 코드만 도는 구간 셋(벡터 검색 · 조회 실행 · 게이트 판정).
- **한 구간의 시간은 그 구간의 총 벽시계다 — 재시도와 형식 실패를 포함한다.** 성공한 마지막
  호출만 재면 래퍼 재시도가 통째로 사라진다. 이 저장소는 토큰에서 이미 같은 사고를 겪었다
  (전송 3회를 2회로 신고). **예외로 죽은 호출의 경과도 토큰과 같은 자격으로 올려보낸다.**
- **재생성이 돌면 시도별로 쌓인다.** 합계와 시도별 값을 함께 알 수 있어야 한다.
- **시도 기록은 처리 기록 복원이 생성자를 직접 부르는 DB 왕복 구조다.** 새 칸은 기본값을
  갖고 DB 에는 싣지 않는다 — 복원을 깨지 않으면서 "계측은 리포트까지만"(DB 스키마 무변경)을
  지키는 유일한 모양이다.
- **게이트 판정 구간의 시간은 호출자가 잰다.** 게이트 모듈은 시간에 의존하지 않는다.
- **DB 스키마 무변경 · 응답 계약 무변경.** 결과 객체와 평가 리포트까지만.
- **미측정은 0 이 아니다.** 집계는 미측정을 분모에서 뺀다.

**검증 게이트**: 구간 합이 전체 시간을 넘지 않는다 · 미측정이 0 과 구분된다 · 재시도가 난
구간의 시간이 총합으로 잡힌다 · 재생성 실행에서 시도별로 쌓인다 · 리포트 JSON 과 사람이 읽는
줄이 같은 값을 적는다 · 응답 스키마와 DB 스키마 검사 무변경 · 전체 스위트 녹색 · 파일 diff.

**thinking-base**: 응답과 처리 기록에 싣지 않는 이유는 둘이다 — 처리 기록은 스키마 변경이라
볼륨 재생성과 **유료 재색인**을 동반하고, 응답 계약 확장은 이 사이클의 하드 게이트다.

## T5 — 캐시 적중 토큰 집계  (무과금)

**의존**: T4

**목표**: 생성·검색 계열의 달러가 상한이 아니라 실측이 되게 한다. spec §4-2.

**작업 대상**
- 수정: 생성 계열 호출 래퍼 — 캐시 적중 토큰 읽기
- 수정: 평가 산출 모듈 — **별도 칸**으로 싣기, 집계
- 수정: 단가 문서 — 캐시 단가 매핑, **상한/실측 정본 구분**
- 신규: 테스트

**행동 계약**
- **입력 칸에 접지 않는다** — 접으면 같은 은폐가 반대 방향으로 생긴다.
- **칸은 계열별로 둔다 — 생성과 검색 두 쌍이다.** 두 계열이 같은 클라이언트를 지나므로 한
  쌍으로 묶으면 어느 계열의 캐시였는지 되짚을 수 없다. 판정 계열의 기존 한 쌍은 그대로 둔다.
- **없는 값은 0 이 아니라 "미측정"이다.**
- 응답 계약에는 나가지 않는다 — 판정 계열의 캐시 칸과 같은 경계.
- 토큰 계열 분리는 그대로다. 캐시 칸이 계열을 늘리지 않는다.
- **정본을 가른다** — 이번 실측만 캐시를 반영한 값이고 커밋된 옛 산출물은 영구히 상한이다.
  옛 수치는 "상한"으로 병기하고 기준일을 함께 적는다. 파생 비율 문장의 재계산은 T12 가 한다.

**검증 게이트**: 캐시 칸이 별도로 실린다 · 값이 없을 때 0 으로 접히지 않는다 · 응답 계약
무변경 · 단가 문서의 상한/실측 구분이 서 있다 · 전체 스위트 녹색 · 파일 diff.

**thinking-base**: 판정 계열에는 같은 배선이 이미 있다. **"교훈을 적을 때 그 규칙이 걸려야 할
나머지 대상을 함께 세어라"** 는 이 저장소의 규칙에 정확히 걸리는 자리다.

## T6 — 실행 조건 기록 확장  (무과금)

**의존**: T5 · T1 · T2 · T3

**목표**: 마지막 기준선이 "어느 코드로 낸 값인가"를 산출물만으로 복원할 수 있게 한다. spec §4-3.

**작업 대상**
- 수정: 평가 산출 모듈의 조건 지문 — 일곱 항목 추가 (지금은 **열여덟 칸**이고, 그중 판정
  effort 칸은 항목 ②와 **다른 축**이니 고치지 말고 옆에 더한다)
- 수정: 평가 산출 모듈 — **T3 이 근거 묶음까지 내보낸 기권 미정의 사유를 리포트로 잇는다**
- 수정: 회귀 가드 — 새 항목의 대조·미상 처리
- 수정: `src/reply_gate/AGENTS.md` 의 회귀 가드 행(자기 행만)
- 신규: 테스트

**행동 계약**
- 더할 항목 일곱: ① 중단된 측정 표시 ② 판정 모델의 사고 과정 축 ③ 초안 판정 규칙의 판
  (접기·패턴 집합) ④ L1 채점표의 판 ⑤ 조회 가드의 판(허용 함수·허용 형변환 타입·유래 승인
  규칙) ⑥ 검색 순서 규칙 ⑦ 기권 게이트의 미정의 처리 방식.
- **내용 지문은 같은 코드·같은 데이터면 항상 같은 값이어야 한다.** 실행 환경이나 시각에
  의존하면 지문이 스스로를 무력화한다.
- **옛 산출물의 새 항목은 "미상"** 이지 0 도 "없음"도 아니다.
- **대조는 미상을 관용하고 세트 편입은 확인된 동일성만 인정한다**는 술어 차이를 유지한다.
- 짝으로 읽는 항목의 기존 규칙은 그대로다.
- 회귀 가드는 승격 참조 파일을 **쓰지 않는다** — 구조 검사가 계속 지킨다.

**검증 게이트**: 일곱 항목이 전부 지문에 실린다 · 같은 코드로 두 번 돌리면 같은 값이 나온다 ·
옛 산출물과의 대조가 "미상"으로 읽힌다 · 세트 편입 술어가 느슨해지지 않았다 · 짝 항목 규칙
무변경 · 승격 자동 쓰기 금지 구조 검사 통과(음성 대조 포함) · 전체 스위트 녹색 · 파일 diff.

**thinking-base**: 지문 항목 추가는 **커밋된 라이브 전부를 그 항목 "미상"으로 만든다.**
재등재 시점이 그것을 감당할 유일한 자리이고 이번이 마지막 재등재다. 특히 기권 미정의 처리는
바꿔도 기존 지문 값이 **전혀 움직이지 않아**, 항목을 만들지 않으면 그 변경이 산출물에 아무
흔적도 남기지 않는다. 앞선 태스크들의 형태가 정해져야 무엇을 지문으로 삼을지 정할 수 있어
T1·T2·T3 뒤에 온다.

## T8 — 풀셋 라이브 3회  (**과금 · 직전 승인**)

**의존**: T6

**목표**: 현재 기본값 조합의 첫 풀셋 실측 3회를 산다. spec §5-1 · §5-2 · §5-3.

**작업 대상**
- 신규(추적됨): 라이브 리포트 3쌍
- 외부 상태: 실제 모델 호출(생성 · 임베딩 · 판정), Postgres

**행동 계약**
- **실행 전에 사용자 승인을 받는다.** 조건과 예상액을 함께 알린다.
- **실행 전에 확인할 것**: DB 기동 · 정책 인덱스의 임베딩 출처가 기대와 같은지 · 리포트 번호
  구간 · 생성 키와 판정 키가 **둘 다** 있는지.
- **강등 실행 금지.** 판정 키가 없다고 L2 를 꺼서 측정 2 만 돌리지 않는다.
- **어느 측정이 죽어도 리포트는 쓴다.** 중단은 리포트의 미실행 사유와 종료 코드로 알린다.
- **관측 항목 여섯을 기록한다**(spec §5-3). **합격선(3회 중 2회 이상)이 걸리는 것은 1~4 뿐**
  이고 **실제 회차를 그대로 적는다.** 5는 결정론 층의 **동일성 확인**이고(T1 의 무과금 대조가
  곧 측정 1 이라 라이브가 새로 알려줄 것이 없다), 6은 **사람의 관측**이다 — 둘 다 합격선
  항목이 아니므로 이것 때문에 원복을 발동시키지 않는다.
- **못 맞추면**: 대조 수치가 지목하는 축만 되돌린다. **귀인이 갈리지 않으면 되돌리지 않고
  사용자에게 판단을 넘긴다.** 재구매는 풀셋 세트 1번까지이고 그 1번도 승인 사안이다.
- **커밋된 라이브 리포트를 사후 편집하지 않는다.**

**검증 게이트**: 리포트 3쌍이 라이브 계열 이름으로 산출되고 추적 대상에 들어간다 · 관측 항목
여섯이 실측값·회차와 함께 정리된다 · 종료 코드가 규칙대로다 · 실행 뒤 서버·컨테이너 좀비 0.

**thinking-base**: 한 번만 사는 이유는 **고칠 때마다 기준선이 한 번 더 어긋나기 때문**이다.
축이 여럿 동시에 움직이는 대신 귀인은 라이브가 아니라 **무과금 대조**가 든다 — 그래서
T1~T3 의 대조가 이 태스크의 사실상 선행 조건이다.

## T9 — 승격 기준선 재등재  (무과금 · **사람의 결정**)

**의존**: T8

**목표**: 회귀 판정의 구속 줄이 다시 살아난다. spec §5-5.

**작업 대상**
- 수정: 승격 기준선 참조 파일 (**사용자 확인 뒤에만**)
- 신규: 재등재 결정 기록

**행동 계약**
- **요약 보고 → 사용자 확인 → 파일 수정** 순서다. 확인 전에 파일을 고치지 않는다.
- **지문의 모든 항목을 새 값으로 채운다** — "네 칸"이 아니라 전부다. 어긋나 있던 넷에 더해
  T6 이 추가한 일곱 칸까지. **값 문자열은 산출물이 찍는 문면과 글자 단위로 같아야 한다.**
- 새 스템 3개 · `supersedes` 에 직전 승격 스템 3개 · **승격 사유에 관측 근거를 회차와 함께**.
- **저장소 어디에도 이 파일에 쓰는 코드 경로를 만들지 않는다.**

**검증 게이트**: 등재 정합성 검사가 통과한다(스템끼리 조건이 같고 참조의 지문이 산출물과
같다) · 승격 자동 쓰기 금지 구조 검사 통과 · 전체 스위트 녹색 · 파일 diff.

**thinking-base**: 하나라도 빠지면 **다시 어긋난 채로 등재된다.** 특히 "미배선" 두 칸을 안
채우면 재등재를 하고도 구속 줄이 계속 멈춘다.

## T10 — 닫혔다는 증거: 확인 라이브 1회  (**과금 · 직전 승인**)

**의존**: T9

**목표**: 재등재가 실제로 닫혔다는 증거를 산다. spec §5-6.

**작업 대상**
- 신규(추적됨): 라이브 리포트 1쌍
- 외부 상태: 실제 모델 호출, Postgres

**행동 계약**
- **등재 뒤에 돈다.** 등재 전에 돌면 자기 자신과 대조하는 꼴이라 증거가 되지 않는다.
- 조건은 T8 과 같다. **실행 전 승인**을 받는다(약 $0.5).
- **구속 줄이 "보류"로 나오는 것이 정상이다** — 조건이 확인된 실측이 1/3 이라 세트가 안 찼다.
  **보류를 실패로 읽지 않는다.**
- **증거는 "대조 불가"가 아니라는 것이다** — 지문이 전부 일치해 **선언 없이** 대조가 진행되고
  어긋난 항목 목록이 비어 있어야 한다.
- 어긋난 항목이 나오면 **T9 의 등재 문면이나 T6 의 지문 산출 중 어디가 갈렸는지**를 짚어
  고치고, 고친 뒤에는 다시 사지 않고 **산출물 대조로 확인**한다(지문 비교는 무과금이다).
  그 기록이 갈음 증거이고 재등재 게이트를 그것으로 판정한다(spec §5-6·§9). 확인 라이브는
  재구매 한도 밖이다.

**검증 게이트**: 리포트 1쌍 산출 · 구속 줄이 선언 없이 대조를 진행하고 어긋난 항목이 비어
있다 · 실행 뒤 좀비 0.

**thinking-base**: 이 증거를 무과금으로 얻으려면 **가드만 다시 계산하는 실행 모드**가 필요한데,
그것을 만드는 것은 하네스에 새 진입점을 더하는 일이라 이번 범위 밖이다. 그래서 라이브 1회로
산다.

## T11 — 시연: 세 장면을 실제로 흘린다  (소액 과금)

**의존**: T10

**목표**: 두 층이 각각 무엇을 잡는지를 실제 기록으로 보인다. spec §6.

**작업 대상**
- 외부 상태: 로컬 서버 기동, 웹 폼 실행, 처리 기록 3건
- 수정: 전시 문서의 데모 절 — 이 실행의 응답 본문으로 갱신
- 수정: 운영 문서의 실행 절차 — 실제로 밟은 순서대로

**행동 계약**
- **세 장면과 문의는 spec §6 의 표가 고정한다** — G16(구조 기각 → 재생성 → 통과) ·
  G30(L1 통과 → L2 기각, **주문번호를 함께 넣는 주문 문의다**) · G21(검색 기권 → 인계).
  **문의 문구는 골든셋 원문 그대로 넣는다** — 바꿔 적으면 실측과 다른 것을 잰다.
- **재현 확률이 장면마다 다르다.** 장면 3은 12/12, 장면 2의 **L2 기각은 3/3 이지만 재기각
  인계는 1/3**, 장면 1은 **직전 라이브 15 케이스-실행 중 1회**로 가장 낮다.
  **장면 2는 L2 기각이 본체다** — 재생성이 통과하면 그대로 싣는다.
- **증거는 문의 ID 목록**이다. 조회 라우트로 다시 열리는지 확인하고, 전시 문서에 응답 본문을
  인용한다. **별도 산출물 파일을 만들지 않는다.**
- **시도 상한은 장면 1 이 10회, 장면 2·3 이 3회다**(spec §6 — 상향은 사용자 지시로만).
  **상한 안에 재현되지 않으면 그 사실과 시도 회차를 그대로 적는다** — 회차는 성패와 무관하게
  전부 적는다. 시도를 늘리는 것이 아니라 실패 회차를 숨기는 것이 "잘 나온 것만 실었다"다.
- **장면 1이 재현되면 미해결 19번이 닫힌다. 아니면 열어 둔다** — 표시는 T12 가 하고, T11 은
  **재현 여부와 회차**를 넘긴다.
- **시연 과금은 문의 단위 총 $0.5 미만이다**(spec §6). 별도 승인 없이 실행하되 $0.5 를
  넘게 되면 멈추고 승인을 받는다.
- **실행 뒤 서버 종료를 확인한다.** 좀비 0.
- **한 번의 관측을 "항상"으로 적지 않는다.**

**검증 게이트**: 세 장면의 문의 ID 와 응답 본문 · 조회 라우트 왕복 확인 · 데모 절 갱신 ·
서버 종료 확인 · 문서 링크·앵커 0건 깨짐 · 파일 diff.

**thinking-base**: 데모 절에 지금 실려 있는 응답 본문은 **이전 기본값**에서 흘린 것이다.
마지막 사이클의 전시 문서가 현재 동작과 다른 장면을 싣고 있으면 안 된다.

## T12 — 프로젝트를 닫는다  (무과금 · 문서 전용)

**의존**: T10 · T11

**목표**: 다음 세션을 전제하지 않는 문서로 만든다. spec §7.

**작업 대상**
- 수정: 미해결 목록 — 두 갈래 재분류 + 이번에 닫힌 항목 표시
- 수정: 문제정의 — 사이클 5 절, **범위 종결**, 판정 층 결론
- 수정: 현재 위치 · 전시 문서 · 단가 문서
- 수정: 엔지니어링 노트 — 이번에 실제로 밟은 함정만
- 수정: 결정 기록 색인 — 앞선 태스크가 만든 새 결정 기록들을 등재
- 수정: 아카이브된 사이클 입력 문서에 "이력이다" 한 줄

**행동 계약**
- **두 갈래로 가른다**: 의도적으로 하지 않기로 한 것 / 여전히 미해결인 것. 각각 사유를 적는다.
- **항목 번호를 다시 매기지 않는다** — 저장소 45곳이 이 번호로 인용하는데 대부분 번호가 링크
  **글자**에만 있어, 바꾸면 **링크 검사가 못 잡은 채** 인용이 통째로 다른 항목을 가리킨다.
- **닫는 방식을 정직하게 적는다** — "고쳤다"·"사라졌다"·"반증됐다"는 다르다.
- **미해결 19번은 조건부다** — T11 이 장면 1을 재현했을 때만 닫고, 아니면 시도 회차와 함께
  열어 둔다. **"닫았다"를 먼저 적고 기록을 나중에 맞추지 않는다.**
- **"다음 사이클의 문제"를 남기지 않는다.** 대신 범위가 여기서 닫혔다는 것과 그 이유를 적는다.
- **판정 층의 재현 어긋남은 반증으로 닫되 원인을 단정하지 않는다.**
- **측정 1 수치는 분모를 병기한다** — T1 이 채점표를 늘렸다.
- **옛 상한에서 파생된 비율 문장을 새 값으로 재계산하거나 조건을 붙인다.**
- **"코드가 강제한다"고 적는 자리에 구조 검사의 한계를 병기한다.**
- **인용 규율**: 사이클 문서를 절 라벨로 인용하지 않는다 · 하드 게이트 번호는 규칙 문서의
  정본 목록만 · 달러에는 기준일 병기 · T번호에는 사이클 병기.
- **커밋된 라이브 리포트를 사후 편집하지 않는다** — 정정은 문서에 병기한다.
- **검증 건수를 실제 실행값으로 갱신한다.**

**검증 게이트**: 문서 링크·앵커를 프래그먼트까지 검사해 0건 깨짐 · 인용 가드 테스트 통과 ·
문서가 인용하는 수치가 커밋된 산출물에서 재집계로 확인됨 · 전체 스위트 녹색 · 파일 diff.

**thinking-base**: 미해결 목록은 원래 "지금 세션에서 해결할 수 없는 것"이라는 정의를 갖고
있다. **프로젝트가 끝나면 "다음 세션"이 없으므로** 그 정의가 성립하지 않는다 — 그래서
재분류가 필요하고, 그것이 이 태스크가 존재하는 이유다.

## 실행 그래프

간선은 **실제 생산자 → 소비자**만 담았다. 늘리면 병렬이 죽고, 빼면 통합에서 깨진다.
전이로 이미 걸리는 간선은 적지 않는다(예: T12 는 T11 만 가리키고, T10 은 T11 을 통해 걸린다).

**`regen_barriers` 가 빈 이유**: 이 사이클에는 파도 사이에 다시 만들어야 할 산출물이 없다.
스키마도 볼륨도 안 바꾸고(하드 게이트 1), 정책 색인은 그대로이며(재색인은 과금이다),
검색 캐시는 오프라인 전용이라 제품 경로가 그것을 재생성하지 않는다.

```yaml
tasks:
  - id: T1
    depends: []
    risk: RISKY
  - id: T3
    depends: []
    risk: RISKY
  - id: T7
    depends: []
    risk: RISKY
  - id: T2
    depends: [T1]
    risk: RISKY
  - id: T4
    depends: [T7, T1, T3]
    risk: RISKY
  - id: T5
    depends: [T4]
    risk: RISKY
  - id: T6
    depends: [T5, T2]
    risk: RISKY
  - id: T8
    depends: [T6]
    risk: RISKY
  - id: T9
    depends: [T8]
    risk: RISKY
  - id: T10
    depends: [T9]
    risk: RISKY
  - id: T11
    depends: [T10]
    risk: MECHANICAL
  - id: T12
    depends: [T11]
    risk: NONE
regen_barriers: []
```
