# 사이클 4 플랜 — 채택 축과 회귀 가드 (+ 판정 심화 · 비용 서사 · 청킹 비교)

이 문서는 **잠정 청사진**이다. spec 과 어긋나면 spec 이 이긴다.
자유롭게 수정할 수 있지만, 수정이 spec 의 행동 계약을 바꾸는 것이라면 사용자 승인이 필요하다.

**개정 이력**: 2026-08-19 적대리뷰(심판 5인 · 131건 전건 검증)와 손계산 결과를 반영해
전면 개정했다. 바뀐 것은 후보 축(T3), 태스크 하나 삭제(T4), 태스크 하나 신설(T0),
그리고 **파도 순서**다.

---

## 단계 서사

1. **자를 먼저 만들고 후보를 확정한다** — 회귀 가드(T1)와 손계산 산출물화(T0)를 병렬로.
   손계산은 무과금이고, 그 결과가 T3 격자의 축을 정한다.
2. **기준선을 사고 격자를 짠다** — 현 기본값 라이브 3회(T2, 첫 과금)와 기권 게이트
   격자(T3)가 병렬. 사용자 확인 후 T2 를 **승격 기준선**으로 등재한다.
3. **축을 고른다** — 격자를 실측해 채택/비채택을 결정한다(T5). 청킹 격자(T12)가 병렬.
4. **배선하고 판정한다** — 이긴 축을 제품에 넣고(T9) 라이브 3회로 판정한다(T10).
   **이 시점의 판정 층은 기준선과 같다** — 바뀐 축이 하나뿐이라 원복 귀인이 성립한다.
5. **판정 층을 다듬는다** — J11 재검토·모순 검출 개선(T6) 뒤에 judge 비교표(T7)와
   캐싱 전후(T8)가 병렬.
6. **서사로 만든다** — 비용 분해·비동기화 검토(T11), 문서·README·데모(T13).

**과금선**: T2 가 첫 라이브(직전 승인), T10 이 두 번째 라이브(직전 승인). T5·T12·T6·
T7·T8·T13 은 **소액 등급**이라 §10 상한 안에서 승인 없이 실행한다.

## T0 — 손계산 산출물화 + 후보군 확정 결정  (무과금)

**목표**: spec §4-2 가 인용하는 수치를 **저장소 안에서 재현 가능한 산출물**로 만들고,
반증된 축들의 처분을 결정 기록으로 남긴다. spec §4-2·§12-5.

**작업 대상**
- 신규: 손계산 스크립트(위치는 `scripts/` 또는 테스트 픽스처 — 조정 가능)
- 신규: `docs/tracking/decisions/`(적응 컷·상대 마진 반증 + 0009 갱신 지시 · 상충쌍
  보존·탐지기 배제) · `docs/tracking/decisions/index.md`
- 신규: 테스트

**행동 계약**
- 입력은 **커밋된 검색 산출물뿐**이다(`reports/retrieval-strategies-live-*.json`).
  새 임베딩도 새 과금도 없다. 라벨은 **채점에만** 쓴다.
- 런타임과 같이 **상위 `top_k`(=5)로 먼저 자른 뒤** 규칙을 건다(spec §4-4). 전체 코퍼스
  랭킹으로 계산하면 배선 시점에 라이브와 어긋난다.
- 재현해야 하는 수치: 절대 하한 × 적응 컷 비율 × 상대 마진 **576 구성 중 0개** ·
  방향 1 하한 ≤ 0.3571 vs 방향 2 하한 > 0.4812 공집합 · 조건별 분리 여유
  (small-1536 +0.0147 / oracle +0.0534 / large-1536 −0.0114 / large-3072 −0.0160).
- **결정 기록 둘**: ① 적응 컷·상대 마진 반증과 결정 0009 갱신 지시 ② 상충쌍 보존·상충
  후보 탐지기 배제(컷 0.30 이 세 쌍을 이미 채택 · G22 과채택 증가)와 근거 수치.
- **어떤 전략 코드도 `planted`/`planted_note` 에 닿지 않는다**는 구조 테스트를 여기서
  세운다(spec §4-2). 정책 코퍼스의 심은 주석은 정답 그 자체이고 `policy_index` 가
  `PolicyChunk.planted` 로 이미 노출하므로, 라벨 금지만으로는 막히지 않는다.

**검증 게이트**: 스크립트가 커밋된 산출물로 위 수치를 그대로 낸다. 구조 테스트가 라벨·
골든셋·`planted` 계열 접근을 전부 막는다(음성 대조 포함). 전체 스위트 녹색. 파일 diff.

**thinking-base**: 이 태스크가 파도 1 에 있는 이유는 **답이 공짜로 나오는 질문을 유료
실측 뒤에 두지 않기 위해서**다. 사이클 3 은 도달 불가능한 후보군에 라이브를 태울 뻔했다.

## T1 — 회귀 가드 상설화 + 조건 지문 + 귀인 개선

**목표**: 라이브 평가 실행마다 하네스가 이중 기준선과 대조해 케이스 단위로 회귀를 잡고,
조건이 다른 실측끼리 비교하지 않게 만든다. spec §5 전체.

**작업 대상**
- 수정: `src/reply_gate/evaluation.py` — 이중 기준선 대조·비악화 판정·조건 지문·귀인
  개선 3건
- 신규: 승격 기준선 참조 파일의 로더·형식 (위치는 `data/` 아래 권장, 조정 가능)
- 수정: `scripts/AGENTS.md` · `src/reply_gate/AGENTS.md` (새 절·소유 경계)
- 신규: 테스트

**행동 계약**
- **두 줄 보고**: 승격 기준선(구속) + 직전 라이브(경보). 상반되면 승격이 이긴다.
- **비악화 판정은 두 겹이다**(spec §5-2):
  1. 기준선에서 3회 모두 일치한 케이스가 새 실측 3회 중 2회 이상 일치.
  2. **근거 부분 손실 검사** — 기준선에서 채택됐던 **정답 근거 ID** 가 새 실측에서
     빠지면 미달이다. 판정 단위는 케이스별 다수결(3회 중 2회 이상 채택)이고 빠진 ID 를
     이름으로 찍는다. **`matched` 만으로는 이 사이클을 촉발한 회귀를 못 잡는다** —
     커밋된 6세트에서 G18 은 모순 기각이 있을 때도 사라졌을 때도 `matched=True` 였다.
  3. **감시 모집단을 "기준선 3/3"으로 한정하지 않는다** — 기준선 2/3 이던 케이스가
     0/3 으로 무너지는 것도 경보다.
- **귀인 필드를 판정 조건으로 승격한다** — `missing_relevant_evidence_ids` 가 위 2번의
  입력이다. 표기로만 두지 않는다.
- **조건 지문**(spec §5-3): 라벨 버전 · 채택 축 구성(**컷 · 기권 게이트 통계량 · τ**) ·
  재작성 · 임베딩 모델/차원 · top_k · 생성/판정 모델 · **thinking/effort** · 판정
  프롬프트/픽스처 버전 · 캐싱 여부 · 측정 범위. **선언된 실험 변인은 대조를 진행하며
  차이 목록을 병기하고, 선언되지 않은 불일치만 "대조 불가 + 어긋난 항목"이다.**
  **τ 와 임베딩 모델은 한 쌍으로 읽는다** — 모델이 다르면 τ 가 같아도 대조 불가다.
- **재등재 경로**(spec §5-1): 판정 층이 바뀌면 승격 기준선을 다시 등재할 수 있어야
  한다. 승격과 같은 자격 — **사람이 참조 파일을 바꾸는 것**이고 자동 경로는 없다.
- **측정 3 은 무변경 가드 대상이 아니다** — 선언된 실험 변인으로 다룬다(spec §4-5).
  측정 1 무변경 검사는 가드에 남는다.
- **리포트 스템 규칙을 함께 고친다**(spec §7-5): 라이브 이름의 자격 판정 근거를
  `measurement2_is_real` 에서 **"과금 실행 여부"** 로 바꾼다. 그래야 측정 3 단독 실측이
  `evaluation-live-l2-*` 로 커밋된다. 이름 계열은 늘리지 않는다.
- **커밋된 기존 산출물은 읽기만 한다.** 사후 편집 금지. 새 필드는 새 실행부터다.
- 지문 스키마는 **검색·판정 구성 일반**으로 설계한다 — T9 가 τ 값을 넣을 때
  `evaluation.py` 를 다시 고치지 않아도 되게(값 추가만으로 확장되게).

**검증 게이트**: 대역 픽스처로 — 비악화 미달 검출, **근거 부분 손실 검출**(G18 회귀
재현 픽스처), 지문 불일치의 "대조 불가", 승격 부재 표기, 재등재 경로, 귀인 3분류 확장,
측정 3 단독 실행의 리포트 스템이 각각 재현된다. 음성 대조(멀쩡한 실행이 경보를 안 낸다)
포함. 전체 스위트 녹색. 파일 diff.

**thinking-base**: 구속을 승격 기준선에 둔 것은 판정의 재현 가능성 때문이다. 직전 줄은
경보로 남겨 정보는 잃지 않는다. 이 배치를 "단순화"를 이유로 한 줄로 합치지 마라.
그리고 **가드의 술어를 `matched` 하나로 되돌리지 마라** — 그것이 이 사이클의 출발점이다.

## T3 — 기권 게이트 격자 + 제약 채점

**목표**: 질의 단위 기권 게이트를 격자 축으로 넣고, 케이스 하한·상충쌍·기권을 판정하는
채점 규칙을 세운다. spec §4-2·§4-3.

**작업 대상**
- 수정: `src/reply_gate/retrieval_eval.py` · `src/reply_gate/retrieval_strategies.py`
  (기권 게이트를 구성 인자로)
- 신규: 테스트

**행동 계약**
- 게이트는 **결정론 후처리**다 — 점수는 그대로 두고 **질의 단위로** 채택 집합을 비운다.
  LLM 호출을 새로 넣지 않는다.
- **통계량 5종을 전부 격자에 넣는다**: 1위−`top_k`위 산포 · 상위 표준편차 · 1위 대비
  산포 비 · 1위−2위 gap · `top_k`위/1위 비. 손계산에서 뒤의 둘은 분리하지 못했지만
  **반증된 통계량도 산출물이다** — 격자에서 빼지 말고 결과로 보여라.
- **통계량은 상위 `top_k` 만 보고 계산한다**(spec §4-4). 런타임이 SQL `LIMIT` 으로 먼저
  자르므로, 전체 코퍼스 랭킹으로 계산하면 T9 배선에서 라이브와 어긋난다.
- τ 는 스윕 인자다. 절대 하한(컷 0.30)은 유지한 채 그 위에 얹는다.
- **채점 제약 셋**(spec §4-3):
  ① **정답 조항이 비어 있지 않은 25건**에서 **정답 조항을 하나도 채택 못 하면 즉시 탈락**
  ("근거 0건 금지"가 아니다 — G04 의 1위는 오답이다)
  ② 상충쌍 케이스 **셋(G18·G01·G02)** 에서 상충쌍 동시 채택
  ③ **G21–G24 가 채택 0건**(감소가 아니라 기권 — 라이브 표적 ②와 같은 문턱)
  채점자는 라벨을 본다. **전략 코드는 라벨·골든셋·`planted` 계열에 닿으면 안 되고
  T0 이 세운 구조 테스트가 그 경계를 지킨다.**
- 리포트는 구성별 macro 수치와 **케이스별 행**(정답 채택 여부 · G21–G24 채택 건수 ·
  G18/G01/G02 상충쌍 포함 여부 · **경계까지의 여유**)을 함께 싣는다. 경계 여유를 찍는
  이유는 τ 가 얼마나 아슬아슬한지가 라이브 이전 가능성의 유일한 사전 신호이기 때문이다.
- 기존 `retrieval-*` 산출물 덮어쓰기 거부 규율 그대로.

**검증 게이트**: 대역 임베딩으로 통계량 5종 × τ 스윕 완주. 손계산 픽스처로 — 케이스
하한 위반 구성이 탈락으로 찍히고, 상충쌍 미보존이 표기되고, "감소했지만 기권은 아닌"
구성이 탈락하는 것. 전체 스위트 녹색. 파일 diff.

## T5 — 격자 실측 + 채택/비채택 결정 초안  ⚠️ 소액 과금 (상한 안 · 승인 불요)

**목표**: 기권 게이트 격자를 실측해 spec §4-3 규칙대로 하나를 고르거나, 아무것도

- 리포트는 git 추적 대상으로 넣는다(사후 편집 금지 자동 적용).

**검증 게이트**: 격자 리포트가 전 구성을 담고, 결정 초안이 그 수치를 인용한다.

- 분해는 커밋된 산출물만 읽는다(무과금·사후 편집 금지). L1 선기각의 판정 호출 절약,
  사이클 3 T10 의 −22.9% 는 **컷 0.50 조건 병기**, 이번 T10 의 새 조건 수치를 나란히.
- 비동기화 문서: 지연 구조 분해(실측 인용) + 설계안 + 트레이드오프(API 계약·상태 전이·
  데모 단순성) + **"이번 사이클은 구현하지 않는다"** 결론. 코드 무변경.

**검증 게이트**: 인용 수치가 전부 커밋된 산출물과 대조되고, 달러 수치마다 단가·기준일이
붙어 있다. 문서-only.

판정 층(T6·T7·T8)을 T10 **뒤로** 옮긴 것이다 — 파도 하나와 축별 귀인을 맞바꿨다.
T12 는 파도 3 부터 언제든 돌 수 있고 T13 앞에만 끝나면 된다.

**핵심 착륙이 앞으로 나왔다**: T9·T10 이 파도 4·5 이고, 이전 청사진에서 T9 를 붙들고
있던 T6·T8 의존이 **사라졌다.** handoff 의 축소 지침("조이면 §6·§7 을 미룬다")이 이제
핵심 착륙을 죽이지 않는다 — T6·T7·T8·T11 을 통째로 미뤄도 T0~T5·T9·T10·T13 이 완주한다.

**T6·T7·T8 이 T10 뒤인 이유**: 셋 다 판정 층(프롬프트·모델·캐싱)을 건드린다. T10 앞에
두면 승격 기준선(T2) 대비 T10 이 채택 축 말고도 판정 층 변수를 함께 들고 있어 결정 0011
의 **축별 원복이 귀인 불가능**해진다. spec §7-2 가 2026-08-19 개정으로 이 순서를 명시한다
— 원칙("조건이 섞인 실측을 만들지 않는다")은 그대로이고 그 원칙을 더 잘 지키는 배치로
바뀐 것이다.

**장벽이 비어 있는 이유**: 스키마·볼륨 변경이 없는 사이클이다(기권 게이트는 점수 후처리,
청킹은 오프라인, 캐싱은 호출 구성). 외부 상태 작업은 T2·T10 의 라이브 실측과 T13 의 웹
폼 재현뿐이고 전부 단일 태스크 안에서 직렬이다. T5 가 "채택 없음"이면 T9·T10 은 건너뛰고
T11 은 T2 산출만으로, T13 은 반증 서사로 간다 — 그래프는 그대로 두고 태스크 안에서
스킵을 기록한다.
