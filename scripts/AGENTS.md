# scripts 패키지

## 범위

사람이 손으로 실행하는 진입점. `uv run python -m scripts.<이름>` 으로 돈다.

| 스크립트 | 역할 | 외부 키 |
|---|---|---|
| `seed_orders.py` | 스키마 적용 + 커밋된 주문 픽스처 500건 적재 | 불필요 |
| `index_policies.py` | 정책 문서를 조항 단위로 임베딩해 `policy_chunks` 에 적재 | 필요 |
| `evaluate.py` | 측정 1(L1 픽스처)·측정 2(골든셋 end-to-end)·**측정 3(L2 판정 단위 정확도)** 산출, 리포트 파일 생성, **회귀 가드 두 줄 보고** | `--live` 일 때만 (L2 켜짐이면 판정 키까지 **둘 다**) |
| `compare_retrieval.py` | DB 없는 4단계 검색 전략 비교(blind 재작성 기본, 벡터 단독·oracle·모델 축은 명시 옵션) | 임베딩은 `--live`, 리랭크는 `--live`/`--rerank-with-openai` — **두 축이 따로다**. 캐시 miss 과금 가능 (기본 대역은 불필요) |
| `generate_blind_rewrites.py` | blind 재작성 픽스처 생성 — 골든셋 문의 원문만 모델에 준다 | `--live` 일 때만. 1회 제작용이고 상시 실행 경로가 아니다 |

**이 패키지의 범위가 아닌 것**: 애플리케이션 로직(→ `src/reply_gate/`). 스크립트는 인자를
파싱하고 패키지의 함수를 부르고 결과를 출력하는 얇은 껍데기여야 한다. 여기에 도메인 판단이
들어가면 테스트되지 않는 로직이 생긴다.

## 불변식

1. **시딩 경로에 LLM 을 넣지 않는다.** 주문 데이터는 저장소에 커밋된 픽스처를 로드한다 —
   생성이 시딩에 들어가면 멱등이 깨지고 재현이 불가능해진다.
2. **재실행이 안전해야 한다.** 시딩은 두 번 돌려도 500건이고, 정책 적재는 중복 없이
   갱신하며 문서에서 사라진 조항은 삭제한다.
3. **비밀을 출력하지 않는다.** 접속 대상을 로그에 남길 때 비밀번호를 제외한다.
4. **평가 하네스는 과금을 조용히 하지 않는다.** 실제 모델 실행은 `--live` 로 명시해야 한다.
   기본 실행은 측정 1(외부 호출 0회)만 돈다.
   **과금 축이 둘 이상이면 플래그도 둘이다** — 검색 비교의 임베딩 위치와 LLM 리랭크 과금은
   별개 인자다. 한 불리언으로 묶으면 "로컬 임베딩" 의도가 리랭크 과금을 켠다(실제로 그랬다:
   `--bge-m3` 가 "외부 API 없음"이라 적힌 채 리랭크를 호출했다). 승인되지 않은 단은 대역으로
   메우지 않고 불변식 5 대로 "미측정 + 사유"로 남긴다 — 실제 수치와 대역 수치를 한 리포트에
   섞지 않는다.
5. **미실행 측정을 0 이나 빈 값으로 채우지 않는다.** 리포트에 "미실행 + 사유"로 남긴다 —
   돌지 않은 측정이 0 으로 찍히면 리포트가 거짓말을 한다.
   **이 규칙은 케이스 단위에도 적용된다.** L2 판정 호출이 무너진 케이스는 게이트가 돌지
   못한 것이지 게이트가 놓친 것이 아니다 — `bait_reject_recall` 의 분모에서 빼고
   `bait_unmeasured` 로 따로 센다(`GoldenOutcome.gate_never_ran`). 그 시도의 종합 verdict 는
   `pass` 라서 `attempt_verdicts` 만으로는 "돌았고 통과"와 구분되지 않는다.
6. **대역으로 낸 수치는 실제 수치가 아니라고 리포트에 경고를 단다.** 어휘 기반 임베딩 대역의
   유사도는 실제 임베딩과 스케일이 다르다.
7. **라이브 리포트 이름 ⇔ 과금 실행 — 양방향 불변식이다.** 과금 실행만 `evaluation-live*`
   에 쓸 수 있고, 과금 실행은 그 이름에만 쓸 수 있으며, 이미 존재하는 라이브 리포트는
   덮어쓸 수 없다. 판정과 거부는 스크립트가 아니라 패키지(`evaluation.resolve_report_stem`,
   단위 테스트 있음)가 하고, **측정 시작 전에** 돈다. 재생성에 과금이 드는 산출물이 재생성이
   공짜인 산출물과 같은 경로를 쓰면 안 된다 — 실제로 한 번 그렇게 잃었다
   (`docs/engineering-notes.md`).
   **자격 판정 근거는 "측정 2 실측 여부"가 아니라 "과금 실행 여부"다.** 불변식의 목적은
   "과금된 산출물을 잃지 않는다"이고 `measurement2_is_real` 은 그 목적의 낡은 대리 변수였다
   — 측정 2 를 건너뛰고 측정 3 만 사는 실행이 라이브 이름을 거부당하면 `evaluation` 스템으로
   떨어져 `.gitignore` 의 `reports/*` 에 걸리고, 추적되지 않은 채 다음 실행에 덮인다.
   **이름 계열은 늘리지 않는다** — `evaluation-live-l2-*` 그대로이므로 계열 불증가·덮어쓰기
   금지·추적 패턴이 전부 유지되고, 돌지 않은 측정은 불변식 5 대로 "미실행 + 사유"로 적힌다.
8. **두 번째 겹: L2 켜짐 실측 ⇔ `evaluation-live-l2` 접두 — 이것도 양방향이다.** L2 켜짐
   실측은 l2 계열에만, L2 꺼짐 실측은 l2 계열이 **아닌** 라이브 이름에만 쓴다. **기본 이름과
   `--report-stem` 명시 스템 양쪽에 건다** — 기본 이름만 갈라 두면
   `--report-stem evaluation-live-4` 한 줄이 꺼짐 기준선 계열을 오염시킨다. L2 켜짐 실측의
   기본 이름은 `evaluation-live-l2-<n>` 자동 넘버링이다(3회 반복 실측이 이름 충돌로 죽지
   않게). 계열이 뒤섞이면 산출물만 보고는 어느 쪽이 L2 를 포함해 잰 값인지 알 수 없다.
9. **판정 키 선검사도 측정 시작 전이다.** `--live` + L2 켜짐이면 `OPENAI_API_KEY` 와
   `ANTHROPIC_API_KEY` 를 **둘 다** 본다. 판정 키 부재를 측정 도중 발견하면 과금만 하고
   산출물 없이 죽는다.
10. **강등 실행 금지.** 판정 키가 없다고 L2 를 꺼서 측정 2 만 돌리지 않는다 — 측정 2·3 을
    **모두** 건너뛴다. 요청은 켜짐인데 나온 값은 꺼짐 기준선이면 두 실측이 함께 오염된다.
11. **측정 선택은 `--measurements` 이고, 고르지 않은 측정은 "미실행 + 사유"다.** 측정 1 은
    무과금·결정론이라 항상 돈다. 측정 3 이 실제로 요구하는 것은 **판정 키 + L2 켜짐**뿐이다
    — DB 도 생성 키도 골든셋도 아니다(입력은 판정 픽스처다). 그래서 `--live --measurements 3`
    은 DB 없이 도는 **측정 3 단독 실측**이고, 불변식 7 대로 라이브 이름을 받는다.
    **예전에는 측정 3 이 측정 2 의 사유를 무조건 물려받았고** 근거는 "실측 여부가 갈리면
    과금된 판정 수치가 덮어쓸 수 있는 이름으로 샌다"였다. 그 근거는 이름의 자격이 과금 실행
    여부로 바뀌면서 사라졌다. 남은 결합은 둘뿐이다: ① **측정 2 를 함께 고른** 실행에서는
    측정 2 의 선검사 사유를 물려받는다(요청되지 않은 부분 구매를 막는다 — 불변식 10 과 같은
    규칙), ② 측정 2 가 **중단되면** 측정 3 도 잇지 않는다(Ctrl-C 를 삼키고 판정을 더 사면
    안 된다).
12. **종료 코드가 1 이 되는 경우는 둘뿐이다: ① 측정 3 이 돌 조건이었는데 미실행,
    ② 사용자 중단(Ctrl-C). 그 밖은 0.**
    ①의 "돌 조건"은 `--live` 로 **판정 선검사를 통과한** 실행이다(측정 3 선택 · L2 켜짐 ·
    판정 키 있음, 그리고 측정 2 를 함께 골랐다면 그쪽 선검사까지). 완주했든 중단됐든 같고,
    사유가 무엇이든(픽스처 로드 실패·중단·연쇄 미실행) 동일하다 — 돈을 쓰고 판정 수치는 못
    낸 실행이 래퍼·CI 에 "성공"으로 읽히면 안 된다. 그래서 "돌 조건"은 **선검사 시점에**
    잡아 둔다: 그 뒤에 생기는 사유는 "돌 조건이 아니었다"가 아니라 "못 돌았다"이다.
    ②는 **과금 여부와 무관하다**: `--stub-llm`·기본 실행의 Ctrl-C 도 1 이다. 리포트는
    그대로 쓰되(과금분 보존) 중단 사실은 종료 코드가 들고 간다.
    `--live` 없는 실행에서 측정 3 이 "`--live` 아님" 사유로 미실행인 것, **L2 꺼짐 기준선
    실행에서 측정 3 이 설계상 안 도는 것**, `--measurements 2` 로 **고르지 않은 것**은
    정상이므로 0 이다.
13. **어느 측정이 죽어도 리포트는 쓴다.** 측정 2·3 의 예상 밖 중단을 트레이스백으로 알리면
    이미 과금이 끝난 완주분과 무료인 측정 1 산출물이 함께 사라진다. 중단은 **리포트의 미실행
    사유**(예외 종류와 메시지 그대로)와 종료 코드로만 알린다.
14. **blind 조건은 생성기의 입력 목록이 지킨다.** `generate_blind_rewrites.py` 는 골든셋 문의
    원문 외에 아무것도 모델에 넣지 않는다 — 정답 라벨·정책 문서·oracle 픽스처를 import 하거나
    경로로 참조하면 구조 테스트가 막는다. **쓰지 않는 import 도 잡는다**: 처음 만든 검사가
    `ast.Name` 만 봐서 미사용 import 를 통과시켰고, 음성 대조로 그것을 확인한 뒤 고쳤다.
    산출은 `--out` 경로에만 쓰고 기존 픽스처를 덮어쓰지 않는다. 생성 모델은 런타임 의도
    해석과 **같은 등급**이어야 한다 — 상위 모델로 만들면 배포 가능한 이득이 아니라 또 하나의
    상한을 재게 된다([결정 0010](../docs/tracking/decisions/0010-검색-정답의-관련성-경계를-정하고-blind-재작성을-모델이-만든다.md)).
15. **리포트는 검색 구성을 실행 조건 필드로 담는다 — 파일 이름 계열을 늘려서가 아니다.**
    같은 지표를 다른 검색 구성에서 낸 두 리포트가 필드 없이 나란히 놓이면 어느 조건의
    수치인지 산출물만으로 되짚을 수 없다(재작성 켜짐/꺼짐 · 컷 · `top_k` · 임베딩 모델).
    그래서 검색 구성 요약은 **선택 필드가 아니라 필수 필드**다. 이름으로 조건을 표현하려는
    유혹은 불변식 7(이름 ⇔ 과금 실행)과 충돌한다 — 이름은 과금 여부만 말한다.
16. **라이브 실행마다 회귀 가드가 두 줄로 보고한다.** 승격 기준선(**구속** — 비악화 판정과
    "미달이면 원복 기본"의 발동 근거)과 직전 라이브(**경보** — 정보로 병기, 판정을 발동시키지
    않는다). 두 줄이 상반되면 **승격 기준선이 이긴다.** 판정은 스크립트가 아니라
    패키지(`reply_gate.regression_guard`)가 하고, 스크립트는 결과를 콘솔에 찍기만 한다.
    **가드가 실패해도 리포트는 쓴다**(불변식 13과 같은 규칙) — 실패는 "미산출 + 사유"다.
    **판정의 정의인 검사가 돌지 않았으면 "통과"가 아니라 "보류"다** — 기준선 산출물에 귀인
    절이 없어 근거 부분 손실 검사가 못 돌았거나, 세트가 안 찼거나, 공통 케이스가 없는
    경우다. 사유를 아래 미판정 줄에만 남기고 헤드라인을 통과로 적는 것은 불변식 5 위반이다.
    승격 등재가 자기가 가리키는 산출물과 어긋나면(스템끼리 조건이 다르거나 참조의 조건
    지문이 산출물과 다르면) 대조 전에 **재등재**를 요구한다.
17. **승격은 사람만 한다.** `data/promoted_baseline.json` 을 사람이 바꾸는 것이 승격이고,
    판정 층(판정 프롬프트·픽스처·캐싱)이 바뀐 뒤의 **재등재**도 같은 자격이다. 하네스에
    자동 승격 경로를 두지 않는다 — 구속 기준선을 코드가 갱신하면 판정이 자기추인이 된다.
    구조 테스트가 저장소 전체에서 그 파일에 **쓰는** 호출을 찾아 막는다(음성 대조 포함).
    승격 참조가 없으면 리포트는 **"기준선 미등재"** 라고 적는다 — 0 이나 "통과"가 아니다.
18. **선언 없이 달라진 조건끼리 대조하지 않는다.** 실행 조건의 **조건 지문**이 대조 가능성을
    가른다(라벨 버전 · 채택 축 구성 · 재작성 · 임베딩 모델·차원 · `top_k` · 생성/판정 모델 ·
    판정 thinking/effort · 판정 프롬프트·픽스처 버전 · 캐싱 · 측정 범위). **τ 와 임베딩
    모델은 한 쌍으로 읽는다** — 모델이 다르면 τ 가 같아도 대조 불가다. 이번에 의도적으로
    바꾼 축은 `--declare-experiment` 로 **선언**해야 대조가 진행되고 차이 목록이 병기된다.
    선언되지 않은 불일치는 "대조 불가 + 어긋난 항목"이고, 한쪽에 값이 없는 항목은 "미상"이다.
    지문 스키마는 **열린 맵**이라 새 검색·판정 축은 `_condition_fingerprint` 에 값만 더하면
    되고 `evaluation.py` 를 다시 열지 않는다.

## 테스트 지침

스크립트 자체는 얇으므로 별도 테스트를 두지 않는다. 대신 스크립트가 부르는 패키지 함수가
테스트 대상이다. 스크립트를 바꿀 때는 **실제로 실행해 exit code 와 출력을 확인**하고,
DB 를 건드리는 것은 실행 전후 건수를 대조한다.
