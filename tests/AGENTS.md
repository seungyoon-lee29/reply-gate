# tests 패키지

## 범위

이 저장소의 검증 전부. **테스트가 이 제품의 유일한 주장(신뢰성 지표)을 지탱하므로,
여기서는 테스트가 부속물이 아니라 산출물이다.**

`uv run pytest` 로 전부 돌고, DB 가 필요한 것만 `db` 마커로 갈라져 있다
(`pyproject.toml` 의 `markers`). **DB 없이 돌리면 그 테스트들은 사유를 담아 skip 되므로,
전체 녹색을 주장하려면 `uv run pytest -m db` 로 skip 0 을 따로 확인해야 한다.**

**이 패키지의 범위가 아닌 것**: 애플리케이션 로직(→ `src/reply_gate/`), 실행 진입점
(→ `scripts/`), 결정론 대역 구현(→ `src/reply_gate/testing.py` — 대역은 제품 패키지가
소유하고 테스트는 쓰기만 한다).

## 테스트의 네 종류

| 종류 | 무엇을 지키나 | 예 |
|---|---|---|
| **행동 검사** | 함수·라우트가 계약대로 동작하는가 | `test_gate.py` 사유 4종 양성·음성, `test_api.py` 응답 스키마 |
| **구조 검사(AST)** | *코드가 그렇게 쓰여 있는가* — 실행해서는 못 보는 불변식 | `test_answer_key_isolation.py`(정답 격리), `test_durable_citations.py`(인용), `test_regression_guard.py`(승격 자동 쓰기 금지) |
| **DB 통합** | 스키마·권한·왕복이 실제 Postgres 에서 맞는가 | `test_db_readonly.py`, `test_records.py` |
| **평가 장치 검사** | 픽스처·라벨이 여전히 그 자리에 있는가 | `test_adoption_axis.py`, `test_retrieval_labels.py` |

**구조 검사가 이 저장소의 특징이다.** 규율로 두 번 이상 실패한 규칙만 여기로 온다 —
`docs/engineering-notes.md` "소스 주석이 아카이브될 설계 문서를 인용했다" 가 그 전례다.

## 불변식

1. **외부 API 를 실제로 부르는 테스트는 없다.** 과금 실행의 입구는 평가 하네스의
   `--live` 하나뿐이다. `live` 마커는 등록만 되어 있고 쓰는 테스트도 제외 장치도 없다 —
   붙이려면 제외 장치를 함께 만든다.
2. **`db` 마커 테스트는 DB 가 없을 때만 skip 한다.** skip 사유에는 접속 대상·원인·복구
   명령을 담는다(`conftest.py`). **조용히 늘 skip 되는 테스트는 검증이 아니다.**
3. **구조 검사에는 음성 대조를 함께 둔다.** 검사기가 실제로 무언가를 잡는다는 것을 같은
   파일이 증명해야 한다 — 빈 검사가 초록으로 보이는 사고를 blind 구조 검사에서 한 번
   겪었다. 지금 음성 대조를 들고 있는 파일: `test_answer_key_isolation.py` ·
   `test_abstention_wiring.py` · `test_abstention_gate.py` · `test_chunking_grid.py` ·
   `test_durable_citations.py` · `test_judge_prompt_caching.py` · `test_regression_guard.py`.
4. **검사 대상 목록을 손으로 관리하지 않는다.** 패키지 파일 목록은 디렉터리에서 유도하고,
   면제 목록은 "존재하는 파일만 담는다"를 함께 검사한다. 유도는 **재귀**여야 한다 —
   비재귀 `glob("*.py")` 은 하위 패키지를 통째로 놓쳐서, 하나 생기는 순간 그 안의 런타임
   코드가 조용히 검사 밖으로 나간다.
5. **AST 검사는 `node.names` 를 전부 훑는다.** `import a, b` 는 alias 가 여럿이라
   첫 이름만 보면 둘째부터가 가드 밖이다.
6. **경로가 변수를 한 번 거치는 것을 계산에 넣는다.** 호출 문면만 훑는 검사는
   `reference = DEFAULT_PROMOTED_BASELINE_PATH` 뒤의 `reference.write_text(...)` 를 놓친다.
7. **소스를 문자열로 스캔해 가드를 켜고 끄지 않는다.** 주석·docstring 에 이름이 스치기만
   해도 가드가 스스로 꺼진다. AST 로 보면 주석은 애초에 없고 docstring 은 제외할 수 있다.
8. **`Settings()` 를 인자 없이 부르지 않는다 — 선언값을 재려면 `conftest.declared_settings()`
   다.** 인자 없는 생성은 개발자의 `.env` 와 프로세스 환경을 함께 읽어, "기본값이 결정대로
   인가"를 재는 검사가 **로컬 환경을 재게** 된다. 환경 변수 경로를 일부러 재는 테스트만
   `Settings()` 를 쓴다.
9. **단언식 안에 설정 객체를 두지 않는다.** 실패 출력이 객체를 통째로 repr 하고 거기에
   자격 증명이 실린다 — 실제로 한 번 났다. **bool 로 먼저 묶어라**
   (`docs/security.md`, `tests/test_config_secrets.py`).
10. **평가 장치를 테스트 편의로 바꾸지 않는다.** 골든셋·L1 픽스처·판정 픽스처·검색 정답
    라벨·재작성 픽스처·승격 기준선은 `CLAUDE.md` "절대 깨지 않는 것" 5·6 이 지키는 대상이다.
    픽스처 한 바이트가 조건 지문을 바꿔 커밋된 리포트 전부와 대조가 끊긴다.
11. **테스트 이름은 한국어 서술문**이고 무엇을 지키는지가 이름에서 읽혀야 한다. docstring
    에는 **왜 그 불변식이 있는지**(대개 실제로 깨졌던 사건)를 적는다.

## 손댈 때

- **행동을 바꾸면 그 행동의 검사부터 바꾼다.** 검사를 지워 초록을 만드는 것은 원복이
  아니라 은폐다.
- **가드를 새로 만들 때는 음성 대조를 같은 커밋에 넣는다**(불변식 3).
- **구조 검사가 실패하면 검사기를 느슨하게 하기 전에 그 검사가 지키는 문서를 먼저 읽는다** —
  대개 `docs/standards.md` 나 모듈 노트에 이유가 있다.
