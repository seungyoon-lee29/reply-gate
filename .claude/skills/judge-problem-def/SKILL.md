# 문제정의 심판 (judge-problem-def)

문제정의 문서가 얼마나 잘 됐는지를 **독립 심판 N회 실행**으로 점수화한다.
페르소나 역할극은 쓰지 않는다 — 같은 루브릭을 가진 심판을 새 컨텍스트에서
독립적으로 여러 번 실행하고, 점수의 평균과 편차로 안정성을 함께 본다.

## 실행 방법

1. 심판 서브에이전트를 **기본 5회** 독립 실행한다 (사용자가 횟수를 지정하면 그 값).
   각 심판은 서로의 결과를 보지 못한다.
2. 각 심판에게 아래 루브릭과 대상 문서 경로만 준다. 기대 점수·이전 결과를 힌트로 주지 않는다.
3. 심판은 문서를 읽고 **각 기준에 1–10점 + 근거 인용(문서의 실제 문장)**을 붙인다.
   근거 인용이 없는 점수는 무효로 취급한다.
4. 메인이 집계한다: 기준별 평균·최솟값·최댓값, 총점 평균, 심판 간 표준편차.
   심판이 낸 약점 지적은 **걸러내지 않고 전부** 보고한다 (전역 규칙).

## 루브릭 (각 1–10점)

| # | 기준 | 무엇을 보나 |
|---|---|---|
| 1 | **페인 포인트 실재성** | 문제가 실제로 아픈 문제인가. 구체적 실패 사례·비용이 제시되나, 아니면 일반론인가 |
| 2 | **문제-해결 정합성** | 제시한 접근이 정의한 문제를 정면으로 겨냥하나. 문제 따로 해결 따로가 아닌가 |
| 3 | **대안 분석의 정직함** | 기존 방식이 왜 부족한지가 허수아비가 아닌 실제 반론을 다루나 |
| 4 | **성공 판정의 반증 가능성** | 성공/실패를 가르는 기준이 측정 가능하고, 실패로 판명될 수 있는 구조인가 |
| 5 | **범위의 명시성** | 하지 않는 것이 명시돼 있고 그 이유가 원리적인가(못 한 것 vs 안 한 것 구분) |
| 6 | **피드백 루프** | 실측·현실이 문제정의를 수정한 흔적이 있나. 정의가 박제인가 살아있나 |

## 심판 출력 형식 (JSON)

```json
{
  "scores": [{"criterion": 1, "score": 8, "evidence": "문서 인용", "weakness": "지적 사항 또는 null"}],
  "total": 46,
  "top_weaknesses": ["가장 아픈 약점 1–3개"],
  "verdict": "한 문단 총평"
}
```

## 보고 형식

- 기준별 평균 점수 표 + 총점 평균/60
- 심판 간 표준편차 (판정 안정성)
- 모든 심판의 약점 지적 전문 (중복은 "N명 지적"으로 병합하되 내용은 유지)
