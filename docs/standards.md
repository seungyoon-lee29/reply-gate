# 규칙

어기면 빌드·테스트·런타임이 깨지거나 구조가 어긋나는 것만 적는다. 선호는 규칙이 아니다.

## 검증 게이트 — 병합 전 통과 조건

네 명령이 모두 exit 0 이어야 한다.

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy                 # strict
uv run pytest
```

**`uv run pytest` 는 DB 기동을 전제한다.** `db` 마커가 붙은 통합 테스트는 Postgres 에
접속되지 않으면 사유를 담아 skip 된다. 조용히 늘 skip 되는 테스트는 검증이 아니므로,
**전체 녹색을 주장하려면 `docker compose up -d --wait` 를 먼저 실행하고
`uv run pytest -m db` 가 skip 0 인지 확인해야 한다.**

`mypy` 는 strict 이고 `src`·`tests`·`scripts` 를 전부 본다. 테스트에서 목을 주입할 때는
`typing.cast` 를 쓴다.

## 소유권 — 정의를 두 곳에 두지 않는다

| 정의 | 단독 소유자 | 위반하면 |
|---|---|---|
| 주문번호 형식(정규식·검증·생성) | `src/reply_gate/order_ref.py` | 시딩과 접수 검증이 어긋나 존재하는 주문이 거부된다. DB CHECK 제약이 **같은 정규식 문자열**을 쓰고 테스트가 두 곳의 일치를 검사한다 |
| 답변 계약·근거 ID 체계·판정/인계 enum | `src/reply_gate/contracts.py` | L1·L2 두 층과 저장·응답이 함께 쓰는 계약이다. 편의로 구조를 바꾸지 않는다 |
| 의존성 선언·린트/타입/테스트 설정 | `pyproject.toml` | 태스크 코드가 의존성을 늘리면 재현성이 깨진다 |
| 스키마 화이트리스트 | `src/reply_gate/sql_guard.py` | 두 곳에 두면 한쪽만 넓혀져 조용히 샌다 |

## 하드 게이트 — 절대 깨지 않는 것

1. **L1 게이트는 LLM 을 호출하지 않는다.** `src/reply_gate/gate.py` 는 `anthropic`·`openai`·
   `httpx`·`requests`·`urllib`·`socket`·`random`·`time`·`datetime`·`os`·`uuid` 를 import 하지
   않는다. AST 기반 구조 테스트가 이를 검사한다. 게이트가 확률적이 되는 순간 검출률·오탐률을
   재현 가능한 숫자로 말할 수 없다.
2. **text-to-SQL 안전장치 3종은 생략 불가.** read-only 계정 · 스키마 화이트리스트 · 쿼리 검증.
   "데모니까 나중에"가 허용되지 않는다.
3. **루프 종료·데이터 접근·권한·근거 채택은 코드가 통제한다.** LLM 은 의도 분류 라벨·SQL
   문자열·초안 JSON·**L2 판정 JSON**·**검색용 재작성 질의** 까지만 만든다. 재생성 상한
   1회는 `for` 문의 범위가 강제하고 DB CHECK 가 같은 상한을 중복으로 건다. **판정 JSON 도
   산출물일 뿐이다** — 그 산출을 재생성·인계·종결로 옮기는 것은 코드이고, 해석되지 않는
   판정은 통과가 아니라 거부다. **재작성 질의도 검색 입력일 뿐이다** — 무엇이 근거가
   되는지는 임계값과 `top_k` 가 자르고, 호출이 실패하면 코드가 원문 질의로 폴백한다
   (인계가 아니다 — `docs/business-rules.md` "검색 단계 실패").
4. **비밀은 어디에도 평문 금지.** 코드·문서·설정·권한 목록 전부.
5. **평가용으로 심은 장치를 제거하지 않는다.** 정책 문서의 미끼·모호·상충 조항,
   기각 유발 골든셋 문의, L1 픽스처, **L2 판정 픽스처**(`data/judge_fixtures.jsonl` —
   측정 3 의 유일한 입력이라, 사라지면 과금 실행이 판정 수치 없이 끝난다),
   **검색 정답 라벨**(`data/retrieval_labels.jsonl` — 검색 recall·precision 의 유일한 정답
   입력), **blind 재작성 질의 픽스처**(`data/rewritten_queries.jsonl` — 정책·라벨을 본 적 없는
   생성 모델이 원문만 보고 만든 배포 가능 조건)와 **oracle upper-bound 픽스처**
   (`data/rewritten_queries_oracle.jsonl` —
   정책·라벨 기반 상한 대조군). 제거하면 기각 장면과 검색 품질 측정이 재현되지 않는다.

## 검색 관련성과 답변 충분성은 다른 계약이다

검색 recall 의 정답은 **두 겹**이다([결정 0010](tracking/decisions/0010-검색-정답의-관련성-경계를-정하고-blind-재작성을-모델이-만든다.md)):
① 문의에 정면으로 답하는 조항, ② 그 조항과 **같은 사안을 다르게 정한 상충 조항**.
조건·제한 조항(재고 소진·대형 상품 지연)과 채널·전제 조항(접수 채널·주문번호 안내)은 넣지
않는다 — 문의만 보고 해당 여부를 알 수 없는 조항은 어떤 검색기도 공정하게 맞힐 수 없다.
접근 통제·공개 제한은 포함한다. 실행 요청("환불해 주세요")의 정답 유무는 실행 요청인지가
아니라 **조항이 그 요청에 답하거나 고객이 스스로 할 방법을 주는지**로 가른다.

②를 넣는 이유는 채점표가 제품이 원하는 동작을 벌하지 않게 하기 위해서다 — L2 가 모순을
잡으려면 검색이 상충하는 두 조항을 함께 올려야 하는데, 정답이 한쪽뿐이면 그 동작이
precision 에서 깎인다.

이 분모는 답변이 반드시 모든 조항을 인용해야 한다는 뜻이 아니다. 답변 citation sufficiency는
L1·L2가 주어진 답변과 인용 근거를 대상으로 별도 판정한다.

## 재시도 상한 — 전부 코드가 강제

| 지점 | 상한 | 초과 시 |
|---|---|---|
| LLM 전송 오류 | 최초 + 1회 (래퍼가 **단독** 통제) | `llm_call_failed` |
| 의도 분류 형식 불일치 | 최초 + 1회 | `llm_call_failed` |
| SQL 생성·검증·실행 | 최초 + 1회 (오류를 피드백으로) | `sql_failed` |
| 초안 생성 형식 불일치 | **재시도 없음** | 원문을 L1 에 넘겨 `schema_violation` |
| 초안 재생성 | 최초 + 1회 | `rejected_twice` |
| L2 판정 전송 오류 | 최초 + 1회 (래퍼가 **단독** 통제 — 판정 모듈은 다시 재시도하지 않는다) | `llm_call_failed` (실패 단계 `l2_judge`) |
| L2 판정 형식 불일치 | 최초 + 1회 (직전 산출과 사유를 피드백으로) | `llm_call_failed` (실패 단계 `l2_judge`) |

L2 두 행의 실패는 **재생성 사유가 아니다** — 인프라·형식 실패는 초안을 고쳐서 나아지지
않으므로 루프를 더 돌리지 않고 인계한다. 두 실패 모두 **그때까지 과금된 판정 토큰을 예외에
실어** 올려보낸다: 실행됐으나 실패한 호출의 토큰도 실비용이다(`docs/contracts.md`
"토큰 집계 경계").

**표의 상한은 층별 값이고, `LLMCallError.attempts` 는 실제로 나간 전송 수다.** 두 층이
겹치면(형식 루프 안에서 전송 오류) 값은 합이다 — 형식 실패로 나간 전송 1회 + 래퍼가 센 2회
= 3. **토큰과 같은 자격으로 누적한다**: 앞선 시도의 비용을 세면서 그 시도가 있었다는 사실을
세지 않으면 기록이 실제와 갈린다(실제로 그랬다 — 전송 3회를 `attempts=2` 로 신고했다).
응답 계약의 `attempts[]`(초안 재생성 배열, `docs/contracts.md`)와는 **다른 카운터**다.

**SDK 자동 재시도를 반드시 끈다.** 쓰는 두 SDK(OpenAI·Anthropic)가 **모두** 전송 오류·429·
5xx 를 기본 2회 재시도한다 — provider 를 늘릴 때도 같은 확인이 필요하다. 래퍼 재시도와
중첩되면 "1회 재시도"가 실제로는 최대 6회 전송 시도가 되어 지연·처리 기록이 어긋난다.
**생성이든 주입이든** 래퍼 생성자가 관문(`llm._pin_transport_policy`)을 통과시켜
`max_retries=0` 과 타임아웃을 고정하고, 끌 수단이 없는 클라이언트는 조립에서 거부한다
(fail-closed). 테스트가 **양쪽 경로**를 검사하고, 구조 테스트가 "모든 클라이언트 대입은
관문을 지난다"를 못박는다. 값을 `client or SDK(..., max_retries=0)` 의 **`or` 우변에만
두면 주입 시 우변이 평가되지 않아 우회된다** — 실측으로 전송 6회 / 기록 2회였고, 같은
표현식에 있던 타임아웃도 120초 의도가 SDK 기본 600초가 됐다.

## 샘플링 파라미터를 보내지 않는다

`temperature`·`top_p`·`top_k` 를 요청에 넣지 않는다. 결정론을 샘플링 파라미터로 보장하지
않는 것이 이 프로젝트의 재현성 전략이고, 모델 계열에 따라 파라미터를 아예 받지 않아 400 이 난다.
`reasoning.effort` 는 **지정했을 때만** 보낸다 — 모델 등급이 조정 가능이라 지원하지 않는
계열로 바뀔 수 있다.

## 모듈 경계

- `gate.py` 는 아무 모듈도 부르지 않는다(`contracts.py` 제외). 잎 노드로 유지한다.
- `judge.py` 는 **판정만 한다** — 파이프라인 제어·저장·재생성·L2 스위치 판단을 하지 않고,
  `gate.py` 를 import 하지 않는다(두 층은 서로를 모른다). 호출 횟수를 정하는 것은 호출자다.
- `sql_guard.py` 는 DB 에 접속하지 않는다 — 검증만 하고 실행은 호출자가 한다.
- `draft.py` 는 검증하지 않는다. 산출이 계약을 어겨도 고치지 않는다 — 그건 L1 의 일이고,
  여기서 미리 막으면 게이트 지표가 무의미해진다.
- text-to-SQL 실행은 **반드시** `db.readonly_connect()` 로 연 커넥션을 쓴다.
- FastAPI 라우트 등록·응답 스키마 조립은 `api.py` 가 단독으로 한다.

## 오류를 업무 판정으로 바꾸지 않는다

- `psycopg.Error` 는 인계 사유로 변환하지 않고 전파한다(→ 500). DB 장애를 `no_evidence` 로
  기록하면 판정 일치율 지표가 오염된다.
- 자격 증명 부재는 **503 설정 오류**이며 `llm_call_failed` 가 아니다. 처리 기록도 남기지 않는다.
- **정책 인덱스의 임베딩 출처가 질의와 다르면 503** 이고 `no_evidence` 가 아니다. 모델만 바꾸고
  재색인하지 않은 상태를 "검색이 못 찾았다"로 집계하면, 운영 실수가 검색 품질 지표로 위장한다.
  같은 차원의 다른 모델은 DB 도 pgvector 도 막지 않으므로 이 판정은 **코드가** 한다
  (`policy_index.search_policy_chunks` 가 질의 출처를 인자로 받아 유사도 계산 전에 대조).
- 주문번호 **형식** 오류는 인계가 아니라 **422** 다 — 파이프라인에 진입하지 않는다.

## 데이터 재현성

- 합성 주문은 **저장소에 커밋된 픽스처**(`db/fixtures/orders.jsonl`)를 로드한다.
  시딩 경로에 LLM 생성을 넣지 않는다 — 넣으면 시딩이 멱등이 아니게 된다.
- 정책 적재는 재실행 시 중복 없이 갱신되고, 문서에서 사라진 조항은 삭제한다.
  남겨두면 검색이 존재하지 않는 근거를 돌려준다.

## 컨테이너·프로세스 위생

- 컨테이너 이름은 결정론적으로 짓는다(`reply-gate-postgres`). 무작위 이름은 정리하지 못해 샌다.
- 백그라운드로 띄운 서버는 반드시 종료를 확인한다. 장시간 명령에는 timeout 을 건다.

## 사이클과 태스크 번호 표기

작업 단위는 **사이클**이다 — 기획 → 구현 → 리뷰·수정을 한 바퀴 돈 것이 사이클 하나이고,
그 입력·계획·인계가 `.dryforge/<3자리>/` 의 spec·plan·handoff 3-doc 로 남는다
(`001` = 사이클 1, `002` = 사이클 2, 진행 중인 사이클은 `.dryforge/` 루트).
**T번호는 그 사이클 `plan.md` 안에서만 유효한 태스크 ID 이고 사이클마다 1부터 다시 매긴다.**

그래서 같은 번호가 사이클마다 다른 것을 가리킨다 — 사이클 1 T7 은 골든셋·평가 하네스,
사이클 2 T7 은 API·웹 폼, 사이클 3 T7 은 질의 재작성 배선이다.

- **사이클을 넘어 사는 글**(`docs/` 전체, 코드 주석·docstring, 커밋 본문)에서 T번호를
  인용할 때는 **`사이클 3 T10` 처럼 사이클을 함께 적는다.** 절·문단마다 처음 나오는 곳에
  붙이면 되고, 같은 절 안 반복은 맨 번호로 둔다.
- **사이클 안에서만 사는 글**(`.dryforge/plan.md`·`handoff.md`)은 맨 `T10` 으로 둔다.
  그 문서 전체가 한 사이클 것이다.

사이클이 안 붙은 T번호는 **읽는 시점의 현재 사이클로 오독된다.** 실제로
`tests/test_pipeline.py` 의 `T9`(사이클 2 = 판정 대역)가 사이클 3 의 T9(평가 리포트 확장)로
읽히는 상태였다.

## 커밋

Conventional Commits, 본문은 한국어. 제목에 무엇을 했는지, 본문에 왜 그랬는지를 적는다.
커밋 제목의 `feat(T5):` 같은 스코프는 그 사이클 안의 것이라 사이클을 붙이지 않는다 —
커밋은 날짜와 브랜치가 사이클을 말해준다.
