# 0021. 탐지 전 접기를 패턴별로 두고 번호 계열 안에서만 넓힌다

- **상태**: 채택
- **날짜**: 2026-08-20
- **관련**: [0002 PII를 근거 유래 allowlist로 판정한다](0002-PII를-근거-유래-allowlist로-판정한다.md) ·
  `docs/business-rules.md` "PII 규칙" · `docs/engineering-notes.md`

## 문제

L1 의 탐지 전 접기가 **NFKC + 폭 없는 서식 문자(`Cf`) 제거** 뿐이라 두 계열이 그대로 통과했다.

① **구분자 변종 12자** — `U+2010`·`U+2011`·`U+2012`·`U+2013`·`U+2014`·`U+2015`·`U+2212`·
`U+2027`·`U+30FB`·`U+FF65`·`/`·`_`. 번호 패턴의 구분자 클래스는 `[-. ()]` 뿐이라
`010–9999–8888`(en dash) 이 아무 패턴에도 걸리지 않았다.
② **결합 표식** — `U+0301`·`U+FE0F` 같은 `Mn` 범주 문자. `Cf` 가 아니라 지워지지 않아
숫자열 **안쪽**에 끼우면 `[0-9]{3,4}` 가 끊겼다.

적대적이지 않은 경로로도 난다. 생성 모델이 한국어 문장에서 en/em dash 를 쓰는 것은 흔하고,
양방향이라 미탐(지어낸 en dash 번호 통과)과 오탐(근거는 en dash 인데 초안이 ASCII 정상 에코
→ 기각)이 함께 열린다.

## 고른 것

**접기를 패턴별 속성으로 만들고, 넓히기는 번호 계열 안에서만 한다.**

- 번호 계열 네 패턴(휴대전화·일반전화·대표번호·주민등록번호)은 공통 접기 위에 ①의 12자를
  하이픈으로 접고 ②를 무시한다.
- 이메일은 **공통 접기 그대로** 둔다.
- 패턴 집합·접기의 정의는 **게이트 모듈이 단독 소유**하고, 근거 렌더의 개인정보 필터와
  조회 가드가 가져다 쓴다.

### ①은 열거, ②는 범주 — 반대로 구현하는 이유

12자를 범주 이름으로 짜면 절반이 뚫린다. 실제로 찍어 확인했다: 대시 범주(`Pd`)에 드는 것은
`U+2010`~`U+2015` **여섯 자뿐**이고 `U+2212` 는 수학기호(`Sm`), `U+2027`·`U+30FB`·`U+FF65`·
`/` 는 구두점(`Po`), `_` 는 연결선(`Pc`) 이다. 그래서 ①은 **열거된 고정 집합**이다.

②는 반대다. 결합 표식은 **범주가 계열을 덮는다** — 다만 그 범주는 하나가 아니라 `M` 계열
셋(`Mn`·`Mc`·`Me`)이다(아래 정정 참조).
대표 2자(`U+0301`·`U+FE0F`)로 한정하면 `U+0300` 같은 동일 계열이 그대로 남아, ①에서 경고한
구멍을 반대쪽에서 여는 셈이 된다.

### 이메일을 넓히지 않는 이유

밑줄과 빗금을 하이픈으로 접으면 `a_b@shop.co.kr` 와 `a-b@shop.co.kr` 가 **같은 allowlist
값이 된다.** 근거에 있는 주소를 한 글자 바꿔 지어낸 주소가 근거 유래로 통과하므로, 우회 하나를
닫으면서 반대 방향 우회를 여는 것이다. 밑줄은 이 저장소의 사유 코드·근거 ID·컬럼명에 흔해서
전역으로 접으면 번호와 무관한 문자열까지 함께 움직인다.

이 우려는 구성한 예시가 아니라 **커밋된 모집단에서** 확인된다: 저장소 전체의 이메일에 번호
계열 접기를 걸면 서로 다른 주소의 개수가 실제로 줄어든다(회귀 검사가 그 부등호를 든다).

### 층별 주입점을 없앤 이유

전에는 초안 판정만 패턴 집합을 인자로 주입받을 수 있었고 근거 필터는 기본 집합을 직접 들었다.
**접기가 층마다 달라 뚫린 것과 같은 모양의 비대칭**이라, 주입점을 없애고 소유자를 하나로
확정했다. 소비자는 셋이다 — 게이트(소유자) · 근거 필터 · 조회 가드. 조회 가드가 자기 정의를
새로 만들면 저장소에 개인정보 정의가 셋이 되고, 그것이 이 결정이 닫으려는 결함 그 자체다.
구조 검사가 그 형태를 AST 로 지킨다(정본 이름 재정의 금지 — **앞의 밑줄을 벗겨서** 본다).

## 버린 것

- **접기를 전역 함수 하나로 두고 넓힌다.** 이메일까지 함께 움직여 위의 반대 방향 우회가 열린다.
- **12자를 `category == "Pd"` 로 유도한다.** 열거된 절반이 그대로 뚫린 채 문서만 닫혔다고
  적게 된다.
- **결합 표식을 대표 2자로 고정한다.** 같은 범주의 나머지가 그대로 남는다.

## 대조 — 모집단을 명시한 양방향 관측 (무과금)

`uv run python -m scripts.contrast_pii_folding` 이 재현한다. 접기만 갈아 끼워 두 판정을 나란히
낸다(수정 전 접기는 지금도 이메일 패턴이 쓰는 공통 접기다). 산출물은 남기지 않는다 — 재현이
무과금이라 재실행이 곧 근거다.

**탐지값 차이 (신규 탐지 / 탐지 소실)**

|---|---|---|---|

| 주문 테이블 값(컬럼 이름 포함) | 전수 | 16,000 | 0 / 0 |

| 골든셋 문의 | 전수 | 30 | 0 / 0 |
| 실제 초안 텍스트 | **프로브** | 37 | 0 / 0 |

**판정 차이 (미탐 닫힘 / 새 오탐 / 기각 풀림)**

| 모집단 | 방식 | 초안 | 결과 |
|---|---|---|---|
| L1 픽스처 | 전수 | 35 | **6 / 0 / 0** (미탐 닫힘은 F28~F33) |
| 실제 초안 텍스트 | **프로브** | 30 | 0 / 0 / 0 (분류 불가 0) |

> **정정 (2026-08-22) — 이 표의 열 이름이 틀렸었다.** 원래 두 칸이
> `미탐 닫힘 / 정상 에코 오기각` 이었는데, 오른쪽 칸이 실제로 센 것은 **기각이 통과로
> 풀린 건수**였다. 정상 초안이 **새로** 기각되는 건(= 진짜 오탐 증가)은 왼쪽
> "미탐 닫힘" 칸에 섞여 들어가 있었다 — 정상 문자열 `A_1588_0000` 한 건을 넣으면
> 출력이 `미탐 닫힘 1건 · 정상 에코 오기각 0건` 이었다. 즉 **접기를 넓힐수록 오탐
> 증가가 성과 칸을 키우는 모양**이라, *"오탐이 늘면 채택하지 않는다"* 를 이 계기로는
> 발동시킬 수 없었다.
>
> 스크립트가 이제 라벨(픽스처의 기대 판정)로 방향을 갈라 네 칸으로 센다.
> **수치와 결론은 그대로다** — 위 `6 / 0 / 0` 은 재실행으로 확인한 값이고, 새 오탐 0 은
> 아래 세 근거로도 따로 성립한다: ① 정책 94줄·주문 16,000·골든셋 30 의 탐지값 census
> 신규 0건 ② 대역 실행 전/후 오탐률 `0/8 → 0/9` ③ 커밋된 라이브 19세트의 시도 기록
> 525건에서 신규 표면 0건. **틀린 것은 계기였지 수치가 아니었다.**
> 계기에 검사를 걸었다(`tests/test_contrast_pii_folding.py`).

**끝에서 두 줄은 전수가 아니라 프로브다.** 커밋된 리포트가 초안 문면을 담지 않아 실제 초안에는
자유 모집단이 없다. 결정론 대역 생성기로 골든셋 문의 전건의 초안을 만들어 대신 쟀고, 대역은
표기 변형을 스스로 만들어 내지 않으므로 "변화 0"이 실제 모델의 초안도 안 바뀐다는 뜻은 아니다.

**결정론 대역 실행 전/후** (`uv run python -m scripts.evaluate --stub-llm`, 무과금):

| | 측정 1 검출률 | 측정 1 오탐률 | 측정 2 일치율(대역) |
|---|---|---|---|
| 수정 전 | 100.0% (19/19) | 0.0% (0/8) | 96.7% (29/30) |
| 수정 후 | 100.0% (26/26) | 0.0% (0/9) | 96.7% (29/30) |

**심어 둔 27건에서는 판정이 한 건도 바뀌지 않았다.** 측정 1 의 분모가 움직인 것은 오직
채점표를 늘렸기 때문이다. **오탐은 어느 모집단에서도 늘지 않았다** — 늘었으면 채택하지 않는다.

## 대가

- **측정 1 의 분모가 바뀐다.** L1 픽스처가 27건 → 35건이고 위반 19 → 26, 정상 8 → 9 다.
  새 분모의 수치를 옛 분모의 수치와 나란히 인용하지 않는다 — 인용할 때 분모를 병기한다.
  기존 27건은 한 건도 지우거나 고치지 않았다(추가만).
- **초안 판정이 실제로 달라진다.** 커밋된 라이브 리포트의 조건과 갈리므로, 이 변경은 승격
  기준선 재등재와 한 묶음이다.
- **접기가 패턴마다 다르다는 사실 자체가 비용이다.** 패턴을 새로 넣는 사람이 접기를 명시해야
  한다 — 그래서 기본값을 두지 않고 자료형이 강제하게 했다.

## 무엇이 이 결정을 뒤집나

- 이메일 패턴에도 번호 계열 표기 변형이 실제로 나타나고, 밑줄·빗금 충돌을 열지 않는 별도
  접기를 만들 수 있을 때.
- 커밋된 모집단에서 정상 에코가 새 접기로 기각되는 사례가 나올 때 — 그때는 넓힌 접기를
  되돌리는 것이 아니라 **어느 축이 오탐을 냈는지** 갈라 축별로 판단한다
  ([결정 0011](0011-원복을-축별로-가른다.md)).

## 정정 (2026-08-22) — `Mn` 하나는 결합 표식 계열을 덮지 못한다

**무엇이 틀렸나.** 위 본문과 도메인 규칙 문서가 *"변이선택자까지 전부 `Mn` 한 범주에 들어
**범주가 계열을 정확히 덮는다**"* 고 적었다. 참이 아니다 — 유니코드 결합 표식은
`Mn`(nonspacing) · `Mc`(spacing combining) · `Me`(enclosing) **세 범주**로 갈린다.
변이선택자가 전부 `Mn` 에 든다는 것은 맞지만, 그것이 계열 전체를 덮는다는 뜻은 아니었다.

**대가.** 숫자 자리 사이에 `U+0903`(Mc)·`U+20E3`(Me)를 끼운 번호가 그대로 통과했다.
찍어서 확인했다 — 접기가 `Mn` 하나만 보던 동안 `pii_shaped("010-99〈Mc〉99-8888")` 이
거짓이었다. **①에서 경고한 "범주가 계열을 못 덮는다"를 반대쪽에서 연 것**이고, 이 기록이
스스로 경계했던 바로 그 모양이다.

**고친 것 셋.**

1. **접기** — 범주 하나 비교를 `M` 계열 접두사 비교로 넓혔다. 한 줄이다.
2. **채점표** — `F36`(Mc) · `F37`(Me)을 **추가**했다(기존 픽스처는 손대지 않는다).
   넣지 않으면 새로 닫은 계열을 헤드라인 검출률이 한 번도 재지 않는다. 측정 1 의 분모가
   **35 → 37**, 위반 26 → 28 로 늘었다. 접기를 `Mn` 으로 되돌리면 검출률이
   **100.0%(28/28) → 92.9%(26/28)** 로 떨어진다 — 채점표가 이제 이 계열을 실제로 잰다.
3. **조건 지문의 탐침** — `_PII_RULE_PROBE` 가 `Mn` 문자 하나만 담고 있어서, 접기를
   `Mn` 으로 좁혀도 `draft_rule_version` 이 **한 글자도 움직이지 않았다.** 탐침에 세 범주를
   각각 태웠다. 이제 좁히면 지문이 갈린다(`draftrules-5ffe275f00bc` ↔
   `draftrules-fc5017f58da1`).

**세 번째가 이 정정의 핵심이다.** 국가번호 두 갈래에서 이미 한 번 겪은 함정과 같은
모양이다 — **탐침이 갈래를 안 태우면 그 갈래를 지운 변경이 "규칙 무변경"으로 읽힌다.**
그때는 정규화를 탐침 전체에 걸어서, 이번에는 탐침이 한 범주만 담아서 났다.
**내용 지문을 만들 때는 그 규칙이 가르는 갈래를 세고, 갈래마다 탐침이 있는지 확인해라.**

## 이 정정이 승격 기준선에 남기는 것

`draft_rule_version` 과 `l1_fixture_version` 두 칸이 **등재된 참조와 갈렸다.**

| 지문 항목 | 등재된 참조 (`-28`·`-29`·`-30`) | 지금 코드 |
|---|---|---|
| `draft_rule_version` | `draftrules-a0e153753e62` | `draftrules-5ffe275f00bc` |
| `l1_fixture_version` | `l1fixture-6eb235f9dcd0` | 재집계값(픽스처 35 → 37) |

**등재를 고치지 않는다 — 승격은 사람만 하고, 재등재는 새 라이브를 사는 일이다.**
커밋된 산출물 `-28`·`-29`·`-30` 은 그때의 코드로 낸 값이고 그 세 세트끼리는 여전히
정합하다(등재 정합성 검사가 그것을 본다). 갈린 것은 **앞으로 살 라이브와의 대조**다:
다음에 풀셋을 사면 이 두 칸이 어긋난 항목으로 나오고, 그것을 `--declare-experiment` 로
선언하거나 재등재해야 한다. **이 사이클은 더 사지 않으므로 그 상태로 둔다.**

이 대가를 알고 받는 이유는 하나다 — **코드가 옳은데 채점표와 지문이 그것을 모르는 상태**가
이 저장소가 가장 경계하는 모양이기 때문이다. 닫은 계열을 헤드라인이 재지 않고, 되돌려도
지문이 안 움직이면, 다음에 읽는 사람은 닫혔다고 적힌 문서만 보게 된다.
