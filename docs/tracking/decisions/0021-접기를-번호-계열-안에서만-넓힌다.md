# 0021. 탐지 전 접기를 패턴별로 두고 번호 계열 안에서만 넓힌다

- **상태**: 채택
- **날짜**: 2026-08-20
- **관련**: [0002 PII를 근거 유래 allowlist로 판정한다](0002-PII를-근거-유래-allowlist로-판정한다.md) ·
  `docs/business-rules.md` "PII 규칙" · `docs/engineering-notes.md`

## 문제

L1 의 탐지 전 접기가 **NFKC + 폭 없는 서식 문자(`Cf`) 제거** 뿐이라 두 계열이 그대로 통과했다.

① **구분자 변종 12자** — `U+2010`·`U+2011`·`U+2012`·`U+2013`·`U+2014`·`U+2015`·`U+2212`·
`U+2027`·`U+30FB`·`U+FF65`·`/`·`_`. 번호 패턴의 구분자 클래스는 `[-. ()]` 뿐이라
`010–9999–8888`(en dash) 이 아무 패턴에도 걸리지 않았다.
② **결합 표식** — `U+0301`·`U+FE0F` 같은 `Mn` 범주 문자. `Cf` 가 아니라 지워지지 않아
숫자열 **안쪽**에 끼우면 `[0-9]{3,4}` 가 끊겼다.

적대적이지 않은 경로로도 난다. 생성 모델이 한국어 문장에서 en/em dash 를 쓰는 것은 흔하고,
양방향이라 미탐(지어낸 en dash 번호 통과)과 오탐(근거는 en dash 인데 초안이 ASCII 정상 에코
→ 기각)이 함께 열린다.

## 고른 것

**접기를 패턴별 속성으로 만들고, 넓히기는 번호 계열 안에서만 한다.**

- 번호 계열 네 패턴(휴대전화·일반전화·대표번호·주민등록번호)은 공통 접기 위에 ①의 12자를
  하이픈으로 접고 ②를 무시한다.
- 이메일은 **공통 접기 그대로** 둔다.
- 패턴 집합·접기의 정의는 **게이트 모듈이 단독 소유**하고, 근거 렌더의 개인정보 필터와
  조회 가드가 가져다 쓴다.

### ①은 열거, ②는 범주 — 반대로 구현하는 이유

12자를 범주 이름으로 짜면 절반이 뚫린다. 실제로 찍어 확인했다: 대시 범주(`Pd`)에 드는 것은
`U+2010`~`U+2015` **여섯 자뿐**이고 `U+2212` 는 수학기호(`Sm`), `U+2027`·`U+30FB`·`U+FF65`·
`/` 는 구두점(`Po`), `_` 는 연결선(`Pc`) 이다. 그래서 ①은 **열거된 고정 집합**이다.

②는 반대다. 결합 표식은 변이선택자까지 전부 `Mn` 한 범주에 들어 범주가 계열을 정확히 덮는다.
대표 2자(`U+0301`·`U+FE0F`)로 한정하면 `U+0300` 같은 동일 계열이 그대로 남아, ①에서 경고한
구멍을 반대쪽에서 여는 셈이 된다.

### 이메일을 넓히지 않는 이유

밑줄과 빗금을 하이픈으로 접으면 `a_b@shop.co.kr` 와 `a-b@shop.co.kr` 가 **같은 allowlist
값이 된다.** 근거에 있는 주소를 한 글자 바꿔 지어낸 주소가 근거 유래로 통과하므로, 우회 하나를
닫으면서 반대 방향 우회를 여는 것이다. 밑줄은 이 저장소의 사유 코드·근거 ID·컬럼명에 흔해서
전역으로 접으면 번호와 무관한 문자열까지 함께 움직인다.

이 우려는 구성한 예시가 아니라 **커밋된 모집단에서** 확인된다: 저장소 전체의 이메일에 번호
계열 접기를 걸면 서로 다른 주소의 개수가 실제로 줄어든다(회귀 검사가 그 부등호를 든다).

### 층별 주입점을 없앤 이유

전에는 초안 판정만 패턴 집합을 인자로 주입받을 수 있었고 근거 필터는 기본 집합을 직접 들었다.
**접기가 층마다 달라 뚫린 것과 같은 모양의 비대칭**이라, 주입점을 없애고 소유자를 하나로
확정했다. 소비자는 셋이다 — 게이트(소유자) · 근거 필터 · 조회 가드. 조회 가드가 자기 정의를
새로 만들면 저장소에 개인정보 정의가 셋이 되고, 그것이 이 결정이 닫으려는 결함 그 자체다.
구조 검사가 그 형태를 AST 로 지킨다(정본 이름 재정의 금지 — **앞의 밑줄을 벗겨서** 본다).

## 버린 것

- **접기를 전역 함수 하나로 두고 넓힌다.** 이메일까지 함께 움직여 위의 반대 방향 우회가 열린다.
- **12자를 `category == "Pd"` 로 유도한다.** 열거된 절반이 그대로 뚫린 채 문서만 닫혔다고
  적게 된다.
- **결합 표식을 대표 2자로 고정한다.** 같은 범주의 나머지가 그대로 남는다.

## 대조 — 모집단을 명시한 양방향 관측 (무과금)

`uv run python -m scripts.contrast_pii_folding` 이 재현한다. 접기만 갈아 끼워 두 판정을 나란히
낸다(수정 전 접기는 지금도 이메일 패턴이 쓰는 공통 접기다). 산출물은 남기지 않는다 — 재현이
무과금이라 재실행이 곧 근거다.

**판정 차이 (미탐 닫힘 / 정상 에코 오기각)**

**끝에서 두 줄은 전수가 아니라 프로브다.** 커밋된 리포트가 초안 문면을 담지 않아 실제 초안에는
자유 모집단이 없다. 결정론 대역 생성기로 골든셋 문의 전건의 초안을 만들어 대신 쟀고, 대역은
표기 변형을 스스로 만들어 내지 않으므로 "변화 0"이 실제 모델의 초안도 안 바뀐다는 뜻은 아니다.

**결정론 대역 실행 전/후** (`uv run python -m scripts.evaluate --stub-llm`, 무과금):

| | 측정 1 검출률 | 측정 1 오탐률 | 측정 2 일치율(대역) |
|---|---|---|---|
| 수정 전 | 100.0% (19/19) | 0.0% (0/8) | 96.7% (29/30) |

**심어 둔 27건에서는 판정이 한 건도 바뀌지 않았다.** 측정 1 의 분모가 움직인 것은 오직
채점표를 늘렸기 때문이다. **오탐은 어느 모집단에서도 늘지 않았다** — 늘었으면 채택하지 않는다.

## 대가

- **측정 1 의 분모가 바뀐다.** L1 픽스처가 27건 → 35건이고 위반 19 → 26, 정상 8 → 9 다.
  새 분모의 수치를 옛 분모의 수치와 나란히 인용하지 않는다 — 인용할 때 분모를 병기한다.
  기존 27건은 한 건도 지우거나 고치지 않았다(추가만).
- **초안 판정이 실제로 달라진다.** 커밋된 라이브 리포트의 조건과 갈리므로, 이 변경은 승격
  기준선 재등재와 한 묶음이다.
- **접기가 패턴마다 다르다는 사실 자체가 비용이다.** 패턴을 새로 넣는 사람이 접기를 명시해야
  한다 — 그래서 기본값을 두지 않고 자료형이 강제하게 했다.

## 무엇이 이 결정을 뒤집나

- 이메일 패턴에도 번호 계열 표기 변형이 실제로 나타나고, 밑줄·빗금 충돌을 열지 않는 별도
  접기를 만들 수 있을 때.
- 커밋된 모집단에서 정상 에코가 새 접기로 기각되는 사례가 나올 때 — 그때는 넓힌 접기를
  되돌리는 것이 아니라 **어느 축이 오탐을 냈는지** 갈라 축별로 판단한다
  ([결정 0011](0011-원복을-축별로-가른다.md)).
