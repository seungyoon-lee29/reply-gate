# 0009 — 검색 전략의 채택 판정을 하나의 절대 축으로 통일한다

**날짜** 2026-08-13
**상태** 확정 (유료 비교 실행 전)

## 무엇이 문제였나

사다리 4단이 각각 다른 축으로 채택을 판정했다.

| 단 | 채택 축 |
|---|---|
| vector | 코사인 ≥ 컷 |
| vector_rewrite | 코사인(max) ≥ 컷 |
| vector_rewrite_hybrid | **RRF 점수 ≥ 컷** |
| ..._rerank | **순위 상한 n** |

이 구성은 세 가지를 동시에 깨뜨렸다. 유료 실행 전 적대적 리뷰에서 4명이 독립적으로 같은
지점을 짚었다.

1. **하이브리드 이후 단은 기권할 수 없다.** 벡터·BM25 두 순위가 코퍼스 26개 조항 전량을
   덮으므로 모든 조항이 양쪽 순위에 있고, RRF 최소 점수는 `2/(60+26) = 0.023256` 이다.
   기본 컷 0.02 는 그 아래여서 **어떤 조항도 걸러내지 못한다.** 하이브리드는 모든 문의에서
   정확히 top_k(5)건을 채택했다. 근거가 없어야 정답인 문의(G21–G24·G28)에서 벡터는
   precision 1.0 을 받고 하이브리드는 **구조적으로 0.0** 을 받았다.
2. **리랭크 효과를 측정할 수 없다.** 후보가 항상 `fused[:top_k]`(5건)이고 채택 상한도 5라
   리랭크 채택 집합은 하이브리드와 항등이었다. precision·recall·recall@5 가 정의상 같은
   값이 되어, 움직일 수 있는 것은 r@1·r@3 둘뿐이었다.
3. **precision 분모가 전략마다 달랐다.** "채택 0건 + 정답 있음"은 precision 평균에서
   빠지는데(규약대로) 컷의 실효 강도가 단마다 달라 제외 케이스 수가 크게 갈렸다. 대역
   실측에서 vector 는 30건 중 13건 평균, 하이브리드는 30건 평균이었다. 같은 열에 놓인 두
   수가 서로 다른 표본의 평균이었다.

## 왜 이렇게 됐나

**RRF 점수는 순위 기반이라 "이 조항이 애초에 관련 있는가"를 표현할 수 없다.** 순위 융합은
순서를 바꾸는 연산이고, 절대 관련성 신호를 갖지 않는다. 채택·기권 판정을 그 축으로 옮기는
순간 "아무것도 관련 없다"를 말할 수단이 사라진다.

## 무엇을 골랐나

**채택 판정은 전 전략이 코사인 유사도 하나를 쓴다.** 단계마다 다른 것은 순서와 채택 상한뿐이다.

- 순위 품질(recall@1/3/5)은 컷과 무관한 **전체 순위**로 계산한다. 리랭크 행도 리랭크된
  후보 뒤에 풀 밖 조항을 융합 순서로 이어 전체 순위를 복원한다 — 그래야 recall@5 가 다른
  행과 같은 정의다.
- 채택 판정은 그 전략의 순서 상위 N개에 절대 게이트를 적용한다. 코사인이 측정되지 않은
  후보(어휘 다리에만 있던 조항)는 게이트를 통과하지 못한다.
- 융합 후보 풀(`fusion_pool_size`, 기본 10)을 리랭크 채택 상한(기본 5)보다 **크게 강제**한다.
  같거나 작으면 리랭크가 채택 집합을 바꿀 수 없으므로 실행 전에 거부한다.
- RRF 컷은 후보 풀의 보조 필터로 남기되 기본값을 0.0(무필터)으로 내리고, 0 이 아닌 값은
  **이 코퍼스에서 실제로 걸러낼 수 있는지 검사**한 뒤에만 받는다. 도달 불가능한 값은
  최소 도달 가능 수치를 담아 거부한다.
- 컷은 전략마다 스윕한다. 검색을 다시 돌리지 않고 컷만 바꿔 재채점하므로 추가 과금이 없고,
  전략마다 자기 최적 컷을 함께 리포트한다. 고정 컷 한 점 비교가 유일한 근거가 되지 않는다.
- 비교표에 precision·recall 분모를 함께 인쇄한다.

## 대안과 트레이드오프

- **RRF 컷을 올려 걸리게 만든다** — 코퍼스 크기와 rrf_k 가 최소값을 결정하므로 어떤 고정값도
  코퍼스가 바뀌면 다시 무의미해진다. 그리고 순위 점수에 절대 의미를 부여하는 해석 자체가
  틀렸다. 기각.
- **각 arm 을 top-N 으로 잘라 융합한다** — 표준 관행이고 RRF 컷이 걸릴 수는 있게 되지만,
  기권 문제는 그대로다. 절단만으로는 "관련 조항이 하나도 없다"를 표현하지 못한다. 기각.
- **하이브리드에 기권을 포기하고 순위 품질만 비교한다** — spec §10 성공 판정 ②가 근거 없는
  문의를 검색 단계에서 걸러내는 것이라 포기할 수 없다. 기각.

**받아들인 비용**: 하이브리드·리랭크의 채택 집합이 코사인 게이트에 종속된다. 어휘 다리가
의미적으로는 먼 조항을 순위 위로 올려도 절대 게이트를 넘지 못하면 채택되지 않는다. 이는
의도한 것이다 — 어휘 일치는 **순서**를 바꾸는 근거이고, 채택 여부는 절대 관련성이 정한다.
그 결과 하이브리드가 recall 을 끌어올릴 수 있는 상한이 코사인 컷에 묶이며, 컷 스윕이
그 상한을 함께 보여준다.

## 함께 고친 것

같은 리뷰에서 나온 나머지 하네스 결함도 이 커밋 범위에서 고쳤다.

- 재작성문이 벡터 다리에만 들어가 사다리가 누적이 아니었다 → BM25 어휘 다리와 리랭크 입력에도
  적용한다(원문은 계속 함께 유지).
- 리랭크 실패가 전면 무기록 폴백이었다 → 폴백 건수·사유·토큰을 리포트가 집계한다(spec §8-1).
- `--sweep-*` 가 사문화되어 컷 스윕이 산출 경로에 없었다 → 전략 리포트에 싣는다.
- `--bge-m3` 가 "외부 API 없음"이라 안내하면서 OpenAI 리랭크를 과금했다 → 리랭크 과금을
  `live` 와 별개 축으로 분리하고, 미승인 시 그 단을 사유와 함께 미측정으로 남긴다.
- `run_embedding_model_axis` 가 테스트에서만 호출됐다 → `--embedding-axis` 로 배선했다.
- 재작성 조건이 파일 경로와 결속되지 않아 oracle 입력을 blind 로 인쇄할 수 있었다 →
  저장소 픽스처 경로가 조건을 결정하고, 선언이 다르면 거부한다. 기본값도 없앴다.
- `load_retrieval_labels` 가 기본 코퍼스로만 교차검증해 `--policy-dir` 에서 fail-open 이었다
  → 호출자가 실제로 쓸 골든셋·정책 디렉터리로 검증한다.
- 실패 귀인이 정답 조항 일부만 찾아도 생성 문제로 셌고, 근거 없이 답변이 확정된 케이스는
  아예 세지 않았다 → 부분 누락과 "근거 없이 답변 확정"을 별도 분류로 센다.

## 아직 열려 있는 것

라벨·oracle 픽스처의 **데이터** 문제는 이 결정에 포함하지 않았다. 검색 라벨의 "직접 관련된
모든 조항" 규칙이 전화 문의(2조항)와 이메일 문의(1조항)에 비대칭 적용된 건과, oracle 픽스처
G28·G25 가 개정된 라벨과 반대 방향을 가리키는 건은 분모를 바꾸는 사안이라 사용자 결정이
필요하다. [findings](../findings.md) 를 본다.
